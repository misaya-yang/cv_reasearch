# Fundus50：中间层与2048的即时配对验证

**用户后续指令：只完成1024的50例，取消2048；以下原始2048设计未执行。**

用户要求现在跑50例。动机是FoRIS附录F的Fundus层/分辨率结果，以及当前U在Fundus等于T；本试验检查换表示是否改善我们的原读出，不重开组合搜索。

- 固定50个参考/查询配对：从已有100个Fundus确认配对中用seed2026101303无放回抽取，所有配置共享输入；这些配对已曝光，属于开发诊断。
- 层索引（0起）19、20、23；输入1024、2048，共6个配置。各层来自同一次新DINOv3-L16前向，不训练、不调参数。
- 同时比较原U/T和完整FoRIS。U保持rho>.9回退T，否则保留原调制、V/P和UN图；仅将网格尺寸适配为64/128。FoRIS使用原完整语义流程及原分辨率缩放CRF。
- 每层/分辨率的位置去偏基座用同一原生黑图SVD算法计算，避免把末层的基座错误套到中间层。
- 主评估统一原图2048网格，次评估统一CLI1024；都按同一GT评分，不跨网格挑最好值。全部自然预测生成后再读取query GT。
- 报告同照片配对区间、回退比例、实际编码与方法头部耗时。模型和位置基座准备、写盘另计。
- 若中间层或2048在相同配对上有明确收益，后续扩大该表示比较；若不提高，不为这50例另调权重或门槛。现行T0–T9计划保持原样。
