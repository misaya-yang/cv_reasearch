# 单参考细结构、像素定位与相对几何实验计划

日期：2026-10-13。目标是把 Pro 建议变成三个可否证的问题，不并排实现三个新模块。E1 的 M+/MFU 补算与 E2 的报告半评分已完成；本计划首轮只读已封存缓存，不覆盖 E1 文件，不访问 x1013 的 T 半，也不触发 DINOv3 推理。

## 依据与当前边界

1. **Fundus 像素定位已有因果控制。** R2 在 150 个 Fundus 开发配对上，`VP_identity` 为 34.052，真实参考像素修正为 36.801，块内置换对照为 34.169；真实修正相对 identity +2.749 pp，相对置换 +2.632 pp。Road 100 例上，identity 30.278、真实修正 30.222、置换 30.303；固定块面积 oracle 31.852，显示还有诊断余量但现有规则没有取出。R2 已封存所有预测与控制，不重跑它。
2. **IoU 尚未说明 Fundus 增益是否来自连通结构。** R2 报告有 IoU、FN/GT、FP/GT，但没有 clDice、中心线覆盖、连通分量拆分/误连分析。它的固定块面积约束也不允许跨块补面积。
3. **当前部件标签不支持“左右身份”主张。** PASCAL-Part 有 56 个查询标签，例如 `horse+LEG` 和 `bird+LEG`，左右腿在标签中合并。PACO 当前绑定使用数字 category ID，需回查原始类别名与分割关系后才能确定是否有侧向身份标签。没有可辨别的身份真值时，不运行或报告“左右消歧”成绩。
4. 相关论文将边界说得更窄：FoRIS 的附录 F.4 以代表图像的特征可视化提出“去偏改善匹配位置但未连接断裂片段”，这不是去偏导致拓扑损坏的因果实验；INSID3 对跨图匹配使用去偏特征、对图内聚类保留原特征；已有工作也专门定义了需要方向/几何消歧的左右对应。拓扑指标用 clDice 和显式错误连接计数共同报告，不能凭“连通分量变少”判成功。[FoRIS F.4](https://arxiv.org/html/2609.03384v1) · [INSID3](https://arxiv.org/html/2603.28480v1) · [Telling Left from Right](https://arxiv.org/html/2311.17034v2) · [clDice](https://arxiv.org/abs/2003.07311)

## 实验 A：断裂出现在哪个输出阶段？

**动机：**区分细线证据没有进入分数、固定读出切断了已有证据、像素定位偏移，和 CRF 改变了连接关系。正结果将决定后续应研究排序/支持、范围，还是像素位置；若 GT 分支在连续场中也无支持，就停止用平滑或闭运算解释该缺口。

**队列与输入：**x1013 S 半 Fundus 108 例、DeepGlobe road 62 例；只读已有 T0 `VP_UN` 连续场、A4 掩码、E1 C1 CRF 掩码及对应 GT。比较 A4、C1、FoRIS；不扫阈值，不调参数，不读 T 半。

**测量：**原有 CLI-1024 class mIoU/FN/FP；GT 中心线上的连续分数分位数及低于既定 .5 读出切点的比例；8 连通前景分量的漏失、拆分、误连计数；Zhang–Suen 细化后的中心线 precision/recall 与 clDice-style harmonic mean。对同图配对 bootstrap。中心线和分量只作结构诊断，不代替完整输出指标。

**判据：**

- GT 中心线有较高连续分数，但 .5 输出删掉它，说明分数有支持而范围决定失败；不据此声称 DINO 缺少拓扑。
- A4 漏掉的真分支在连续分数中也没有支持，说明单纯修阈值/CRF 没有依据；转向特征或像素观察证据。
- C1 若增加 clDice/中心线 recall，同时不增加假连接、FP 和 mIoU 损失，才支持“颜色边界帮助结构连续”的窄结论。
- 只减少预测分量数量、但误连 GT 分开的分量，判失败。

## 实验 B：为什么参考像素修正在 Fundus 成功、Road 失败？

**动机：**R2 的真实像素修正、块内置换和固定块面积 oracle 已存在。正结果会指向可迁移的参考像素可分性或目标支持；负结果会关闭“细长结构共享同一种块内修正”的解释。复用 R2 的 150 Fundus / 100 Road 配对，不新增编码。

**比较：**R2 `VP_identity`、`pixel`、`pixel_permuted`、`patch_constant` 与完整 FoRIS。保留每例冻结的参考 holdout alpha 和 fit 统计；不重新拟合，不用 query GT 选实例或阈值。

**测量：**与实验 A 相同的结构指标；另按 R2 既有参考 holdout 选择 TP、混合块数和 alpha 分层，报告真实像素修正相对 identity/置换对照的 paired IoU 与结构差。所有分层仅作事后解释，不选规则。

**判据：**

- Fundus 若 mIoU 和中心线质量共同提升、置换控制失去提升，支持参考标签提供了有效块内定位信息；仍不单凭此宣称跨域拓扑保持。
- 若 Fundus 只减少 FP、中心线质量不变，归类为区域/误报修正，不写成拓扑恢复。
- 若 Road 的参考 holdout 区分力不足且 pixel 无增益，说明当前参考关系不能迁移；固定面积 oracle 只代表诊断容量，不是自然方法。

## 实验 C：相对几何是否修正了部件身份？

先做**标注资格审计**，不启动新模型臂：逐项查 PASCAL-Part/PACO 的原始类别名、同一母体的前景/相邻非前景标注，以及是否存在左右或前后身份标签。已知 PASCAL `LEG` 合并两侧；PACO category ID 需从原始元数据解码。

若没有侧向身份标签，左/右实验停止，不能以整块 `LEG` IoU 推断身份消歧。若存在满足条件的类，才在照片隔离的 S 子集上固定比较：去偏匹配、原特征匹配、正确参考关系、同母体关系置换、绝对画面坐标控制。主诊断是目标与相似兄弟部件的区分率/匹配 margin；自然分割 mIoU 和十域护栏仍需同时报告。只有真实关系超过置换控制、且不靠绝对画面位置，才考虑固定方法；随后另行冻结新照片确认。

该方向不能直接包装为“加入几何图”。左右/朝向几何对应已有专门研究；我们需要证明单张完整参考 mask 与相邻非目标关系能提供此前没有的任务粒度信息。

## 顺序、算力与交付

1. 先做 A 与 B 的缓存重评分，固定输入/照片分组并写出逐例结构指标；使用 CPU 单 worker，可与当前 E1 共享运行但不覆盖其文件。两项均不需要 GPU 或新的 DINOv3 推理。
2. 并行完成 C 的类别/标注资格审计。若当前标签没有 side identity，暂停该主张；若要使用新的 keypoint 数据，先冻结具体数据协议与输出目标，再复用 GPU 做新图编码。
3. 首轮交付：完整 A/B 报告、逐例指标与输入哈希；不根据诊断集调参，也不读 T。任何新算法只在这些诊断给出可操作机制后再写。

数据和预测继续留在 `../cv_data/a/`；压缩后仅保存紧凑逐例证据到 `evidence/research/`。新结果影响下一步的规则已在各实验判据中预先列明。
