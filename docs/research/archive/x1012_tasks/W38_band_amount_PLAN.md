# W38：图像能否给出边界带内的覆盖量

2026-10-15 写定。第 1–3 节在运行前固定，执行中不改。

## 1 动机

- **W37 的发现：**
  - 给边界带内的每个 token 正确的覆盖量，再按 F 在 patch 内取像素（O2），比自然掩码高 **+9.43**；
  - 但用场推出的覆盖率估计（核迁移 c、线性解混）都更差，0/10 个域达标；
  - 所以缺的是一个**局部的“量”**，排序本身是对的。
- **W34 的 T8：** 由 F 推出的量无法纠正 F 的范围误差。新的量必须来自 F 以外。
- **规则内剩下的来源：** 在规则允许的范围内（冻结编码器单次编码、不提高分辨率、不用外部模型），F 以外只剩像素 RGB。CRF 只用通用的成对模型在用它。
- **本任务回答两件事：**
  1. 沿 F 的排序，用颜色分离来定带内覆盖量，是否带有关于真实覆盖量的方向信息；
  2. 这些信息是否超出 CRF 已经用到的部分。

## 2 设计

**样本：** W37 同一批 1,285 个 S 例，含回退例。

**场、自然掩码、带：** 与 W37 完全相同，直接调用 `w37_coverage` 的 `capture`、`pool16`、`band`。

**每个带内 token 的覆盖量 k（0–256）：**
- **nat：** N 在该块内的像素数。
- **crf：** CRF(N) 在该块内的像素数。CRF 与 SH+ 相同；回退例不做 CRF，取 nat。
- **rgb（主）：**
  - 块内像素按 F 降序排列，排序稳定；
  - 对 k = 1–255 计算颜色类间分离 $S(k) = \frac{k(256-k)}{256^2}\,\|\bar x_{top} - \bar x_{rest}\|^2$，颜色取 RGB/255；
  - 取 $k^* = \arg\max_k S(k)$；
  - 门控：$S(k^*)$ 不低于同一例所有带内块 $S(k^*)$ 的中位数时，用 $k^*$，否则用 nat。
- **rgb_all（次要）：** 不加门控，一律用 $k^*$。
- **true（容量参照）：** GT 在该块内的像素数。

**重建：** 与 W37 的 R2 相同。带内每块取 F 最高的 k 个像素，带外保持 N。各臂依次记为 nat、crfA、rgb、rgb_all、true。另外报告 SH+（W27，CRF 后）作为参照。

**指标：**
1. **局部 T8 相关：** 在全部带内 token 上计算 ρ(k_est − k_nat, k_true − k_nat)。区间按“例”为簇，做 500 次 bootstrap，种子 c.SEED。
2. **class mIoU：** 与 W37 相同，CRF 前，相对 nat；区间用 `score.paired_ci`。

## 3 读法（运行前写定）

- **通过（三条都满足）：**
  - ρ_rgb ≥ .25，且区间下界 > 0；
  - rgb − nat ≥ +1.0（十域均值），十域配对区间下界 > 0，且 ≥ 7/10 域 ≥ 0；
  - ρ_rgb > ρ_crf。

  通过后写方法验证计划：rgb 覆盖量加 CRF，对 SH+ 在 S 上比较，再读 T 一次。
- **不通过：** 关闭“用图像颜色定带内覆盖量”。rgb_all 只作诊断，**不在看过结果后替换主臂**。
- **一并报告：** 各臂逐域结果；ρ_crf，即 CRF 已经收回多少带内的量；门控采用 $k^*$ 的比例；用时。

## 结果

（执行后追加。）

**2026-10-15 04:40 完成。不通过：ρ 一条过了，mIoU 一条没过（rgb −1.73，0/10 域）。“沿 F 排序取颜色分离最强的切点”定带内覆盖量，这个构造关闭。**

- **运行：** 1,285 例，2 个进程 × 1 线程，nice 19，中位 1.4 s/例。
- **实现检查：** nat 与 W23 SH（CRF 前）的整数 I/U 一致，1285/1285。门控平均在 50.1% 的带内 token 上用 k*。
- **数据：** 完整报告在 `../cv_data/a/x1013_W38/report.txt`，证据在 `evidence/research/w38_band_amount_S.jsonl.gz`。

| 覆盖量来源 | 局部 ρ（例簇 bootstrap 95%） | mIoU − nat（十域，CRF 前） | 域 ≥ 0 |
|---|---:|---:|---:|
| crfA：CRF 的量，按 F 放置 | +.170 [+.155, +.183] | +0.13 | 7/10 |
| **rgb（主）** | **+.353 [+.345, +.361]** | **−1.73**，区间 [−1.96, −1.60] | 0/10 |
| rgb_all（不门控，诊断） | +.457 [+.449, +.465] | −5.37 | 0/10 |
| true（容量） | 1 | +9.43 | 10/10 |
| 参照：W27 SH+（CRF 后） | | +0.18 | |

**判定：**
- ρ_rgb = .353 ≥ .25，下界 > 0，且大于 ρ_crf = .170，这两条满足；
- rgb − nat = −1.73，十域区间 [−1.96, −1.60]，0/10 域 ≥ 0，不满足；
- 三条要同时满足，所以不通过。按读法关闭这个构造；rgb_all 只作诊断，不替换主臂。

**诊断（不改变判定）：**
1. **crfA ≈ SH+**（+0.13 对 +0.18）：CRF 对 SH 的增益，几乎全部可以表达为“带内每个 token 取多少像素”。
2. **ρ 过、mIoU 不过：ρ 量的是计数的平方误差，mIoU 跟的是像素错误，而且两类错误代价不对称。**
   - 由 sufficient statistics 算得：rgb 的 E[x²]/2E[xy] = 0.94 < 1，带内计数的平方误差从 12,523 降到 12,153，T8 的平方误差改进条件成立；
   - 但全部例池化后，像素错误（U − I）反而从 112.1M 增到 116.2M（rgb_all 127.0M，crfA 111.3M）。块内排序不完美时，像素错误不只是计数误差，还要加上排错的像素；
   - 另外，IoU = I/U，漏掉一个前景像素损失 1/U，多取一个背景像素只损失 IoU/U，前者是后者的 1/IoU 倍（IoU ≈ .6 时约 1.7 倍）。把量往真实计数收的估计，即使计数更准，也可能因为丢掉前景而降 IoU；
   - 所以 W34 T8 的 ρ 筛查是平方误差口径的必要性筛查，对 IoU 不充分。以后的覆盖量估计应直接看像素错误与 I、U 的变化。
3. **带内系统偏置：** 带内真实覆盖量平均比 nat 少 16.3 像素/token（y 的均值），nat 在带内整体偏多。这个偏置用常数平移只能消掉约 2% 的平方误差，不是主要来源。
4. 最优无截距收缩 β = E[xy]/E[x²] 为 .53（rgb）、.44（rgb_all），这是看过结果后的数，只作记录，不据此改臂。

**结论：** 图像颜色带有关于带内覆盖量的方向信息（ρ 约为 CRF 的两倍），但“取分离最强的切点”这个量过冲。缺的仍是可靠的量，而不是方向。

**事后更正（不改判定）：** 第 1 节“F 以外只剩像素 RGB”说得过强。同一次冻结编码里的中间 token、QK/V、未归一化响应，以及参考 RGB 与 mask 的关系，都是 F 没有用尽的允许观测（[W39 D](W39_D_coverage_REPORT.md) §3.1）。本实验只关闭“颜色分离切点”这一个规则，不关闭 RGB 或其他通道。
