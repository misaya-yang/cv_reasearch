## 动机

S 半上逐例 GT 最优切点把候选从 52.4 提到 62.8，FoRIS 从 50.1 提到 61.2。常数切点、Otsu、面积估计、监督融合都已关闭（`TOKEN_READOUT_CEILING_20261012.md`）。这次不再试新的切法，而是问：自然掩码错在哪些像素上。

误差分四类：
- 干扰物：整个预测连通块都不碰 GT；
- 漏实例：整个 GT 连通块都没被预测到；
- 边界：距 GT 边界 16 px（一个 token）以内的错误；
- 内部：其余错误。

每一类单独修正后，看 IoU 增益。

## 2 融合场的切点余量（rho ≤ .9，1,970 例）

- **余量集中在少数例子上。** 前 20% 的例子占总余量的 65%，前 10% 占 42%。这 20% 的例子：
  - 平均余量 38.9；
  - 自然 IoU 32.9，其余例子是 66.7；
  - 自然面积与 GT 面积之比，分位数 10/25/50/75/90% 为 0.25 / 0.47 / 1.28 / 2.69 / 5.04。也就是说，要么只盖住一半，要么漏到 2.7–5 倍；
  - 其余例子的同一比值是 0.79 / 0.95 / 1.06 / 1.34 / 2.44。
- **方向五五开。** 欠覆盖占余量的 51%。t* < .4、.4–.6、> .6 大约各占三分之一，各域方向也不一致：PASCAL-Part、PACO、SUIM、Road 偏松，LVIS 偏紧。
- **大余量例子多是单连通目标。** 单连通目标占前 20% 的 68%，在全体中占 59%。

## 3 结论

1. 剩下的余量主要不在“找错东西”（干扰物、漏实例合计约 +5），而在**已经找到的目标该连多大**：
   - 大目标只盖住一部分；
   - 中小目标顺着相连区域漏出去。

   出错的是少数例子，错的是倍数级的面积，方向没有全局偏好。所以任何全局切点、面积先验、方向先验都提不出这部分余量，这与已关闭路线的结论一致。
2. 一个 token 的边界带在自然图像域约值 +8～9（FN+FP），是 64² 分辨率的上限问题。在 Fundus/Road 上，这是主要误差（细结构）。
3. FoRIS 和本线都用与参考的 token 相似度决定范围：
   - 查询中与参考不相似的部分会被丢掉，表现为内部 FN；
   - 与参考相似的相邻区域会被并入，表现为内部 FP。

   MFU 减少了后者，但前者两条线都没有解决。

## 对下一步的含义

可检验的方向是“用参考定位，用查询自身结构定范围”。在设计规则之前，先做一个小规模可行性检查（每域 ≤ 50 例）：以查询自身特征做分组（只用查询，不看参考），看它能否在这 20% 的大余量例子里装下正确范围。具体比较：
- 分组 oracle 与切点 oracle；
- 一条以已定位核心为种子的固定规则与 MFU。

只有分组 oracle 明显高于切点 oracle 时，这个方向才值得做；否则关闭。
