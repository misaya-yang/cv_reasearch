# W31 候选范围重新编码验证方案

2026-10-14。最初为方案评审；用户随后授权按本修正版执行 K0 四选择器的一轮比较。第 1–6 节的科学定义和门槛不变，只使用 S，不读取 T 或新照片留出，不改变 W30 已冻结的 SH+。K1/K2 未授权执行。

## 1 要检验的研究主张

值得争取的贡献是：**在排序场给出候选范围之后，候选 mask 条件下的重新编码，能否提供原整图 token 匹配之外、由参考任务决定的范围判别证据。** 参考示范约束的是目标定义、部件或整体的粒度及完整性，不是把参考像素面积直接迁移给查询。

令 T(I,M) 为固定的候选渲染，E_cls 为冻结 DINOv3 的末层归一化 CLS：

    v(A; R, M_R, Q) = cosine(E_cls(T(Q,A)), E_cls(T(R,M_R)))

    A_selected = argmax_{A in C(Q)} v(A; R, M_R, Q)

成立需要同时区分三个解释：原 token 的区域平均已经足够；裁剪放大本身带来收益；验证器确实携带参考任务条件下的范围证据。只有最后一个解释支持上述机制主张。

这属于相对旧整图 O24 的新增可用测量。原始输入仍是同一个 (R,M_R,Q)，不增加标注，也不突破原始输入不可辨识反例。冻结编码器的确定性重用不产生额外的真实任务定义。

## 2 已有依据和不能外推的部分

- W27/W28 证明最终 SH 的总体融合优势；现有错误分解发现，两批共同六域非回退样本的剩余错误像素中，CRF 前共同错误约占 60.1%/62.1%。固定场的凸融合不能改变两条线共同的二值决定，因此新的测量有研究动机。
- W04/W07 的相对排序优势对应旧候选及其队列，不是最终 SH 的排序饱和证明。W14 的约 10 点阈值 oracle 主要对应 MFU，不能直接记成 SH 的九候选余量。
- Ward 三节点 oracle 80.95 来自另一候选族、队列和指标，不能作为本方案的候选上限。本方案必须在自己的九个候选上重新计算 oracle。
- J 的既有正结果说明特定候选族中有选择信号。W25 按 J 选 λ 仍失败，不能由跨水平相关推出 J 对任意候选族可靠。
- 历史 CLS/区域判断失败是负面先验，新渲染制式仍需独立检验，不能只因换成“范围”一词就忽略旧失败。

相关工作限制了可写的新颖性：[Matcher](https://arxiv.org/html/2305.13310v2) 已用参考 mask 与候选内 dense features 的 EMD、purity、coverage 选择候选；[Mask-Adapted CLIP](https://openaccess.thecvf.com/content/CVPR2023/papers/Liang_Open-Vocabulary_Semantic_Segmentation_With_Mask-Adapted_CLIP_CVPR_2023_paper.pdf) 已研究遮罩裁剪后重新编码，并指出 masked-image 的分布差异。因此，“生成候选再编码打分”本身不能宣称首次提出。候选来源免 SAM、冻结视觉示范比较及范围识别的因果证据，才是本方案需要建立的具体区别。

[DINOv3 原论文附录 C](https://arxiv.org/html/2508.10104v1) 对齐局部裁剪与全图的 CLS。由此推测，局部与完整目标可能仍有很高相似度；这是需要直接检验的失败风险，不是必然失败的定理。

## 3 K0 候选选择能力

### 3.1 固定数据和候选

使用 W27 的同一批 S 任务，共 1,285 例。只对 1,090 个非回退例构造并编码新候选；195 个回退例原样保留，以便恢复完整十域的同分母比较。非回退子集单列九域，不给 Fundus 伪造非回退分数。

直接捕获冻结 simple_head 的连续融合场 F，先要求 s=0 的自然掩码在全部样本上复现 W27 的整数 I/U。不能改用 T0 的旧场替代最终 SH。

令 A0 = |F>.5|，在完整 1024² 预测画面上固定：

    s in {-2,-1.5,-1,-.5,0,.5,1,1.5,2}
    k_s = clip(floor(A0 * 2**s + .5), 0, 1024**2)
    candidate_s = top_k_s(F)

按坐标固定排序处理同分，不读 GT；裁剪面积并去除重复候选。s=0 必须逐像素等于自然掩码。空掩码保持原结果，不编码空裁剪；相同验证分数优先选择 s=0，其次最小 |s|，最后较小 s。忽略区域只用于评分，不能从查询标签构造候选。

该候选族仍以 .5 自然掩码为面积锚点，并含固定的搜索区间与分辨率，不能称“去掉所有阈值/无常数”。候选包含 SH 仅保证 oracle 不差，不保证自然选择不伤害 SH。

### 3.2 渲染和四个选择对照

主渲染固定为 mask 外填编码器 RGB 均值，对应标准归一化后的零输入；按非空 mask 的最小轴对齐包围盒取方形、居中补零，缩放为 448²；参考和查询同样处理。只用原 DINOv3-L/16 权重、FP32、末层 CLS、L2 归一化和余弦，不尝试层、token 类型、填充色或分辨率网格。

以下选择器始终面对同一批候选；自然 SH 作为不选择的基准。

| 选择器 | 用途 |
|---|---|
| 既有 J | 同候选池的无新编码强控，固定复用 r5_candidate.quality 的当前公式 |
| 缓存 token 区域平均 | 以 coverage 对已有去偏 O24 作区域均值、归一化后比较参考，检验重新编码的增量 |
| 重新编码遮罩候选 | 本方案的固定验证器 |
| 重新编码未遮罩裁剪 | 使用相同包围盒、方形画布和 448 分辨率，保留框内原 RGB；参考也同样处理，检验裁剪/放大是否已解释收益 |

未遮罩裁剪是机制对照，不是可按结果替换主方法的另一个候选。若只看到它同样有效，应将证据收窄为候选裁剪观察有用，不能归因于遮罩条件下的范围验证。

所有候选、嵌入、选择索引封存后，才读取 S 查询 GT。GT 只用于评分和候选 oracle，不进入选择器。oracle 报告逐例 IoU 最优候选策略的槽池化 mIoU，以及逐例 IoU 的均值；前者是诊断参照，不冒称域级 mIoU 的严格最大值。选择能力看同例候选之间的排序和最终选择收益，不能只看跨样本的全局相关系数。

### 3.3 指标和决策

主指标为 CRF 前的同例差值：每域 (fold,class) 池化 I/U 后槽等权，再十域等权。按 W27 规则做 500 次查询照片成组配对 bootstrap，seed=c.SEED；同时报九域非回退子集和逐域结果。先保存全部选择，再看 GT。区间不能按候选逐条当作独立样本计算。

保留 Opus 的两个实用门槛：重新编码选择相对自然 SH 均值至少 +1.0 pp，相对同池 J 至少 +0.5 pp；两项配对区间下界均须大于 0。机制主张另要求相对缓存池化、未遮罩裁剪的增量区间下界均大于 0。不得看到结果后选择满足条件的域、render 或编码层。

另报每例选择相对 oracle 的损失、选中 s 的分布、超出四倍面积窗口的限制，以及事先定义的欠覆盖/过覆盖分组中的 FP/FN 收支。候选 oracle 不足时，先说明本候选族容量有限；不能把有限候选失败等同于全部范围验证无效。

若平均收益不通过，停止此固定构造，不追加填充色、全局特征或候选密度搜索。若实用门槛通过但机制增量不成立，不能写“新增范围信息已经证明”，也不直接进入新方法的留出确认。

## 4 K0 的任务粒度干预

仅在上述门槛通过后做这一项机制验证。使用已有真实 A/B 任务中 S 查询照片的全部可用配对，优先保留原生定义明确的部件/整物体配对；在编码前仅凭来源和标注关系冻结成员、计数、渲染及代码 SHA。没有可用的真实部件/整体配对时如实报告覆盖缺口，不用“随便遮掉半个物体”制造新的合法任务定义。

固定同一参考 RGB、同一查询 RGB、同一候选池，只切换合法参考 mask M_A/M_B。候选池取两任务各自九候选的并集，完全由自然预测生成，去重后封存；这个共同池只作干预诊断，不能当单参考部署方法的成绩。两任务的查询 GT 只在封存后评分。

报告正确/交叉参考选择对两种真实任务的 IoU、部件候选与整体候选的偏好切换，以及按照片配对的区间。可用各任务的候选 oracle 定义可区分能力分母，但须同时报告全部配对，不只展示成功见证。

不能用“换成同域另一例后收益必须减半”作主要因果门槛：在 Lung、ISIC 中另一例通常仍是合法参考；换到另一类别则主要检验身份，而非完整性。同一 RGB 的真实任务切换更接近本方案要证明的粒度判别。若只有类别切换有效、部件/整体的范围偏好不响应，应收窄为区域类别验证，不能宣称参考指定了完整范围。

## 5 K1 和现有 W30 的关系

K0 的能力、增量和任务粒度证据成立后，才值得提出一次新的固定方法验证：SH 排序场 + 本验证器 + 同一个 CRF；另外在 FoRIS 自己的连续场生成相同规则的九候选，并施加同一个验证器。报告验证器对两种宿主的收益及完整计算成本。验证器对 FoRIS 也有效可以支持其通用性，不等同于与任务无关的翻转/分辨率设置。

K1 保留 Opus 的实用目标：十域平均相对 SH+ 至少 +1 pp、无一域显著下降、COCO/ISIC 的点估计不低于同例 FoRIS。T 的一次性检验须有单独冻结的完整实现与读法，不能用本评审稿直接开放读取。

当前 W30 已按用户决定冻结为 SH+，继续按该计划执行。本轮不把新方法加入 W30，不推迟其运行，也不读取确认结果来选择方法。未来若另行安排新方法确认，须在接触留出之前冻结，两个臂即使同批产出也不能按留出结果择优包装。

## 6 成本和交付

仅主遮罩验证器最多约 10,900 张 448² 输入；未遮罩裁剪对照再增加相近数量，去重和复用参考可减少实际次数。15–30 分钟尚未实测，不能写成已知成本。先在 S 的固定前缀测编码吞吐、CPU 准备与内存，再估计全量时间；不因测速改变特征定义或科学门槛。

执行时只用一个 MPS 编码进程，CPU 最多 4 worker、每个 torch 2 线程，保留约 30% CPU，内存紧张时减少 worker，避免占用 W30 的运行窗口。逐候选记录支持恢复；小证据写 evidence/research/。原拟数据目录 ../cv_data/a/x1013_W31/ 已被另一会话的不同定义占用，本修正版改写 ../cv_data/a/x1013_W31_K0_revised/，不覆盖或混用其结果。不改冻结源码、不删除文件、不提交 Git。

本轮仅执行第 3 节的 K0 四选择器比较；只有能力与增量门槛都通过才执行第 4 节的 S 任务粒度干预。若最终只得到“遮罩裁剪再编码可以分类候选”的结果，仍不足以证明新的范围识别原理；若同候选池、同预算、任务粒度干预与独立确认均支持，才可以形成“候选范围的任务条件验证”这一有证据的具体贡献。

执行细节（读取本轮结果前固定）：同框裁剪保留 mask 包围盒内的 RGB，长边补成方形的部分为归一化零；不扩框。固定小批量 10，必要时只因资源减少批量，不改渲染。自然掩码先与 W27 封存掩码逐像素核对，所有选择封存后再读取 S GT 核对整数 I/U，再出结果。欠覆盖/过覆盖分别定义为自然掩码有效面积小于/大于 GT 有效面积，相等另列；四倍窗口限制报告逐例 IoU oracle 是否落在候选最小/最大面积边界，不冒称知道窗口外的最优范围。
