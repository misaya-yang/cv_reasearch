# W55：SH 的“传播误检”从哪一步来——相对读出是不是原因

> **W58 更正（2026-10-15）：** 数值结果保留。81.3% 仅指预定义传播 FP 中 U 参与部分在 U_abs 反事实下消失，不等于最终融合的净收益或全部错误的归因。代码 solve_abs 用原始 s 重算置信权重，故原文“相同权重”应读作相同权重公式、不同实际权重。M 参与率不是移除 M 有益的证明。见 [W58 理论审查](../../x1012_tasks/W58_theory_archive_REPORT.md)。

2026-10-15 写定。第 1–3 节在运行前固定，执行中不改。

## 1 动机

- [W51](W51_competition_PLAN.md) 读法 2 写定的下一步：灾难例像素错误中最大的一类是**传播误检**（25.2%）——点证据的比较已判为背景（c32 ≤ .5，即 F ≤ B），SH 的输出仍是前景。这一步之前没做。
- 代码事实（W55 前核对）：SH 的两条线在第一步就把输入 min-max 到 [0, 1]：
  - 点线：`w09.solve` 先 s = (c_mod − min)/(max − min)，求解后再 `minmax(up(·))`；
  - 原型线：`w19.mean_solve` 先 s = minmax(p)。
  所以证据的绝对强弱在进入两条线之前就被丢掉了。
- **猜想：** 证据弱的例子，弱信号被拉成和强信号同一尺度，再沿图扩散，形成传播误检。W45–W51 综合报告 §6 第 1、2 条。
- 这是诊断：不产生方法，不调参。用户要求的“结构性缺陷 → 修复 → 以缺陷前提为开关”路线中，它检验 SH 自身的一个候选缺陷。

## 2 设计

**样本：** W23 S 半 1,285 例（与 W37–W51 同批）。回退例（rho > .9，195 例）没有两条线，只报告、不参与归因。T 半与留出不读。

**每例（冻结 SH，`w42.capture` 加钩子，CRF 前）：**
- c32（点证据）、c_mod（新颖度调制后、min-max 之前的点线输入）、U0_raw（点线求解输出、min-max 之前）；
- U = minmax(up(U0_raw))，M = up(mean_solve 输出)，A0 = (.5U + .5M > .5)，与 W23 SH 一致；
- **反事实点线 U_abs：** 与 `w09.solve` 相同的权重与 λ = 16，但输入用 c_mod 本身（不做 min-max），输出 up 后不做 min-max。只用来回答“如果点线保留绝对尺度，这个像素还会不会是前景”。

**像素归属（只看传播误检像素）：** 纯背景 token（GT 覆盖率 ≤ .1）上、c32 ≤ .5、A0 = 1、GT = 0 的像素，分为：
- 只有 U > .5；只有 M > .5；两者都 > .5（.5U + .5M > .5 要求至少一条 > .5）。
- 对 U > .5 的像素，再看 U_abs > .5 是否成立：不成立记为“min-max 造成”。

**每例证据强弱（不看 GT）：** max c32；c32 > .5 的 token 比例；c_mod 的极差（max − min）。

**汇总：** 灾难例（SH+ IoU < .3）与非灾难例分开，逐例平均（像素池化作对照），按域。

## 3 预测与读法（运行前写定）

**我的预测：**
- P1：灾难例的传播误检像素中，涉及原型线 M 的（只有 M + 两者）≥ 60%，其中“只有 M”最大。理由：M′ 单线面积常是 GT 的数倍（W27 记录），它是全局原型，最容易铺开。
- P2：涉及 U 的传播误检像素中，过半在反事实 U_abs 下消失（即由 min-max 造成）。
- P3：灾难例里，逐例传播误检占比与“c32 > .5 的 token 比例”负相关（Spearman ρ < −.2）：比较判为前景的 token 越少（证据越弱），传播误检越多。

**读法：**
1. 实现检查：A0 与 W23 SH 一致 ≥ 1,280/1,285；c32 与 W51 一致。
2. **M 占主导（P1 成立）：** 灾难例的误检主要来自原型线的全局铺开。下一步另写计划：原型线输出受点证据比较约束（或保留绝对尺度），事先写出预测与开关条件。
3. **U 占主导且 P2 成立：** min-max 是点线误检的原因。下一步检验保留绝对尺度的点线。
4. **两者相当或 P2 不成立：** 传播误检不是单一步骤造成的，记录后不在 SH 内部继续拆，转向图板观察。
5. P3 成立与否单独报告：成立说明“证据弱时相对读出放大误检”这个机制有支持；不成立说明误检与证据强弱无关，猜想要改。

**按读法 2（M 占主导）：**
- 灾难例的传播误检主要来自原型线 M 的全局铺开。点线 U 也有贡献（参与 48%），其中八成是 min-max 造成的。
- 而且证据越弱，传播误检越多。这支持“相对读出在证据弱时放大误检”这一机制，但只是相关，不是因果检验。
- **下一步（另写计划）：** 原型线的输出受点证据的绝对水平约束，开关条件用不看 GT 的证据强弱量（c32 > .5 的 token 比例或 max c32），事先写出预测。

**适用范围：** S 半 1,285 例，SH 这一种方法；“保留绝对尺度后消失”是反事实点线上的计算，不等于改了方法之后的结果。

**更正（10-15 晚，据 W58）：** M 参与在非灾难例中同样高（95.2% 对灾难例 93.5%），所以“M 参与率高”不是灾难例特有的，也不证明修改或去掉 M′ 能提高总分；灾难例的区别只在传播误检占比更高（23.4% 对 13.0%）。81.3% 只是所定义传播 FP、U 参与子集上的反事实消失比例，`solve_abs` 还重算了置信权重，最终融合后的 TP/FN 代价没有计算。上面的“下一步”缺少所声称的支持，需另行论证后才能立项。
