## 1 问题与做法

- **问题：** 只有一张参考图和它的 mask，用冻结 DINOv3 特征，查询里的目标什么时候能识别、靠什么机制识别、什么时候确实识别不了。
- **三层：**
  - **表示：** 特征能否分开目标；
  - **迁移：** 参考定义的目标能否在查询里重新找到；
  - **读出：** 找到之后如何决定范围。
- **难例的标准：** 必须证明信息不在输入或特征里，“别的方法也失败”不算证据。
- **灾难例：** SH+ IoU < .3，占 20.3% 的例子、43.8% 的像素错误。按像素池化的统计会被它们主导（W41–W43 的教训），所以以下占比默认逐例平均。

## 2 理论结果

1. **SH 点证据是一场比较（W51，恒等式）：**
   - c_i = σ((F_i − B_i)/τ)，τ = .05；
   - F_i = τ·log Σ_j e^{s_ij/τ} y_j（像参考前景的程度），B_i = τ·log Σ_j e^{s_ij/τ}(1 − y_j)（像参考背景的程度）；
   - 数值核对误差 2e-7。τ 很尖，c > .5 ⇔ F > B。
   - 按本次操作性定义把比较错误分成四种（不作为因果归因）：背景污染、外观不符（漏检）；竞争者、两边都不像（误检）。另有比较正确但 SH 后续步骤出错的“传播”。
2. ~~读出族的几何上限（W49）~~ **已撤回。** 原说法：对“输出 g×g 标量场、双线性上采样、全图单一阈值”的任何方法，单例 IoU 不超过 C_g = 最佳阈值 IoU(up(真实覆盖率_g), GT)。这不成立：C_g 只是该族中“真实覆盖率”这一个场的成绩，是该族最好成绩的**下界**。（10-15 更正，用户指出：C_g 只是读出族中一个具体场的成绩，是该族最好成绩的下界，不是上限。直接优化 64×64 场后，C_64 < .5 的 164 例平均从 .420 升到 .717，96.3% ≥ .5；抽样 150 例从 .919 升到 .977。见 W49 计划“更正”节。）
3. **一个线性探针的成绩（W45）：** 在查询自身 token 上交叉拟合的岭回归探针 P_Q。原文称之为“这层特征的线性上限”，P_Q < .5 判“表示不足”，**这一推断已撤回**：探针失败不等于信息不在特征里。（10-15 更正，用户指出：P_Q 是一个固定的线性岭回归探针，8×8 token 块棋盘两折交叉拟合。它失败只说明这个探针在 token 级分不开，不说明信息不在特征里；原 98 例中 26 例某折无 y≥.5 token，37 例少于 3 个；这是硬多数计数，真实软标签无 y>0 的为 9 例、少于 3 个的为 13 例，不能称没有正监督。见 W45 计划“更正”节。）联合拟合参考与查询来判断“概念是否一致”，在 1024 维下没有区分力：两张不同场景的图各占一块子空间，可以同时拟合两种不相干的标注（W47 冒烟，错配参考同样“一致”）。
4. **融合与编辑（W39 A、W41、W38）：**
   - 凸融合动不了两线共同的错误；
   - IoU 为 J 时，新增区域的真实前景率 p>J/(1+J) 才严格改善该同一集合/槽的 IoU。不能把未经标定的预测概率直接代入；增删有限差分须使用精确 I/U，1/J 代价比只是大并集近似。
5. **自参考的退化与极限（W48 §3c）：**
   - 参考等于查询时，sim_max 恒为 1，新颖度恒为 0，SH 在 22.3% 的例子上输出为空；
   - 正确的连续延拓是 c_mod = c。自参考是泄漏 token 标签的 oracle，它本身得分高不说明问题。

## 4 现在的认识

**一条分数阶梯（十域 mIoU，CRF 前）：**

| 条件 | mIoU | 说明 |
|---|---:|---|
| 真实 64 网格覆盖率取 .5 阈值 | 83.6 | 一个 oracle 场的成绩，**不是**读出族上限（W49 已更正；直接优化场在抽样中达 .977） |
| SH，参考 = 查询本身 | 75.7 | 泄漏 oracle，不能与另一构造的成绩相减解释读出损失（W48/W58） |
| 查询 GT 交叉拟合线性探针 | 71.6 | 一个线性岭回归探针的成绩，不是特征的上限（W45 已更正） |
| SH，真参考 | 53.6 | 当前方法 |
| 参考上拟合的线性分类器 | 38.3 | 直接搬方向不行（W45） |
| SH，同域错配类别参考 | 20.1（7 域） | 参考的类别总体上决定输出（W48） |

**表示层（已更正）：目前没有“信息不在特征里”的证据。**
- 原文“60 例连几何上限都 < .5、是有证据的难例”不成立：同一族读出直接优化场，C64 < .5 的例子 96% 可 ≥ .5，Fundus 平均可达 .67（我们 .34，FoRIS .19）。
- 原文“38 例 O24 特征分不开”只是一个线性探针失败。探针拟合软覆盖率；98 例中 26 例有一折没有 y ≥ .5 的 token，但真正没有任何前景监督（无 y > 0）的只有 9 例（W58 核对）。
- 这些结果提供特定输出族可表示性的正证据，不能证明冻结特征能生成对应场，也不能据未证明信息缺失就断定特征足够。当前没有一例被证明完整输入不可解；W58 精确结果进一步区分范围可恢复与场质量缺口。

**迁移与读出：排序与范围都有损失。**
- 灾难例上，只按“像参考前景”排序，AUC 中位数为 .947；换成错配参考是 .760。参考的类别部分进入了排序（W51）；
- AUC 不足以决定小目标完整 IoU。W58 对全部 261 个灾难例的 SH 场精确阈值均值为 .3552；原可错配子集的 .358/.248 是粗阈值扫描，尚不能作精确成对比较。
- 最终 IoU，真参考与错配参考几乎一样（.126 对 .107）。
- 灾难例的像素错误中：
  - 误检占 54%：SH 后续步骤加入的传播 FP 25.2%，两边都不像 19.9%，竞争者 8.9%；
  - 漏检占 22.5%，混合 token 占 23.4%。
- 原 W45 旧读出组的自参考 .886 属历史分组；W58 新的 69 个好阈值例自参考均值为 .841（W48 已封存自然输出重分组）：证据近乎完美时，SH 的面积是对的。但自参考泄漏了答案，这只说明读出规则在好证据下不出错，不能说明证据不完美时读出不是问题。

**已测补救及其边界（不等于排除整个原因）：**
- 逐图标准化/CORAL 未改善，不排除协方差或分布偏移（W46）；
- 指定正则补救收益有限，不能估计伪相关的因果份额（W46，旧 oracle 待重算）；
- 查询无标签几何的转导：−1.84（W46）；
- 目标大小不同：oracle 尺度匹配只收回约 15%（W50，部分样本）；
- “两边都不像”解释真参考与错配参考结果相同：不成立，两者该类占比差 14.8 个百分点（W51）。

**参考背景作为负样本的问题：** 灾难例上 A_B 中位数 .372 < .5，查询目标比查询背景更像参考背景。F − B 的排序（.931）略差于 F 单独（.947）。

## 6 未解决的问题与下一步

1. **传播 FP 从哪一步来（CPU，约 20 分钟）：**
   - 对比较判为背景、SH 输出为前景的 token，查是哪一步加入的：点证据线 U0 > .5、原型线 M′ > .5，还是只有融合后才 > .5；
   - 要检验的假设是：min-max 归一化把判定变成相对的，证据弱时也必然输出一块前景；
   - 事先写出预测再跑。
2. **缺少绝对的判定标准：** 两边都不像（比较没有“都不是”）与 min-max（读出没有绝对尺度）可能是同一个结构缺陷：SH 的每一步都只做相对比较，没有任何一步能说“这里没有目标”。若 1 证实，下一步研究不看 GT 的绝对或拒绝准则，并事先说明它为什么应该减少误检、预计在哪些域。
3. **概念为什么到不了输出：** 排序里有概念（.947 对 .760），输出里没有。要看决定范围的环节是否抹掉了这个差别。
