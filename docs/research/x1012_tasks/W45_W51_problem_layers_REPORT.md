# W45–W51 综合：单参考分割在哪一层失败、为什么

2026-10-15 整理。汇总 W38–W51 的实验与理论，取代分散在各计划“结果”节中的阶段性解读。数字均为 S 半（1,285 例）、CRF 前，除非注明；T 半和新照片留出都没有读。

## 1 问题与做法

- **问题：** 只有一张参考图和它的 mask，用冻结 DINOv3 特征，查询里的目标什么时候能识别、靠什么机制识别、什么时候确实识别不了。
- **三层：**
  - **表示：** 特征能否分开目标；
  - **迁移：** 参考定义的目标能否在查询里重新找到；
  - **读出：** 找到之后如何决定范围。
- **难例的标准：** 必须证明信息不在输入或特征里，“别的方法也失败”不算证据。
- **灾难例：** SH+ IoU < .3，占 20.3% 的例子、43.8% 的像素错误。按像素池化的统计会被它们主导（W41–W43 的教训），所以以下占比默认逐例平均。

## 2 理论结果

1. **SH 点证据是一场比较（W51，恒等式）：**
   - c_i = σ((F_i − B_i)/τ)，τ = .05；
   - F_i = τ·log Σ_j e^{s_ij/τ} y_j（像参考前景的程度），B_i = τ·log Σ_j e^{s_ij/τ}(1 − y_j)（像参考背景的程度）；
   - 数值核对误差 2e-7。τ 很尖，c > .5 ⇔ F > B。
   - 一次比较的错误只有四种：背景污染、外观不符（漏检）；竞争者、两边都不像（误检）。另有比较正确但 SH 后续步骤出错的“传播”。
2. **读出族的几何上限（W49）：** 对“输出 g×g 标量场、双线性上采样、全图单一阈值”的任何方法，单例 IoU 不超过 C_g = 最佳阈值 IoU(up(真实覆盖率_g), GT)。它与特征无关，只由 GT 形状和网格决定。C_64 < .5 的例子在这族读出下不可解，这是可证伪的难例证据。
3. **线性可判定性（W45）：** 在查询自身 token 上交叉拟合的探针 P_Q 给出“这层特征的线性上限”。P_Q < .5 才判表示不足。联合拟合参考与查询来判断“概念是否一致”，在 1024 维下没有区分力：两张不同场景的图各占一块子空间，可以同时拟合两种不相干的标注（W47 冒烟，错配参考同样“一致”）。
4. **融合与编辑（W39 A、W41、W38）：**
   - 凸融合动不了两线共同的错误；
   - IoU 为 J 时，加入一个纯度为 p 的像素，当且仅当 p > J/(1 + J) 才使 IoU 增加；删去一个真阳性的代价是加入一个假阳性的 1/J 倍。
5. **自参考的退化与极限（W48 §3c）：**
   - 参考等于查询时，sim_max 恒为 1，新颖度恒为 0，SH 在 22.3% 的例子上输出为空；
   - 正确的连续延拓是 c_mod = c。自参考是泄漏 token 标签的 oracle，它本身得分高不说明问题。

## 4 现在的认识

**一条分数阶梯（十域 mIoU，CRF 前）：**

| 条件 | mIoU | 说明 |
|---|---:|---|
| 真实 64 网格覆盖率取 .5 阈值 | 83.6 | 读出族的几何上限（W49） |
| SH，参考 = 查询本身 | 75.7 | 泄漏 oracle：证据近乎正确时 SH 的读出只损失约 8 点（W48） |
| 查询 GT 交叉拟合线性探针 | 71.6 | 这层特征的线性上限（W45） |
| SH，真参考 | 53.6 | 当前方法 |
| 参考上拟合的线性分类器 | 38.3 | 直接搬方向不行（W45） |
| SH，同域错配类别参考 | 20.1（7 域） | 参考的类别总体上决定输出（W48） |

**表示层：有证据的难例很集中。**
- 灾难例中 23.0%（60 例）连几何上限都 < .5：Fundus 的细血管、Road 的细路、LVIS 的小物体；
- 8 像素网格能救其中一半，4 像素网格能救八成（W49）；
- 另有 38 例网格画得出来但 O24 特征分不开，是否需要别的层或更高输入分辨率，尚未检验。

**迁移与读出：排序与范围都有损失。**
- 灾难例上，只按“像参考前景”排序，AUC 中位数为 .947；换成错配参考是 .760。参考的类别部分进入了排序（W51）；
- 但 AUC 对小目标不敏感，同一 SH 场的最佳阈值 IoU 只有 .358（错配 .248）。排序本身也不足以分出目标；
- 最终 IoU，真参考与错配参考几乎一样（.126 对 .107）。
- 灾难例的像素错误中：
  - 误检占 54%：SH 后续步骤加入的传播 FP 25.2%，两边都不像 19.9%，竞争者 8.9%；
  - 漏检占 22.5%，混合 token 占 23.4%。
- W45 的“读出失败”一类在自参考下平均 .886（W48）：证据近乎完美时，SH 的面积是对的。但自参考泄漏了答案，这只说明读出规则在好证据下不出错，不能说明证据不完美时读出不是问题。

**已排除或削弱的解释：**
- 协方差或分布偏移：对齐反而更差（W46）；
- 参考特有的伪相关：正则在灾难例上只收回 10%（W46）；
- 查询无标签几何的转导：−1.84（W46）；
- 目标大小不同：oracle 尺度匹配只收回约 15%（W50，部分样本）；
- “两边都不像”解释真参考与错配参考结果相同：不成立，两者该类占比差 14.8 个百分点（W51）。

**参考背景作为负样本的问题：** 灾难例上 A_B 中位数 .372 < .5，查询目标比查询背景更像参考背景。F − B 的排序（.931）略差于 F 单独（.947）。

## 5 今天的更正

1. W41–W43 的像素池化占比被灾难例主导，“生长是主问题”被高估（W45 起改为逐例口径）。
2. W38 中“F 以外只剩 RGB”说得过强，已收窄。
3. W34 的 T8 ρ 筛查不能作门槛（W38、W40 是反例）。
4. “FoRIS 也失败即难例”的思路不成立（OVERVIEW §1 已按问题本身重写）。
5. W48 第一次的自参考臂有退化，无效，改用 self0；“迁移损失 22 点”按构造成立，不是独立发现。
6. W45 的“读出失败”一类，W48 只说明它们在好证据下面积是对的。“实际是迁移问题”的说法过强，已收窄。
7. 两次运行前预测落空，如实记录：
   - W50 放大一侧预测收回 20%–50%，实际约 15%；
   - W51 预测“两边都不像”最大，实际是传播 FP 最大。
8. **W51 的“信息在排序里、只丢在决定范围的环节”过强。** AUC 对小目标不敏感，最佳阈值 IoU 只有 .358，已改为“排序与范围都有损失”。

## 6 未解决的问题与下一步

1. **传播 FP 从哪一步来（CPU，约 20 分钟）：**
   - 对比较判为背景、SH 输出为前景的 token，查是哪一步加入的：点证据线 U0 > .5、原型线 M′ > .5，还是只有融合后才 > .5；
   - 要检验的假设是：min-max 归一化把判定变成相对的，证据弱时也必然输出一块前景；
   - 事先写出预测再跑。
2. **缺少绝对的判定标准：** 两边都不像（比较没有“都不是”）与 min-max（读出没有绝对尺度）可能是同一个结构缺陷：SH 的每一步都只做相对比较，没有任何一步能说“这里没有目标”。若 1 证实，下一步研究不看 GT 的绝对或拒绝准则，并事先说明它为什么应该减少误检、预计在哪些域。
3. **概念为什么到不了输出：** 排序里有概念（.947 对 .760），输出里没有。要看决定范围的环节是否抹掉了这个差别。
4. **token 以下的信息（MPS，约 1–2 小时）：** 对 60 个分辨率不够和 38 个特征不够的灾难例，检验更高输入分辨率或其他层的特征能否把它们分开。按 OVERVIEW §9，这属于研究层；若用作方法，对比方法须用同样设置。
5. **W30（外部检验）** 不回答机制问题，但给出官方协议和新照片留出上的成绩，是论文唯一的同协议外部证据。
