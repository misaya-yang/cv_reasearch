# W51：SH 的判定是一场“像参考前景还是像参考背景”的比较——失败出在哪一边

2026-10-15 写定。第 1–3 节在运行前固定，执行中不改。

## 1 动机与推导

**已知：**
- [W48](W48_reference_specificity_PLAN.md)：灾难例上，真参考与同域错配类别参考的结果几乎一样（逐例 IoU .126 对 .107）；
- [W46](W46_transfer_PLAN.md)：迁移偏差不是分布偏移，也不主要是参考伪相关；
- [W50](W50_scale_matching_PLAN.md)（部分）：尺度匹配只收回约 15%；
- [W45](W45_solvability_PLAN.md)：灾难例中 66% 预测面积大于 GT。

前几个实验都是“先量、再分类”，没有从 SH 怎样做判定出发。本实验从判定公式出发。

**SH 点证据的精确分解。** 核迁移（r5 `independent`）为

c_i = Σ_j w_ij y_j / Σ_j w_ij，w_ij = exp(s_ij / τ)，τ = .05，

其中 s_ij 是查询 token i 与参考 token j 中心化后的余弦，y_j 是参考覆盖率。令

- **F_i = τ · log Σ_j exp(s_ij/τ) · y_j**：i 像参考前景的程度（软最大相似度）；
- **B_i = τ · log Σ_j exp(s_ij/τ) · (1 − y_j)**：i 像参考背景的程度。

则 **c_i = σ((F_i − B_i)/τ)**，这是恒等式，不是近似。τ = .05 很尖，c > .5 当且仅当 F_i > B_i。所以 SH 的点证据就是一场比较：查询 token 更像参考前景，还是更像参考背景。

**一次比较只有四种出错方式，各自的治法不同：**

| 错误 | 条件 | 名称 | 含义 |
|---|---|---|---|
| 漏检 | F ≤ B，且该目标 token 的 B ≥ 查询真实背景 B 的中位数 | 背景污染 | 参考背景里有像目标的东西，目标“像背景”至少和真正的背景一样 |
| 漏检 | F ≤ B，且 B < 查询真实背景 B 的中位数 | 外观不符 | 目标并不特别像参考背景，但更不像参考前景 |
| 误检 | F > B，且该非目标 token 的 F ≥ 查询目标 F 的中位数 | 竞争者 | 从参考看，这个东西至少和真目标一样像前景 |
| 误检 | F > B，且 F < 查询目标 F 的中位数 | 两边都不像 | 它不如真目标像前景，只是更不像参考背景，比较时被“归”到了前景 |

- **另外两类：**
  - **传播：** 比较判对了，但 SH 最终输出错了，由 SH 的图求解、原型线或融合造成；
  - **混合 token：** 发生在 GT 覆盖率介于 .1 与 .9 的 token 上，是 token 粒度的边界或细结构问题（W49）。
- **治法：** 两边都不像 → 缺少“都不是”的拒绝选项；竞争者 → 单张参考在这层特征下无法区分，属于信息不足的候选；背景污染 → 应清理参考的负样本；外观不符 → 真正的外观迁移问题；传播 → SH 自己的后处理。

**事先的预测（运行前写，用来检验我对机制的理解）：**
- 灾难例中，像素错误最大的一类是“两边都不像”，约 35%–45%。理由：面积偏大占多数；而且真参考与错配参考结果相同，说明输出主要由“不像参考背景”决定，而不是“像参考类别”；
- 其次是外观不符；
- 非灾难例中最大的一类是混合 token。

## 2 设计

**样本：** W37–W50 同一批 1,285 个 S 例。T 半和新照片留出都不读。

**每个例子：**
- 真参考，以及 W48 的同域错配参考（单类别域没有）；
- 各跑一次 SH（`w42.capture`，CRF 前，得到 A0）；
- 从同一次 `rc.independent` 的输出（去偏特征 r、q 与参考覆盖率 y）按上式计算 F、B。

**token 标签：** GT 覆盖率 ≥ .9 为纯目标，≤ .1 为纯背景，其余为混合。

**中位数参照：**
- 查询目标 F 的中位数，取纯目标 token；没有纯目标时取覆盖率 ≥ .5 的 token，再没有就取覆盖率最大的 token；
- 查询背景 B 的中位数，取纯背景 token，规则对称。

**错误归属：**
- 把 A0 的像素级 FN、FP（有效区内）按所在 token 汇总；
- 纯目标 token 上的 FN、纯背景 token 上的 FP，按上表归入四类或传播；
- 混合 token 上的错误全部归“混合”；纯目标 token 上的 FP 与纯背景 token 上的 FN（token 内的边缘像素）也归“混合”（冒烟时发现漏算，运行前补上）。

**汇总：**
- 逐例计算各类占该例像素错误（FN + FP）的比例，再对例子取平均（不做像素池化，避免 W41–W43 那样被少数例子主导）；
- 同时报告像素池化的比例作对照；
- 分灾难例（SH+ IoU < .3）与非灾难例，按域、按 W45 四类报告。

**次要量：**
- 纯 token 上三个排序的 AUC（目标对背景）：A_F（按 F）、A_B（按 −B）、A_D（按 F − B）。
- 用来看排序信息来自参考前景还是参考背景。

## 3 读法（运行前写定）

1. **实现检查：**
   - 所有例子上 σ((F − B)/τ) 与 r5 的 c32 最大差 < 1e-4；
   - 真参考的 A0 与 W23 SH 一致 ≥ 1,280/1,285。
2. **主读法：** 真参考、灾难例，按逐例平均占比，取六类中最大的一类（不含混合；若与第二大的差 < 5 个百分点，记为两者并列）。
   - **两边都不像：** SH 缺少“都不是”的选项。下一步另写计划，检验不看 GT 的拒绝准则，并事先写出预测；
   - **竞争者：** 单张参考在这层特征下分不开目标与干扰。下一步查干扰是同类实例（任务本身有歧义）还是别的类别（特征区分力不足）；
   - **背景污染：** 下一步检验清理参考负样本（去掉与参考前景相似的背景 token）；
   - **外观不符：** 外观迁移是主因，下一步比较其他层或部件级匹配；
   - **传播：** 比较本身是对的，错在 SH 的图求解、原型线或融合。下一步拆 SH 的后处理。
3. **与预测对照：** 如实记录预测是否成立，不改类别定义或中位数参照。
4. **错配参考：** 在灾难例上报告同样的占比。若“两边都不像”的占比在真参考与错配参考之间相差 < 10 个百分点，则这一机制能解释 W48 中两者结果相同。
5. 只作诊断，不产生方法，不读 T。

## 结果

**2026-10-15 完成。** 1,285 例，中位 1.2 s/例。实现检查：σ((F − B)/τ) 与 c32 的最大差 2.1e-7；真参考 A0 与 W23 SH 一致 1285/1285。完整报告在 `../cv_data/a/x1013_W51/report.txt`，证据在 `evidence/research/w51_competition_S.jsonl.gz`。

**像素错误的归属（真参考，逐例平均占比；括号内为像素池化）：**

| | 背景污染 | 外观不符 | 竞争者 | 两边都不像 | 传播 FN | 传播 FP | 混合 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 灾难例（261） | 10.8%（13.9） | 10.6%（21.4） | 8.9%（12.1） | 19.9%（26.7） | 1.1%（2.3） | **25.2%**（15.2） | 23.4%（8.4） |
| 非灾难例（1024） | 7.7% | 9.6% | 4.1% | 15.1% | 6.0% | 12.5% | **44.9%** |
| 灾难例 · W45 表示不足（98） | 1.9% | 0.5% | 4.2% | 10.2% | 0.1% | 35.6% | 47.5% |
| 灾难例 · W45 读出失败（60） | 19.6% | 28.6% | 2.6% | 28.0% | 3.2% | 12.4% | 5.7% |
| 灾难例 · W45 迁移失败（72） | 13.3% | 5.9% | 18.4% | 27.6% | 0.7% | 25.3% | 8.8% |

- **按域（灾难例）：**
  - COCO、ISIC 以“两边都不像”为主（45.2%、47.1%）；
  - LVIS、Road 以“传播 FP”与“混合”为主（46.2% 与 23.5%，35.4% 与 61.4%）；
  - Fundus 88.8% 是混合；
  - PASCAL-Part、PACO-Part 的外观不符和竞争者较多。
- **排序（纯 token 的 AUC 中位数）：**

| | A_F（按像参考前景） | A_B（按不像参考背景） | A_D（按 F − B） |
|---|---:|---:|---:|
| 真参考，灾难例 | .947 | .372 | .931 |
| 真参考，非灾难例 | .994 | .436 | .997 |
| 错配参考，灾难例 | .760 | .407 | .723 |

**判定：**
- **读法 2：** 灾难例中最大的一类是**传播 FP（25.2%）**，第二是两边都不像（19.9%），相差 5.3 个百分点，按规则为单一最大类。也就是说，比较本身判为背景，SH 的后续步骤（图求解、min-max 归一化、原型线或融合）却把它输出成前景。
- **读法 3（与预测对照）：** 预测“两边都不像”最大（35%–45%），**没有成立**。它是第二大类（19.9%），只在 COCO、ISIC 和 W45 迁移失败一类上居首；像素池化时它最大（26.7%）。“非灾难例以混合为主”成立（44.9%）。
- **读法 4：** 两边都不像的占比，真参考 24.3%、错配参考 9.5%，相差 14.8 个百分点（≥ 10）。这一机制**不能**解释 W48 中真参考与错配参考结果相同。

**结论：**
1. **灾难例的错误以误检为主。** 误检三类合计 54%（传播 FP 25.2、两边都不像 19.9、竞争者 8.9），漏检三类合计 22.5%，与 W45 中 66% 的灾难例面积偏大一致。
2. **参考的类别部分进入了排序，但排序本身也不够。**
   - 灾难例上，只按“像参考前景”排序，AUC 中位数为 .947；换成错配参考只有 .760。参考的类别确实影响排序；
   - 但两者的最终 IoU 几乎一样（W48：.126 对 .107）；
   - AUC 对小目标不敏感：目标只占几十个 token 时，AUC .95 仍可能让上百个背景 token 排在目标前面。W48 中同一 SH 场的最佳阈值 IoU，真参考只有 .358（错配 .248）；
   - 所以不能说“信息都在排序里，只丢在决定范围的环节”。排序与范围两段都有损失，与 W45 的 .136 → .340 → .606 一致。
   - **更正：** 本条初稿写作“区分信息存在于比较的排序中，丢在决定范围的环节”，说得过强。用户指出结论偏武断后复核改正。
3. **参考背景这一项在灾难例上没有提供区分力。**
   - A_B 中位数 .372 < .5：查询目标比查询背景更像参考背景；
   - F − B 的 AUC 中位数（.931）与 F 单独（.947）接近，差异未做检验。
4. **下一步（按读法 2）：** 拆 SH 的后处理，查传播 FP 由哪一步产生。冒烟例提示了 min-max 归一化：它把场值重新拉到 0–1 后再取 .5，判定变成相对的，证据弱时也必然输出一块前景。这只是待检验的假设。
