# W49：token 网格本身能不能表达目标——分辨率上限

> **W58 更正（2026-10-15）：** 保留原计划和历史结果供追溯，撤回“读出族几何/硬上限”的命名与推论。真实覆盖率插值只是一个具体构造，原 120 分位点又低估了它的最优阈值成绩。原 S 半 1,285 例精确重算已完成：原 60 个低 C64 灾难例中 21 个实际 C64≥.5，剩 39 个仅能称“该覆盖率重建低分”。其中 C128≥.5 为 32/39、C256≥.5 为 39/39，不等于模型提高输入分辨率就能救回。83.60 是自然 .5 阈值的诊断 mIoU，仍非上界。见 [W58 修复报告](W58_score_repair_REPORT.md)及 `w49_token_resolution_S_exact.jsonl.gz`；以下旧结论由该更正替代。

2026-10-15 写定。第 1–3 节在运行前固定，执行中不改。

## 1 动机

- **[W45](W45_solvability_PLAN.md)：** 37.5% 的灾难例属于“表示不足”，即用查询自己的 GT 交叉拟合 token 探针，最佳阈值 IoU 仍 < .5。这些例子集中在 Fundus（100%）、Road（85%）、LVIS（65%），是细血管、细路、小物体。
- **两种原因还没分开：**
  1. **分辨率不够：** 64×64 网格（每格 16 像素）本身画不出这个形状。即使每个 token 都给出完全正确的覆盖率，双线性上采样后取阈值也得不到好 mask。这是几何上限，与特征无关；
  2. **特征不够：** 网格画得出来，但 O24 特征分不开目标。
- 两者的下一步完全不同：前者必须引入 token 以下的信息（像素、更高输入分辨率），后者要换特征（别的层、注意力）。第 1 种只用 GT 就能算，不需要特征。

**上限的定义：**
- 设 y_g 为 GT 在 g×g 网格上的平均池化覆盖率（真实覆盖率，无噪声）；
- C_g = 最佳阈值 IoU(up(y_g), GT)，up 为双线性上采样到 1024（与 `lab.up` 相同，align_corners = False），阈值同 W45 的 120 个分位点；
- C_64 是“输出 64×64 标量场、双线性上采样、全图单一阈值”这一族读出（SH、W45 的探针都在其中）在该例上的最高可能 IoU。它不约束 CRF 或其他像素级后处理。

## 2 设计

**样本：** W37–W48 同一批 1,285 个 S 例，只读查询 GT。T 半和新照片留出都不读。

**计算：** g ∈ {64, 128, 256}（每格 16、8、4 像素），得到 C_64、C_128、C_256；另记 C_64 的自然阈值（.5）IoU。逐例 IoU 用 `c.iu` 的有效区；最佳阈值 IoU 与 W45 的 `best_cut` 相同（不扣有效区），用排序实现，并在前 20 例上与 `best_cut` 逐例核对（差 < 1e-9）。

**汇总：** 按 W45 的四类和灾难与否分组，报告 C_g 的均值、C_64 < .5 的比例；按域报告。

## 3 读法（运行前写定）

1. **实现检查：** 排序版最佳阈值与 `best_cut` 在前 20 例上一致。
2. **把 W45“表示不足”的灾难例分成两类：**
   - **分辨率不够：** C_64 < .5。在 64 网格加双线性加单阈值这族读出下，任何特征都做不好，是有几何证据的难例；
   - **特征不够：** C_64 ≥ .5 但 P_Q < .5。网格画得出来，O24 特征分不开。
3. **含义：**
   - **分辨率不够占多数（≥ 50%）：** 这批难例的根源是 token 粒度。再看 C_128：若 2 倍网格就把多数例子推到 ≥ .5，下一步研究 8 像素粒度的信息来源（更高输入分辨率的特征或像素级证据）；若 C_256 才够，说明需要接近像素级的证据；
   - **特征不够占多数：** 下一步在这些例子上比较别的信息来源（其他层、key、更高输入分辨率），而不是改读出。
4. **附带：** 报告全部 1,285 例中 C_64 < .5 的比例与域分布。这是本读出族的硬上限，任何改进 token 级排序的方法都越不过去。
5. 只用 GT，只作诊断。

## 原始结果（历史；当前结果见 W58）

**2026-10-15 完成。** 1,285 例，中位 0.05 s/例。实现检查：排序版与 `best_cut` 在 40 例上完全一致。完整报告在 `../cv_data/a/x1013_W49/report.txt`，证据在 `evidence/research/w49_token_resolution_S.jsonl.gz`。

**真实覆盖率上采样的最佳阈值 IoU（逐例平均）：**

| | C_64 | C_128 | C_256 | P_Q | C_64 < .5 |
|---|---:|---:|---:|---:|---:|
| 灾难例（261） | .744 | .814 | .865 | .606 | 23.0% |
| 其中 W45 表示不足（98） | .473 | .625 | .739 | .271 | 61.2% |
| 其中其余三类（163） | .88–.96 | | | .75–.89 | 0% |
| 非灾难例（1024） | .885 | .922 | .951 | .811 | 10.2% |
| 全部（1285） | .856 | .900 | .933 | .769 | 12.8% |

**按域：**
- C_64 < .5 的比例：Fundus 90.7%、LVIS 28.0%、Road 22.6%、SUIM 5.3%，其余域 ≤ 1.3%；
- 在真实 64 网格覆盖率上取 .5 阈值，十域 mIoU 为 83.60（Fundus 24.04、Road 53.01、LVIS 78.86，其余 ≥ 95）。

**判定（读法 2）：**
- W45“表示不足”的 98 个灾难例中，**61.2%（60 例）是分辨率不够**（C_64 < .5），38 例是特征不够；
- 分辨率不够的例子中，C_128 ≥ .5 的有 56.7%，C_256 ≥ .5 的有 83.3%。

**结论：**
1. **真难例的主体是几何上限，不是特征。** 在“64 网格标量场 + 双线性上采样 + 单一阈值”这族读出下，即使每个 token 的覆盖率都完全正确，这 60 例也到不了 .5。这是可证伪的难例证据，与任何对比方法无关。
2. **8 像素网格能救一半，4 像素网格能救八成以上。** 要做这些例子，需要 token 以下的信息。
3. **其余 38 例（表示不足中的 39%）网格画得出来，但 O24 特征分不开**，属于特征层面的难例候选。是否换层、换输入分辨率能解决，还没有检验。
4. **这族读出的十域硬上限是 83.6。** SH 用自参考（W48）是 75.7，用真参考是 53.6。

## 更正（2026-10-15，用户指出）

**“硬上限”的推断不成立，结论 1、2、4 撤回。**
- C_g = 最佳阈值 IoU(up(真实覆盖率_g), GT) 只是“g×g 标量场 → 双线性 → 单一阈值”这族读出中**一个具体的场**（真实覆盖率）的成绩。该族的最好成绩是对所有场取最大，真实覆盖率并不是使双线性等值线最贴近 GT 的场（角点取 [0, 1] 以外的值，就能把 .5 等值线放到覆盖率场放不到的位置）。所以 C_g 是该族最好成绩的**下界**，不是上限。
- **检验（`scripts/x1012/w49_field_opt.py`，证据 `evidence/research/w49_field_opt_S.jsonl.gz`）：** 从真实覆盖率出发，用 Adam 在软 IoU 上直接优化 64×64 场（阈值固定 .5，对自由场不失一般性），400 步，取硬 IoU。梯度下降得到的仍是下界。

| | 例数 | C64 | 直接优化 | ≥ .5 |
|---|---:|---:|---:|---:|
| C64 < .5 的全部 S 例 | 164 | .420 | **.717** | **96.3%** |
| 其中 Fundus | 98 | .445 | .674 | — |
| 其中 LVIS | 42 | .363 | .793 | — |
| C64 ≥ .5 的抽样（种子 2026101504） | 150 | .919 | .977 | 100% |

- **因此：**“60 例在这族读出下不可解”“真难例的主体是几何上限”“需要 token 以下的信息”“十域硬上限 83.6”都不成立。83.6 只是一个 oracle 场的成绩。
- 仍然成立的只有：在“真实覆盖率 + 双线性”这一种渲染下，C_g 随网格变细而升高（描述事实）。
- 对 Fundus 的含义：这族读出至少能做到 .67，SH 为 .34，FoRIS 为 .19。限制它们的是场的质量，不是 64 网格。

### W58 与并行直接优化场记录的口径区分

上述 164 例/150 例直接优化是另一会话按旧 C64 队列执行的独立诊断，本轮保留其记录。W58 重算的是原 1,285 例同一真实覆盖率场的精确阈值，不重做该优化，也不将其成绩当特征可读性证明。“某个 GT 优化场存在”不能推出冻结特征可在未知查询上生成它；83.6 的 class mIoU、上述选中子集的逐例均值及不同方法全量成绩不能直接相减。当前 39 个低 C64 灾难例仍不构成不可解证据。
