## 2 机制检验

只把参考 y>0 的混合 token 从负核均值中去掉，负总质量保持 N_B，前景核 df 不变；不是先验替换。query 的近纯 token（覆盖率≥.9 标正类、≤.1 标负类，其他不进入 AUC）的 −B AUC 中位数：

| 域 | 原负核 | 纯背景负核 | 可计算例数 |
|---|---:|---:|---:|
| COCO | .229 | .391 | 150 |
| LVIS | .136 | .195 | 129 |
| PASCAL-Part | .618 | .687 | 148 |
| PACO-Part | .510 | .587 | 149 |
| SUIM | .496 | .656 | 148 |
| iSAID | .188 | .342 | 110 |
| ISIC | .356 | .514 | 150 |
| Lung | .958 | .983 | 105 |
| Fundus | .421 | .742 | 104 |
| Road | .122 | .496 | 33 |

缺少纯前景或纯背景 query token 的例子仅缺 AUC，仍全部进入完整分割评分。`c` 的 AUC 中位数在多数域几乎不变；单独 −B 的改善没有自动成为可用的完整决策改进。

**事后支持量审计（只补查原固定指标分母，不改算法）：** Fundus 可计算 AUC 的104例中，正类 token 数中位仅7个，其所含前景质量占全部 GT 的中位 **2.17%**；93.50% 的前景质量落在未纳入 AUC 的混合 token。Road 对应正类10个、覆盖 **7.56%**，混合部分90.32%；29/62例甚至没有可计算的两类 AUC。以上各百分比是分别取中位，不要求加和为100%。因此 Fundus 的 `c` AUC中位1.000、Road .999，完全不能证明其全像素排序或细结构已解决。其他域的正类前景覆盖中位为65.2%–94.0%，仍是条件评价。

另一个区别是**单独负项与最终比值**：COCO 原 −B AUC .229，但 F 的 AUC .994、c 的 AUC .994；清理后 −B 到 .391，c 仅到 .9944。一个项独立当分类器表现差，并不自动证明它在密度比中有害。实际使用的是相对前/背景支持，且这里还只是近纯 token 的ROC AUC；最终净收益仍由完整像素 IoU 检验。支持量见[小证据](../../../evidence/research/w60_auc_support.json)，逐例在生成目录 `auc_support_cases.json`。

CRF 前相对 A0：新增 TP 2,486,446，新增 FP 4,939,979；删除 TP 701,283，删除 FP 1,560,882。新增覆盖同时带入大量误报；这是像素池化计数，不能直接解释槽等权 mIoU。

## 3 能确定与不能确定的结论

1. **混合参考 token 确实影响负证据的目标/背景排序。** 固定同一输入和参考类别总质量时，清理负字典普遍提高 −B 的 AUC。
2. **它不是一个通用完整修复。** 总体完整分数近零，且有明确域间取舍。不能再从“负证据看起来更正确”直接推到方法更好。
3. **不能据此把其余问题全部归原型线。** 本轮未干预 M，局部刻度、图传播、阈值和两线交互仍可能解释净结果。运行前已写定的 W62 将独立检查 M 负字典与联合通道。
4. **Fundus 的 +1.51 是这一具体干预的开发正信号。** 不属于融合贡献，不自动证明“硬 token 上限”或其他渲染机制。当前不按域开关、不用新阈值挽救本配方。
