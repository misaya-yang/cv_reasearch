# W64 及此前实验复盘：失败原因、FoRIS / INSID3 的机制与免训练研究方向

2026-10-16。按用户要求，先回答为什么反复失败、W64 为什么启动及其遗漏、三种方法有什么实质差别，以及哪些不足值得继续研究。本报告整理现有结果并复核作者代码，不启动新的分割实验。

**研究约束：整个方法免训练。** 使用冻结 DINOv3、一张完整标注参考和一张查询；不训练骨干、读出器或选择器，不引入额外模型。查询 GT 只用于评分和明确标注的诊断。训练式 C0 不属于后续主线；此前提出用跨图监督训练读出器，是改变问题设定，已撤回，未启动训练式方法实验。

## 1 先给判断：失败的共同原因是什么

**我们尚未证明一个统摄所有样本的模型根因；但反复失败的研究方式已经很清楚：从一个局部现象或代理指标，跳到一个完整修正，中间缺少“它为什么能在查询图上把正确目标与干扰分开”的证据。** W64 也重复了这一点。这个判断来自下文多项独立构造的结果，不是把失败次数当作模型能力上限。

具体有四种反复出现的缺口：

1. **改善代理，不等于改善目标。** 参考内补全、背景 AUC、面积斜率、覆盖量相关性、特征重建，分别测量不同事情。它们可以改善，同时完整 mask 的 IoU 下降。后续求解器正确收敛，不能弥补这个差别。
2. **很多改法仍在重排同一批不充分或有偏的证据。** 改先验、归一化、传播尺度、聚类或融合，能够改变输出，但未必增加“这块应该属于哪个目标”的判别依据。这里的“不充分”指当前读出在具体例子上失败，不是整个 DINOv3 无信息。
3. **混合了不同失败。** 有些例子已有好排序而切点错；另一些例子在当前场上怎么切都不够好。一个统一的缩小、放大、压背景或平滑规则，可能救前一组的一部分，同时伤另一组及原来正确的部分。
4. **已有反证没有持续约束新立项。** “参考上更好不保证查询更好”“oracle 不是可部署方法”“正确答案可能违反我们人为设置的重建约束”，在旧档案已出现，后续又换一个指标或算子重复同样的推断。W45/W49 计分错误进一步放大了错误解释，但不是全部方法失败的原因。

这不意味着此前没有进展。SH 的固定融合在 W27/W28 两批开发样本上优于各自单线；W30 新照片留出中 SH+ 相对完整 FoRIS 为 **+3.13 pp [2.28, 3.74]**。这些是有效成果。尚未做到的是：在此基础上得到一个新的、可解释且稳定增益的免训练机制，并证明它相对直接近邻的贡献。[W27](W27_sh_single_line_REPORT.md)、[W28](W28_sh_second_batch_REPORT.md)、[W30](W30_mac_confirmation_REPORT.md)

### 2.1 哪些“根因”仍不能认定

[W58](W58_score_repair_REPORT.md)修正后，原 S 半261个灾难例中：**69个当前 SH 场存在 IoU≥.5 的阈值；107个当前场达不到而查询监督探针能达到；85个两者都未解决。** 107进一步分为73个参考探针缺口、34个 SH 分数缺口。这是诊断分类，不能写成互斥因果份额。

- 不能再说“主要就是阈值”：107个例子已经反驳这一解释对全部灾难例适用。
- 不能说“85个表示没信息”：有限探针低分不构成整个编码器的上界。
- 不能说“单参考天然有歧义，所以做不了”：旧协议审计没有给出可解释本批普遍失败的完整输入多答案证书。
- 不能说“排序 AUC 很高，所以只缺范围”：Fundus/Road 近纯 token AUC 的正类中位只覆盖2.17%/7.56%的真实前景。
- 已确认的单例 SUIM 标签解码丢失需要单列，但它不解释其余方法负结果，更不能把改 GT 后的分数当方法增益。

同 RGB 合法任务切换的 W63 还给出一个正面事实：62/63对匹配方向正确，但两任务都达到 IoU≥.5 的只有38/63。**参考 mask 确实被使用了，使用了任务信息仍不等于输出足够完整、准确。** [W63](W63_task_switch_REPORT.md)、[指标与标签边界](../archive/x1012_tasks/W58_autonomous_window_REPORT.md)

## 3 FoRIS、INSID3 和 SH 实际分别做了什么

本节以固定作者代码为执行依据。此次重新取得 FoRIS `1aa02a11ef5f6673ed7a8a666ccf7d5586998d9e` 与 INSID3 `0c165a10cf52ab91f335883d06260de86854adbe` 的关键文件，逐字节与本地版本一致；代码来源和 SHA 在[核验收据](../../../evidence/research/w64_reference_head_graph_verification.json)。这里比较的是机制，不是宣布当前 SOTA 排名。

### 3.1 INSID3：先得到查询区域，再由参考选种子、聚合区域

[论文](https://arxiv.org/html/2603.28480v1)的核心分工是：跨图匹配采用去位置特征，查询内分组保留原始特征。具体实现如下，不能简单概括为“相似度阈值分割”。

1. 从黑色输入提取特征并做 SVD，建立500维位置子空间；跨图特征投影到其正交补。参考硬前景 token 平均成一个原型。
2. 查询 token 与参考前景原型相似度为正，并且其最近参考 token 被 mask 标为前景，才成为候选。代码所谓 forward/backward 是这两个判据的交集，**不是完整的往返循环一致性检验**。
3. 对原始查询特征做余弦距离的平均连接凝聚聚类，默认相似度参数 .6。代码没有显式空间连通约束。
4. 在有候选的簇中，选跨图相似度最高的种子；其他簇的分数由跨图相似度、与种子的原始特征相似度、候选覆盖比例相乘，超过 .2 则整簇接纳。最后上采样，可选 CRF。

这些实现细节见作者代码 [predict_mask](https://github.com/visinf/INSID3/blob/0c165a10cf52ab91f335883d06260de86854adbe/models/insid3.py#L122)、[候选和聚合](https://github.com/visinf/INSID3/blob/0c165a10cf52ab91f335883d06260de86854adbe/models/insid3.py#L275)、[聚类](https://github.com/visinf/INSID3/blob/0c165a10cf52ab91f335883d06260de86854adbe/utils/clustering.py#L8)。

**它已经解决了一部分“逐点噪声→区域完整性”的问题。** 参考负责定位，查询自身结构负责把同一目标的区域并起来。我们不能再把“从点到区域”“用图像内结构补全”本身当作尚无人处理的新问题。

**代码能直接确认的限制：** 一个非种子簇若没有任何候选，候选覆盖比例为0，聚合分数就为0；在默认正阈值下，CRF前该簇无法被选中。这为“外观不同、匹配不到的目标部分可能漏掉”提供一个具体机制。另一方面，整簇选择无法在一个已经混有目标和邻接非目标的簇内重新分界。至于这两项分别造成多少误差，本轮没有重做阶段消融，不能从代码直接报比例。

### 3.2 FoRIS：在对应之外，逐步校正前景证据和范围

[论文](https://arxiv.org/html/2609.03384v1)将方法组织为前景净化、定位、整合，并明确指出细长、碎片化目标仍困难。作者代码在 INSID3 式对应/聚类基础上增加了以下处理：

1. **有条件去位置。** 根据参考前景原型与查询全局特征的相似度决定是否去位置，默认门槛 .8。
2. **多原型与难负背景。** 对参考前景聚类，温度 .07 的 log-sum-exp 聚合多原型相似度；取最像前景的20%参考背景建立负原型，并将其对前景方向正交化。代码主分数含 .55 的背景权重。
3. **查询定位和区域先验。** 最近参考 token 投票提供候选；构建簇先验时另加每隔两格的稀疏空间网格。查询聚类结合特征、颜色、位置；种子选择和区域分数还利用候选占比。代码向主场加入 .20 的投票项和 .25 的种子簇项。
4. **冲突与簇级修正。** 对前景响应、投票、种子先验的不一致及前/背景共同响应施加惩罚，再按簇的前景优势和冲突程度重加权。最终连续场 minmax、双线性上采样、.5 阈值，可选 CRF。

执行依据：[原型和主场](https://github.com/Xi-Mu-Yu/FoRIS/blob/1aa02a11ef5f6673ed7a8a666ccf7d5586998d9e/models/foris.py#L369)、[区域先验与修正](https://github.com/Xi-Mu-Yu/FoRIS/blob/1aa02a11ef5f6673ed7a8a666ccf7d5586998d9e/models/foris.py#L600)、[连续读出](https://github.com/Xi-Mu-Yu/FoRIS/blob/1aa02a11ef5f6673ed7a8a666ccf7d5586998d9e/models/foris.py#L239)。权重以这份代码为准，不能将论文概括公式直接视为本地运行公式。

**FoRIS 比简单传播多做了什么：** 保留参考的多种外观，用近邻投票约束粒度，用查询簇整合范围，再以冲突项调整可信度。删掉这些步骤能简化方法，但需要承认可能同时删掉对某些大目标或多外观区域有用的处理。

**它的具体限制和待验证解释：**

- 参考 mask 仍被转成硬 token 标签；前景细小部分的质量及不同覆盖率没有完整保留。查询最终读出却是连续场上采样，不能误写成“FoRIS 只能输出硬 token 块”。
- 投票、原型和簇先验有很大部分来自同一套特征与相似度。它们相互一致时仍可能共同错；一致性本身不是独立的目标身份证据。
- 各簇分数主要依据外观、种子相似和候选比例，没有显式匹配“参考里哪些外观共同属于目标、哪些相邻部件必须排除”的区域关系。上下文信息可能隐含在 DINO 特征中，不能说完全没有；尚需证明现有读取遗漏了什么有用信息。
- 固定簇粒度和最终相对阈值没有给出逐例完整性判据。更复杂的修正有用，但没有因此解决所有范围错误。

一个应避免误读的代码细节：默认路径下，stage1 只给每个 token 乘正标量 gate；stage2 使用 ungated 特征，而后续用 gated 特征聚类前又做逐 token L2 归一化。精确算术下 `normalize(g_i f_i)=normalize(f_i)`，所以不能仅凭“feature gating”名称就认定它给这条默认路径增加了新的特征方向或聚类信息。这里只记录静态路径性质，不将浮点实现效应量化为消融结果，也不据此否定 FoRIS 的完整成绩。

### 3.3 SH：软点证据与简化原型，在同一查询图上融合

SH 的参考 mask 保留64×64软覆盖率。点证据为

`c_i = Σ_j exp(sim(q_i,r_j)/.05) y_j / Σ_j exp(sim(q_i,r_j)/.05)`。

参考标签作为软质量进入所有参考 token 的核迁移；之后用新颖度调制和 max-J 选强度，再在查询 kNN 图上做 λ=16 加权求解，得到 U0。另一支采用单前景原型减 .55 倍正交化难负背景，在同图上做排序引导求解，得到 M′。最终固定等权融合并 CRF。ρ>.9 时保留细结构回退，直接读出核迁移场。[SH代码](../../../scripts/x1012/w23_simple_pipeline.py)、[核迁移和图](../../../scripts/x1012/r5_candidate.py)

| 环节 | INSID3 | FoRIS | SH |
|---|---|---|---|
| 参考任务表示 | 硬标签近邻 + 单前景原型 | 硬标签近邻 + 多前景原型 + 难负背景 | 软覆盖率核迁移 + 单前景/难负背景原型 |
| 查询内结构 | 原始特征凝聚簇、种子聚合 | 特征/颜色/位置簇先验 + 簇级修正 | 去位置特征的互邻 kNN 图，连续求解 |
| 对不匹配区域的处理 | 候选占比可阻止簇被选中 | 主场、投票、簇先验与冲突项共同决定 | 匹配强度影响锚定、新颖度调制；两支平滑与融合 |
| 最后范围决策 | 簇分数固定阈值 | 连续场 minmax 后 .5 | 两支场固定 .5 融合，输出阈值 .5 |
| 已有优势 | 用单自监督骨干同时做对应和区域分割 | 多外观处理及多阶段范围修正 | 更简单的完整头；软质量和两种证据的实测互补 |
| 尚未解决的问题 | 候选遗漏、整簇误合并与固定接纳阈值 | 多证据仍可能共同错，范围修正缺少逐例可靠判据 | 两支仍可能共同错，软传播与融合不保证完整范围 |

三者都还需要可靠地确定当前查询的目标归属与完整范围；程度、具体样本和失效机制仍需配对验证。SH 的区别是真实的实现与归纳偏置差别，**不等于新增一个已证实的语义机制**。去位置、难负背景、正交化、图平滑、融合分别有已有工作基础；不用 FoRIS 完整头不能推出组件原创。

我们也并非从未跑过 INSID3：[R6](../archive/x1012_tasks/R6_query_space.md)保留1360例开发数据上的完整作者头、bilinear与CRF640对照。例如同批 COCO FoRIS64.79、INSID3+59.30；PACO42.41/40.37；iSAID50.43/54.77。方向并非所有域一致。这批是本地缓存适配、旧开发协议，不能和 W30 的新照片 SH 数字拼成三方同表，更不能据此断言当前 SOTA 次序。

## 4 我们真正留下了什么，又还缺什么

**已经有证据的价值：** 在当前固定协议中，SH 用较简单的两支证据取得了相对 FoRIS 的整体增益；非回退样本上的融合收益也被单独确认。细结构回退在另一来源 Fundus 图像上仍有优势。后者不能全归给融合，也还不能直接归因为“突破硬 token 上限”。

**尚未兑现的价值：**

- 参考条件改变时，既能保留同一目标的不同外观，又能排除很像目标的相邻部件或其他实例。
- 对应该扩大、应该缩小的查询，依据可观察任务证据作不同方向的决策，而不是在全体样本上统一移动尺度。
- 把软覆盖率、查询内部结构和完整性判定联系起来，解释为什么细结构有效、何时仍失败。
- 在相同训练、骨干、输入、后处理与算力条件下，证明相对直接近邻的新增价值。FoRIS 是工作基线，不是 SOTA 终点；INSID3 也不是必须预设“较弱”的方法。RSRM/FROST/FSSDINO 的重叠机制已在 [W35](W35_cvpr2027_readiness_REPORT.md) / [W36](../archive/x1012_tasks/W36_method_directions_REPORT.md)记录，不能通过只比较 FoRIS 绕开。

因此，后续动机不能写成“FoRIS 不行，所以我们加一个模块”。应写成“在一个明确的目标/干扰关系上，现有规则会做错哪一个决定；新规则使用什么此前未有效利用的信息改变它”。

## 5 对 W64 的具体复盘

### 5.1 当时为什么启动，预期价值是什么

W63 图例出现车门只剩下段、发动机混入机翼、部件响应落到另一实例等问题。W58 又表明部分灾难例不能只靠改阈值解决。因此，W64 想验证：**让参考完整 mask 选择一种查询关系，是否能把漏掉的目标部分接回来，同时避免把相邻非目标接进来。**

实施选择了旧 W39 B / Web B0 已写定但未运行的方案：16个末块 key head 加原 O24 图，共17候选；在参考上隐藏四象限，用可见标签做谐波补全，以平衡 Brier 风险选一个 head；查询端只替换 SH 图，其余保持，另设均匀分头图对照。正结果本应同时表现为完整分割增益、优于均匀图、修正两线共同错误。不是以参考风险下降作为成功条件。[运行前计划](../archive/x1012_tasks/W64_reference_head_graph_PLAN.md)

它有有限但明确的检验价值：区分“这一组图没有动作余量”与“有余量但参考选择失败”。**但我把一个现成、能实现的候选优先落实，没有先给出它比已失败的参考自验证更能跨图迁移的依据。这是立项判断不足。** 计划第一节已经写出了迁移风险，W39也已有条件提醒；风险被列出却没有实质影响优先级。

### 5.2 实际结果

固定原 S 六域90例，每域15例，先封存全部预测再评分。以下为六域观察槽宏平均，500次查询照片配对 bootstrap，单位 pp；不是全S或独立留出结果。

更直接的失败证据：

- 51例选择了非原图。它们的平均参考 Brier 风险下降 .02867，但查询逐例 IoU 平均下降 **.291 pp**；参考改善与查询增益的 Spearman 为 **−.037**。候选包含原图，取最小参考风险本就保证该风险不升，因此源风险下降不是一项独立的泛化证据。这些是描述统计，不是所有源风险与查询风险都无关的定理。

- 数值求解失败记录为0；90/90原SH/SH+整数I/U/面积复现。没有证据把本次阴性归为数值失败或基线跑错。

### 5.3 W64 哪些前提没有被充分考虑

**第一，源内补全和跨图选择是两回事。** 四象限仍共享同一参考图的外观、背景与完整RGB上下文；隐藏的是标签，不是重新采样另一张具有不同外观的图。保护带降低近邻标签捷径，却没有制造真实跨图变化。参考风险因此无法自行估计迁移误差。W64已观察到这个选择器没兑现收益，但尚未把失败量归因到某一种分布变化。

**第二，选择时的任务与使用时的任务不一致。** 参考评分用真实可见标签作Dirichlet锚、无数据项的谐波补全；查询端却是有偏的核/原型软证据、置信权重、λ16、两支融合和阈值。一个图适合传播正确锚点，不代表它适合修复错误且高置信的查询锚点。平衡Brier更小，也不保证经过上述链条后IoU更高。这一不一致在源码中可直接确认，其影响份额未单独消融。

**第三，“native key”不等于模型实际的关系推理。** W64使用RoPE前 key 的同头余弦 kNN，即 K–K几何；它不是原生 Q–K attention，也没有使用V及实际attention输出。一个key子空间的自相似能否表达目标归属，是额外假设。此前没有证据足以把它当已成立的语义关系。

**第四，结构条件化非常粗。** 参考对新增结构通道只传了“17张图选哪一张”的全局编号；查询每张候选图仍由查询自身特征生成。它没有把参考中目标内部的多种外观、目标与邻近负例的关系逐项对应到查询。原点证据仍传递参考信息，不能说整个方法只剩一个编号；但“参考选图”也不能等同“学会了参考定义的区域归属”。

**第五，没有充分区分“能做何种修正”与“能选中何种修正”。** 换图保留了原始两支证据和阈值，动作主要仍是重新传播。真正需要撤销错误高置信前景、补回不相似目标部分时，这个动作族是否合适，不能由谱图或参考补全自动保证。事后+1.846的逐例选择诊断说明有一定余量，不能证明它足以解决我们立项时引用的全部失败类型。

这五点是设计中的未闭合前提，不是五个已经量化的独立病因。不能通过事后各改一处，再把新一轮称为对W64的简单修复。

## 6 哪些不足值得我们补充

### 6.1 主问题：目标归属如何驱动区域补全与排除

我建议把主问题写成：**同一目标中外观不同的区域应一起保留，外观相似但不属于当前任务的区域应被排除；完整参考 mask 中什么关系能帮助查询作出这两个相反决定？**

这比“加更好的聚类/传播”“再选一个head”更具体，也直接对应 INSID3/FoRIS 的薄弱环节：簇的接纳主要依赖候选、原型和种子相似，而没有独立可靠的完整性/排除证据。SH改善了部分匹配和读出，却也没有给出这个判据。

可争取的补充是**任务条件下的区域归属证据**，并不是声称首次用区域、首次用参考或首次做粒度。一个后续方法至少应说清：

- 输入里用了什么：完整参考的前景及相邻非目标关系、查询中的区域关系，或编码器中尚未有效利用的上下文量；不能只换一个分数名称。
- 为什么会同时允许“补不相似的真目标”和“拒相似的非目标”：只有增加或只有抑制的规则不足以覆盖这两种错误。
- 相比 INSID3 的种子聚合、FoRIS 的多原型/簇先验，以及已失败的 W44 关系支持球，究竟新增了什么判别条件。
- 正确目标是否满足这个条件，近邻干扰为什么不满足。GT可用于这项开发诊断，却不能替部署时选择；最终仍由不读GT的固定规则产生完整mask。

现在还没有一个已被证据支持的具体算子满足以上要求。报告不能把“区域归属”这个名称包装成新方法，也不预定必须用树、森林、QK/V或图割。

### 6.2 范围选择继续保留，但只承担它能解决的那部分

69个灾难例已有好切点，不能因为 W64 失败就放弃范围。与其预设绝对概率、固定先验或再次换全局选择分数，更有价值的是弄清楚：现有可观测量在“应扩大”和“应缩小”的查询上是否给出不同方向，失效是没有方向还是量过冲。另一会话的 [W65](../archive/x1012_tasks/W65_extent_headroom_PLAN.md)正在围绕这一问题推进；本报告不接管、不重跑其工作，也不把它预先计为有效方法。

范围结果必须与场质量问题分开报告：一个切点选择器即使成功，也不能解决当前场本身排错的107个诊断例。相反，换场方法必须保住原来已有好范围的样本，不能只展示几个救回案例。

### 6.3 细结构是有正面基础的方向，但归因仍需成立

**10-16后续复核：匹配层对照和异源复测已经完成，不能再把它们写成全部待补。** Fundus指眼底血管任务；官方这批来自FIVES。当前可引用的官方同例结果是34.22 vs 19.13（200例），不是未经定位的“35 vs 17”。

| 既有证据 | 我们 | 完整FoRIS | 对研究判断的作用 |
|---|---:|---:|---|
| 同50对，1024输入，末层23 | 34.34 | 18.75 | 同输入末层的差距 |
| 同50对，1024输入，第19层 | 38.06 | 25.30 | 双方都换层仍领先+12.76 [10.90,14.84] |
| 同50对，1024输入，第20层 | 37.93 | 23.25 | 第二个匹配中间层仍有差距 |
| 另一来源Fundus-AVSeg，100例 | 33.11 | 22.40 | 异源复现；97/100例胜，双向区间+10.71 [9.14,12.25] |
| FIVES train新抽200例 | 34.78 | 18.96 | 同来源另一划分复现，194/200例胜 |

前三行是已曝光开发诊断、统一1024评分，不冒充完整官方层扫；后两行在运行前冻结方法及读法，详见[三层配对结果](../archive/FUNDUS_LAYER50_RESULT_20261013.md)、[W54](W54_fundus_fresh_PLAN.md)。FoRIS论文表10的第19层1024为33.4、其第20层2048为41.7，不能与我们这50例或1024输入直接相减。用户已取消2048输入，10-16再次明确不展开分辨率实验。

**现有证据支持的主线：** 在既有流程明显失效的细血管场景中，同一冻结编码器仍包含可用信息；简单核迁移读出取得大幅增益，并在匹配层对照和另一来源数据上保持。它说明不能将全部失败归于编码器缺少血管信息。相对“赢几个数据集”，这是更具体、可以追查机制的结果；尚不等于细长结构普遍解决、拓扑恢复或某一组件的因果证明。

所有这些血管例都走回退单线，优势属于SH、MFU、U共有的路径，不能归给SH的融合。软参考质量、对应方式、归一化，以及绕过后续区域处理的各自贡献尚未隔离。FoRIS也做连续上采样，不能宣称它受“硬token输出上限”约束。[W58理论复核](W58_theory_archive_REPORT.md#c-对细结构保留有实测依据的表示问题撤销假上限)

### 6.4 下一次立项应该改变什么

不需要为每个想法再跑一整套大诊断，但需要在启动前用已有证据回答三个问题：**它针对哪一种实际错误；提供什么比现有规则更有区分力的信息；正负结果能否区分候选容量、选择错误和输出代价。** 若只能回答“这个量理论上可计算”“参考上可拟合”“某个oracle很高”，立项理由仍不够。

已有失败保持为具体构造的结果；不通过后不补训练、不按域开关、不反复改门槛。候选一旦有完整输出净增益，再围绕其声称的贡献与FoRIS、INSID3及机制直接近邻做匹配比较。竞争方法的存在决定需要证明什么，不决定我们通过换研究设定逃开哪个困难。
