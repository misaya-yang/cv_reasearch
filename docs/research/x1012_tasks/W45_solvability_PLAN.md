## 1 动机

- **研究回到问题本身。** 问题是：只有一张参考图和它的 mask，用冻结特征，查询里的目标什么时候能识别，靠什么机制识别。是否赢 FoRIS 是这个问题解决后的结果，不是研究对象。“FoRIS 也失败”不能证明一个例子做不出来。
- **已知（S 半，描述性分析，见第 5 节）：**
  - SH+ IoU < .3 的灾难例占 20.3%，却占全部像素错误的 43.8%；
  - 在 190 个非回退的灾难例里，只换 SH 场 F 的阈值，平均 IoU 就从 .14 升到 .38；最佳阈值在 .5 以上的占 29.5%，低于 .3 的占 43.7%；
  - 66% 的灾难例预测面积大于 GT；
  - 灾难率随参考与查询的目标面积差距急剧上升：|log 面积比| > 3 的例子中有 65.5% 是灾难例；查询目标 < 2% 画面的例子中有 45.1%。
- **需要可证伪的“难例”定义。** 对每个例子依次问三层：
  1. 查询特征本身能否分开目标（表示）；
  2. 参考定义的分类器能否迁到查询（迁移）；
  3. SH 的排序是否已包含目标（读出）。

## 2 设计

**样本：** W37–W43 同一批 1,285 个 S 例。T 半和新照片留出都不读。

**特征：** SH 实际使用的去偏 O24 token，取单位向量（参考 r、查询 q，各 4096 × 1024）。结论只针对这一层表示，不推广到编码器的其他层或其他通道。

**token 标签：** 16×16 平均池化的覆盖率（查询用 GT，参考用 mask）。

**三个探针（ridge 回归覆盖率，加偏置，λ = 1，事先固定）：**
- **P_Q（表示上限，用查询 GT）：**
  - 2 折交叉拟合：把 64×64 token 网格按 8×8 的块做棋盘划分，用一半训练、预测另一半，再互换；
  - 每个 token 的预测都来自没见过它的模型。8×8 块是为了减少相邻 token 之间的泄漏。
- **P_R（迁移）：** 在参考 token 上拟合，直接用到查询 token 上。
- **F（读出）：** SH 在 CRF 前的场。

**每个场的两种读出（token 场先按 `lab.up` 双线性上采样到 1024）：**
- **最佳阈值 IoU：** 在场值的 120 个分位点上取最高 IoU。这是 oracle，只作诊断；
- **自然阈值 IoU：** 探针取 > .5，F 取 > .5（即 SH）。

**口径：** 逐例 IoU，按例分类计数；另报 class mIoU 的十域均值作为汇总。

## 3 读法（运行前写定）

1. **实现检查：** F > .5 与 W23 SH 的 I/U 一致 ≥ 1,280/1,285。
2. **对 SH+ IoU < .3 的灾难例逐例分类**（按顺序取第一个满足的类）：
   - **表示不足：** P_Q 最佳阈值 IoU < .5。在这层特征下，即使用查询自己的标签也分不好；这些才是在本表示下的难例。
   - **读出失败：** F 最佳阈值 IoU ≥ .5。排序里已有目标，错在面积或阈值。
   - **迁移失败：** P_R 最佳阈值 IoU < .3。信息在查询特征里，但参考定义的分类器没有迁过来。
   - **其他：** 其余情况，即迁移部分成功但 SH 的排序没有用好。
3. **对下一步的含义：**
   - **表示不足占多数：** 在这层特征上没有方法能救这些例子。下一步要换信息来源（其他层、key/attention），而不是改读出；
   - **读出失败占多数：** 主攻范围或阈值的决定（这正是 W14 的“排序对、范围错”在灾难例上的极端形态）；
   - **迁移失败占多数：** 主攻跨图迁移，即参考定义的概念怎样在查询里重新定位。
   - 不预设哪一类赢，也不按论文需要挑类。
4. **非灾难例也报告同样的三层量，作为对照。**

**判定与含义：**
1. **真难例（在这层 token 特征的线性读出下）只占灾难例的 37.5%，集中在 Fundus、Road、LVIS。** 它们是细血管、细路和极小物体：16 像素的 token 本身装不下这些结构。救这些例子需要 token 以下的信息（像素级 RGB 或别的层），改读出没有用。这是“这层表示下做不出来”的可证伪依据，而不是“FoRIS 也失败”。
2. **其余 62.5% 的灾难例在查询自己的特征里是可分的。** 交叉拟合探针的最佳阈值 IoU ≥ .5，所以不是难例。其中：
   - **COCO、PACO、SUIM 以迁移失败为主：** 查询特征能分开目标，但从参考学到的线性分类器在查询上找不到它（P_R < .3），SH 的排序也没有；
   - **ISIC、PASCAL-Part 以读出失败为主：** SH 的排序已包含目标，错在面积。ISIC 例子里参考 mask 几乎覆盖全图，就是这一类。
3. **从 SH 到表示上限的差距**（灾难例 .136 → .606，非灾难例 .682 → .811）可以分成两段：
   - 读出：同一排序下只换阈值，.136 → .340、.682 → .736；
   - 排序或概念：.340 → .606、.736 → .811。
   - 两段都不小。在灾难例上，排序这一段更大。
4. **直接从参考拟合一个线性分类器（P_R）远不如 SH**（38.3 对 53.6）。参考上定义的方向不能直接搬到查询，这正是“迁移”问题的核心。

## 更正（2026-10-15，用户指出）

**“表示不足”的推断不成立，判定 1 撤回，该类改称“线性探针失败”。**
- P_Q 是一个固定的线性岭回归探针（λ = 1），在 token 级上以 8×8 token 块棋盘两折交叉拟合。它的失败只说明“这个探针在 token 级分不开”，不能说明信息不在特征里：非线性读出、更细的读出、别的层都没有检验。原文把 P_Q 叫作“表示上限”“线性上限”，也不准确，它只是一个探针的成绩。
- **探针设计本身会制造失败：** 98 个“表示不足”灾难例中，26 例有一折训练时没有任何正例 token（覆盖率 ≥ .5），37 例少于 3 个（LVIS 27 例）；正例 token 数中位数 18。这些例子里探针根本学不到前景。
- 同时，W49 的“分辨率不够”也已撤回（见 W49 计划“更正”节）。所以“真难例只占灾难例的 37.5%、集中在 Fundus/Road/LVIS、改读出没有用”这一判定撤回；“读出失败”“迁移失败”两类的定义依赖 P_Q ≥ .5，作为描述保留，但不再表示“在查询特征里可分”的证明。

### W58 对训练支持解释的进一步核对

原探针拟合软覆盖率 y，不是 y≥.5 的二值标签。原 98 例中“无 y≥.5 token”为 26 例，但真正任一训练折无 y>0 token 的只有 **9 例**；新 85 个未解决例中分别是 24 与 **7 例**。因此不能据“无硬多数 token”说探针没有任何前景监督或根本学不到前景。完整前景质量/计数见 [W58 支持量证据](../../../evidence/research/w58_probe_support.json)。
