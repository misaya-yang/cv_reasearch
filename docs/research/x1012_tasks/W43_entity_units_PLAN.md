# W43：实体层面的错误是“选错分量”还是“分量内部错”

2026-10-15 写定。第 1–3 节在运行前固定，执行中不改。

## 1 动机

- **W41：** SH 的像素错误有 55.3% 在两线共同区，凸融合与 CRF 都动不到。
- **W42：** 共同错误有 79% 在边界带外，全部错误有 67.6% 在带外。主体是实体层面的整块多取或漏取。COCO、ISIC 的带外共同错误占该域错误的 43.7%、54.1%。
- **实体层面的动作有两类，需要的信息不同：**
  - **选择：** 整块删去 N 的某个连通分量，或整块补上 N 完全没碰到的 GT 分量（漏掉的实例）。只需判断“这一整块是不是目标”。
  - **分割：** 错误嵌在一个大体正确的分量里（多带了相连的背景或别的部件，或漏了相连的部件），必须先把分量切开或往外长。W32 的 key 分组属于这一类。
- **本任务回答：** 用 SH 自己的连通分量做单位，选择类动作的容量有多大，带外错误中有多少落在“可整块删除”的分量里、多少是“漏掉整个实例”。

## 2 设计

**样本：** 同 W37–W42 的 1,285 个 S 例，含回退例。T 半和新照片留出都不读。

**输入：** N = SH（CRF 前），用 `w42_ordered_cut.capture`；带 B、区域 C0/C1/D 与 W41、W42 相同。

**单位：**
- N 的 8 连通分量：每个分量记面积、TP、纯度 = TP/面积；
- GT 的 8 连通分量：每个记与 N 是否有交。

**oracle（只作诊断）：**
- **O_del：** 删去纯度 < J/(1+J) 的 N 分量，J 为该例 N 的 IoU。这是 [W39 A](W39_A_mechanism_REPORT.md) 式 (4) 的删除条件，按例近似；
- **O_add：** 补上与 N 完全不相交的 GT 分量（整个漏掉的实例）；
- **O_sel：** 同时做上面两项。

**错误归类：**
- 带外共同 FP（C1 ∩ 带外 ∩ N ∩ Gᶜ）按所在 N 分量的纯度分五档：[0, .1)、[.1, .3)、[.3, .5)、[.5, .9)、[.9, 1]；
- 带外共同 FN（C0 ∩ 带外 ∩ G ∩ Nᶜ）分两类：所在 GT 分量与 N 不相交（漏实例），或相交（漏的是已检出物体相连的部分）；
- 另报全部 FP、FN（不限区域）的同样归类。

**口径：** class mIoU，CRF 前，相对 N，十域等权；区间用 `w37._boot`。O_C（W41）作为对照。

## 3 读法（运行前写定）

1. **实现检查：** N 与 W23 SH 一致 ≥ 1,280/1,285。
2. **选择类够不够**（十域 mIoU）：
   - **O_sel ≥ 0.5·O_C（O_C = +16.48）：** 实体层面的错误有一半以上能靠整块选择分量来修。下一个方法应是分量级的验证或选择，并且要用与 W31（CLS 示范匹配）不同的信号。
   - **O_sel < 0.5·O_C：** 错误主要嵌在大体正确的分量内部。下一个方法必须能切开或生长分量，属于 W39 B 的关系或森林一类；“对分量打分”这条路的上限不够。
3. **一并报告：**
   - 带外共同 FP 在各纯度档的占比，其中 < .5 的部分可以视为“可整块删除”；
   - 带外共同 FN 中“漏实例”的占比；
   - 逐域结果；每例分量数的分布。
4. 这是诊断，不是方法；oracle 用了查询 GT，不作任何选择器。
