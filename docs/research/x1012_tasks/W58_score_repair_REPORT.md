# W58：W45/W49 精确计分修复、原 S 半重算与根因边界

2026-10-15。按 [W58 计划](W58_score_repair_PLAN.md)完成。原 W23 S 半 1,285 例，CPU 缓存特征；未读取 T 或新照片留出，未启动新候选或编码。未操作 W57。

**结论：** 计分缺陷确实影响小目标分类，但不能用它解释全部研究困难。修正后，261 个灾难例有 69 个在现有 SH 场中存在 IoU≥.5 的阈值，107 个查询探针达到 .5 而 SH 场达不到，85 个两者都未解决。原 60 个“分辨率不够”样本中的 21 个，在原覆盖率场上已经可以达到 .5。所有“探针/覆盖率低分证明特征无信息”的结论撤回。

## 1 修了什么

旧 `best_cut` 只扫描 `quantile(field, linspace(0,.999,120))`。它既不包含所有可实现切点，也不保证包含自然阈值 .5；相邻高分位之间约 0.84% 的全图像素，容易跳过小目标。W49 用排序重写了相同的粗扫描，二者相等只能证明共同实现一致，不能证明最优。

修复后的 [diagnostic_metrics.py](../../../scripts/x1012/diagnostic_metrics.py) 精确扫描不同分数组的边界，并列分数一起进出，包含空/全预测，使用严格 `>` 与项目 `I/max(U,1)` 约定。W45/W49 共用该实现。主诊断按自然 IoU 的 valid 区域评分，另存全画布精确值；本批全部 W45 字段和 W49 三网格的两种精确口径一致，因此实际数值修正来自阈值搜索。

自然预测、O24、参考、λ=1、空间交叉拟合划分、上采样与 SH 完全保持。PQ 训练仍沿用原实现对 GT/ignore 的处理，本轮只修评分；它继续是一个指定探针，不是最佳模型族。

### 3.4 探针训练支持：软标签与硬多数 token 不能混淆

另一个会话记录原 98 例中 26 例有一折没有覆盖率≥.5 的 token。W45 实际拟合的是连续覆盖率，因此这不等于没有正监督。本轮按同一 FOLD/GT 精确核对：

| 分组 | 例数 | 任一训练折无 y>0 token | 无 y≥.5 token | 少于 3 个 y>0 token |
|---|---:|---:|---:|---:|
| 原 representation 组 | 98 | **9** | 26 | 13 |
| 新未解决组 | 85 | **7** | 24 | 11 |

只有 y>0 数量为零才意味着该折没有任何前景监督。低质量/稀少支持会限制所测探针，但以上仍不是整个特征不可解的证据，也没有证明更换划分就会改善部署。逐例前景质量与计数见 [支持量核对](../../../evidence/research/w58_probe_support.json)。

## 4 W49 的修正：重建困难仍存在，硬上限不成立

原 60 个低 C64 的灾难例中，**21 个精确 C64≥.5，剩 39 个**。这 39 例分布为 LVIS 13、SUIM 2、Fundus 14、Road 10。

- 新 85 个“探针未解决”中，39 个 C64<.5，46 个 C64≥.5。
- 在 39 个低 C64 样本中，32 个 C128≥.5（82.1%），39 个 C256≥.5（100%）。这只是 GT 重建在更细网格上的表现，不是提高输入分辨率后模型会恢复的预测。
- 全部 1,285 例里 C64<.5 为 126 例（9.8%）。低分说明该覆盖率构造有几何损失，不能说任意同网格分数场都不可能更好。

**具体反例：** LVIS `new_f381e853352b0fe2e703` 的精确覆盖率 C64 为 .6566，已有 SH 场的阈值成绩至少 .6824。新全量账本共有 3 例 F 精确阈值成绩超过精确 C64。这直接否定“真实覆盖率场是全部标量场上界”。

在旧账本中，982 例 N64 自然阈值成绩高于所报近似 C64；W45 的 F/PQ/PR 分别有 140/327/65 例自然成绩高于旧“最佳值”。其中许多差距小，但足以说明原实现并未计算所宣称的最优值。新实现全部消除这类矛盾。

## 5 依赖 W45 的旧分析如何处理

- **W46/W47/W48/W50：** 导入旧 `best_cut`，历史 oracle 数字仍是粗扫描，不能和新 W45 混算收回率或当精确上限。本轮未重跑这些实验；自然预测数值保留。W46 对齐失败不证明分布偏移不存在，W50 仅部分完成，不能作主因排除。
- **W48 自参考分组：** 复用已封存 self0 的自然 I/U，按新组重汇总。69 个有好阈值例的自参考均值为 .841；参考探针缺口组 .729；SH 分数组 .680；未解决组 .346。该实验含答案，不能据此把损失因果拆成“迁移 22 点、读出 8 点”。未重算 self/mis oracle，因此撤回 .358/.248 的精确比较用法。
- **W51 分桶：** 全体灾难例的传播 FP 25.2%、两边都不像 19.9% 等数值不依赖 W45，保留为操作性描述。按旧 W45 类的子组表失效；新子组的所有分桶见 W58 汇总。新未解决组混合错误 51.1%、传播 FP 34.5%；参考探针缺口组传播 FP 25.4%、两边都不像 24.8%、竞争者 18.7%。这些比例是逐例错误占比平均，不是可恢复 IoU 或因果贡献。
- **W52/W53：** 由旧难例比例与“必要条件”推导的研究优先级不沿用。特定层级失败不证明粒度不可识别；结构本身不是唯一必需路线。
- **W54/W55/W56：** 实测分数保留，纠正硬 token 上限、反事实范围及相关性归因；详见 [理论审查](W58_theory_archive_REPORT.md)。W57 原样保留。

## 6 修正后到底能确定哪些问题

1. **部分失败确实可由同一个 SH 场改变阈值显著改善。** 69/261 是存在性证据；部署时如何选正确阈值仍未解决，不能把 oracle 当方法收益。
2. **另有 107/261 不能只靠 SH 全局阈值达到 .5，而查询监督探针可以。** 这证明原有表示/探针合同下存在未被当前 SH 场利用的可读信息；它仍没有指出具体的跨图机制。灾难例上 F 的精确均值 .355，说明“排序都对，只差面积”依然不成立。
3. **细小目标的覆盖率重建确有损失，但目前没有证明任何一例对整个冻结编码器不可解。** 85 个探针未解决与 39 个低 C64 是待解释集合，不能当不可能性证书。
4. **参考质量先验、minmax 的相对尺度、凸融合的共同错误限制是代码/代数事实。** 它们的实际净责任需完整干预；W57 正检验其中一条，不据本轮另开同类实验。
5. **跨图证据和读出同时存在缺口，未发现一个能解释全部域的单一根因。** ISIC 14/20 有好阈值；COCO 18/23 为探针见证的 SH 分数/参考迁移缺口。后续应按这些可证实差别设计方法，而不以“最多的桶”自动宣布共同病因。
