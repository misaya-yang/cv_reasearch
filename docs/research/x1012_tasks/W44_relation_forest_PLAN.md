# W44：参考关系森林——从已检出部分沿图像内部连接增删（W39 B §5 的一轮运行）

2026-10-15 写定。第 1–3 节在运行前固定，执行中不改。定义取自 [W39 B](W39_B_structure_REPORT.md) §5、§9.2，以及它引用的 [W34 A8](W34_A8_spectrum_REPORT.md) §6.2–6.4 与 [W34 A2](W34_A2_partition_REPORT.md) §10.3–10.4。本计划只把它冻结成一轮运行，不改 W34/W39 的文件。

## 1 动机

- **W41：** SH 的像素错误有 55.3% 在两线共同区，凸融合与 CRF 都动不到。
- **W42：** 共同错误有 79% 在边界带外，主体在实体层面。
- **W43：**
  - 带外共同 FN 有 91.1% 连在已检出的物体上，问题在于“生长”；
  - 带外共同 FP 有 73.4% 在低纯度分量里；
  - 只做分量选择的上限是 +5.46，不够。
- **关系森林正对这一形态：**
  - 参考 mask 告诉我们，哪些相邻 token 关系属于“前景内部”、哪些属于“前景边界”；
  - 把这些关系迁移到查询，建一片不跨越边界关系的森林；
  - 每个 token 看它沿森林连到正、负终端的最强瓶颈，强的一方决定标签；
  - 它不需要两线先出现分歧，就能增删（W39 B §5.3）。
- **本任务回答：**
  1. 这片森林能否把两线共同漏掉的相连部分长出来、删掉干扰，净提升 SH；
  2. 若不能，失败属于 W39 B §9.3 的哪种形态（错桥、终端错、不可达）。

## 2 设计

**样本：** 同 W37–W43 的 1,285 个 S 例。回退例（rho > .9）一律保持 SH 不变。T 半和新照片留出都不读。

**输入：**
- **A0：** SH 在 CRF 前的输出（`w42_ordered_cut.capture`）；
- **o：** SH 实际使用的去偏 O24 token，取单位向量；
- **k：** 冻结编码器末层 attention 在 k_norm 之后、RoPE 之前的 16 个 key 头，取 patch token。由 1024 输入单次前向得到，参考与查询各一次，与 W32 的取法一致；
- **参考覆盖率 y：** 来自 `mask1024` 的 16×16 平均池化；
- **终端用的相似度：** SH 的核相似度，即两图均值中心化后单位 token 的余弦（W40 已核实它能复现 c32）。

**关系向量（A8 式 (3)）：**
- 对每张图的 64×64 token 网格，取 8,064 条 4 邻接边；
- z(e) = [(1 − o_i·o_j)/2, {‖k_i^h − k_j^h‖² / (‖k_i^h − k_j^h‖² + 2v^h)}_h]，v^h 为该图该头 key 的方差；
- 只保留参考和查询中方差都为正的头；
- 两个关系向量的距离 = 各维平方差均值的平方根。

**参考关系（A8 式 (4)）：**
- ℓ = 1[y ≥ .5]；J = 两端都为前景的边，C = 两端标签不同的边；
- ξ_r = min(|2y_i − 1|, |2y_j − 1|)；
- δ_r = 到另一类参考边的最小距离；δ_r = 0 或 ξ_r = 0 的边不投票。

**查询边支持：** s_c(e) = max_r [ξ_r − 2d(z_Q(e), z_R(r))/δ_r]₊，c ∈ {J, C}。

**森林（A8 §6.4）：**
- 按 s_J 降序（并列按端点的行优先序）做 Kruskal 合并；
- 合并后的树若会包含某条 s_C > 0 边的两个端点，就拒绝这次合并。

**终端（A2 §10.3）：**
- 查询 token 与参考 token 互为最近邻；
- 最近的参考 token 必须是纯前景（y = 1）或纯背景（y = 0），且该类最大相似度严格大于另一类；
- 混合 token、平票都不建终端。

**标签（A2 式 (16)）：**
- κ± = 森林中到同类终端路径上的最大瓶颈；终端自身记为 1，无路径记为 0；
- κ₊ > κ₋ 记为 +，κ₋ > κ₊ 记为 −，相等则未定。

**输出臂（全部在 CRF 前；回退例都等于 A0）：**
- **F5（主臂）：**
  - 只改 token 级标签与 A0 不同的 token：A0 的 token 多数（覆盖率 ≥ .5）为背景而森林给 +，整块置 1；A0 多数为前景而森林给 −，整块置 0；
  - 其他 token 保留 A0 的像素。
  - 这是对 W39 B “只编辑这些单元中 A0 原本需要改变的像素”的解读，目的是不让边界 token 被整块改写。
- **F5lit（字面版本）：** 所有 + token 整块置 1，所有 − token 整块置 0。
- **FC（五版本一致，W39 B §5.2）：**
  - 完整参考，加四个版本：各删去参考的一个象限，外扩一个 token 的保护带；
  - 删块版本只用两端都可见的参考边、可见 token 上的终端，δ 在可见边内重算；
  - 五个版本给出同一个严格标签才编辑，编辑方式同 F5；
  - 任一版本缺少 J 或 C 边、或缺少可见的纯正、纯负 token，整例输出 A0。
- **FD（区域控制）：** F5 只在两线分歧区 D 的像素上生效，共同区保持 A0。
- **AC（位置控制）：** 与 F5 相同的新增与删除像素数；新增取 A0 外 F 最高的像素，删除取 A0 内 F 最低的像素。
- **F5+：** CRF(F5)，与 W27 的 SH+ 同合同比较（回退例不加 CRF）。

**整例回退到 A0：** 参考 J 或 C 边为空、没有有效 key 头、纯正或纯负参考 token 为空。

**封存后才读 GT 的诊断：**
- 查询边中 join、cut、未知的比例；
- 森林的加权错误 join 比例：Σ s_J·1[t_i ≠ t_j] / Σ s_J，t 为 token GT 多数标签；
- 正、负终端的正确率；
- 可达率：GT 前景 token 中 κ₊ > 0 的比例；带外共同 FN token 中被判为 + 的比例；
- 编辑按区域 C0/C1/D 的四种计数与 W39 A 式 (6) 的归因。

**口径：** class mIoU，十域等权；区间用 `w37._boot`。

## 3 读法（运行前写定）

1. **实现检查：**
   - A0 与 W23 SH 一致 ≥ 1,280/1,285；
   - 回退例各臂等于 A0；
   - 没有任何查询边同时 s_J > 0 且 s_C > 0（A8 命题 5）。
2. **方法验收（主臂 F5）：** F5+ − SH+ ≥ +1.0，十域区间下界 > 0，且 ≥ 7/10 域 ≥ 0，才写方法验证计划（读 T 一次）；否则不读 T。FC、F5lit 只作次要报告，不替换主臂。
3. **机制（按 W39 B §9.2–9.3 的形态报告，不设额外门槛）：**
   - F5 的归因中 C0 + C1 净正：森林确实修到了共同错误；
   - F5 − FD > 0：分歧区以外的编辑有贡献；
   - F5 − AC > 0（区间 > 0）：森林选的位置比按 F 边际取同样数量的像素更好；
   - **F5 − A0 ≤ 0（十域均值）：** 关闭这个森林构造（这组定义）。按诊断归入以下形态之一：错桥（加权错误 join 高）、终端错（终端正确率低）、不可达（GT 前景可达率低）。不在看过结果后改关系向量、支持球、合并规则或编辑方式。
4. **运行前冒烟测试（4 例：COCO、PASCAL-Part、iSAID、ISIC）观察到的结构性质，不改读法：**
   - 4/4 例没有任何查询边获得 cut 支持（s_C > 0 为 0），森林的“不跨越边界”约束实际上没有触发；
   - 原因：参考 C 边至少一端多为混合 token，ξ 小；它到最近 J 边的距离 δ 也小，支持球半径 ξδ/2 很小。
   - join 支持只覆盖 6%–26% 的查询边；正终端很少（COCO 2 个且都错）；
   - 各臂相对 A0 在 ±0.6 点以内。
   - 这些是 A8/A2 固定定义的行为，全量照原定义运行，不改支持球、终端或编辑方式。
5. **资源：** 编码器在 MPS 上，同一时间只有这一个 MPS 进程（W30 暂停中）。单进程，torch 2 线程，nice 19。
