# W03：独立候选的增益集中在哪一类任务

2026-10-13。只读 W02 的 13,613 例逐例 I/U，并为每例补上参考 mask 与 query GT 的几何描述（面积占比、宽度估计 = 4×距离变换均值，1024 帧像素、连通域数）。无新增编码，无新预测。候选 = 冻结的 R1 VP_UN（.5，ρ>.9 回退 T），对照 = 完整 FoRIS（含 CRF）。分数为 (dataset, fold, class) 池化 I/U 后槽等权，区间为按 query 照片成组的配对 bootstrap。全部配对已曝光，这是开发测量。

**结论。** 增益随目标的典型宽度单调下降：类别典型参考宽度 <32 px（2 个 patch）时 +3.75，32–64 px +1.78，64–128 px +1.07，>128 px −0.17。去掉 Fundus 后数字几乎不变。候选的专长是“细粒度目标”（部件、细小物体、细结构），不是单个数据集；专长的边界在约 8 个 patch 宽。

## 3 边界与反例

- DeepGlobe 道路：参考宽度 8–16 px，属于细结构，但 +0.60 [−2.71, +3.33]，没有受益。
- SUIM：参考面积 <2% 的 202 例为 −8 到 −23。这些是大片场景类在参考图里只露出一小块，参考很小而 query 目标很大，不属于细粒度目标。按“参考小”定义这一类会把它们错收进来；按类别定义不会。
- COCO 全部类别典型宽度 >32 px，是十域中目标最大的；它的负差值与 LVIS、PACO 中 >128 px 类别的零或负差值是同一现象。
- PASCAL-Part 为正但没有剂量效应，增益只有约 +1。
- 细粒度区间的绝对分数仍然很低（LVIS <16 px 类 12.9 → 19.0）。
- LVIS 子集的宽度门槛是看过结果后划的，只能作描述，不能当作事前定义的评测集。

## 4 含义

- “专精一类”有现成的多数据集支持：两个部件集、一个血管集、LVIS 细小类别、航拍小目标，共 7,180 例，去掉 Fundus 仍为 +3.13。
- 这一类之外，候选与 FoRIS 持平（+0.04）。
- 1360 例开发集上，不借用任何 FoRIS 步骤的纯核后验 `c`（软覆盖标签、min-max>.5）在 PASCAL-Part、PACO-Part、Lung、Fundus、DeepGlobe 上已不低于 FoRIS（55.8／44.6／89.4／34.1／31.7 对 55.6／42.4／87.2／19.0／29.4），在 COCO、LVIS、SUIM、ISIC 上明显更低。细粒度区间的增益是否来自 `c` 本身，由 `NEXT_EXPERIMENT_PLAN_20261013.md` 的 T2（全池组件消融）回答。

## 5 九窗口落在同一条轴上

把 B2（`../cv_data/a/x1012_B2/report.json`，1108 例，LVIS 408／PACO 600／DeepGlobe 100；query 切成 3×3 个 512 px 窗口各自以 1024 编码，参考保持整图，读出为不含 FoRIS 组件的 T 或 IND0）的逐例结果按同一个类别典型宽度分档。逐例平均 IoU，窗口减整图：

| 类别典型参考宽度 | n | T：整图 → 九窗 | 差值 | IND0：整图 → 九窗 | 差值 | 九窗更好的例数占比（T） |
|---|---:|---|---:|---|---:|---:|
| <16 px | 144 | 28.6 → 34.3 | +5.7 | 28.7 → 35.3 | +6.6 | 83% |
| 16–32 px | 102 | 34.7 → 37.0 | +2.3 | 32.2 → 39.7 | +7.5 | 63% |
| 32–64 px | 222 | 45.0 → 43.3 | −1.7 | 47.8 → 47.8 | +0.1 | 49% |
| 64–128 px | 318 | 45.4 → 39.9 | −5.6 | 47.2 → 42.3 | −4.8 | 44% |
| >128 px | 322 | 48.7 → 37.3 | −11.3 | 50.8 → 39.1 | −11.7 | 29% |

- 交叉点在约 32 px（2 个 patch），与 §1 中整图候选增益最大的区间是同一处：目标宽度相对 patch 网格的大小同时决定了两件事。
- DeepGlobe：B2 的 class mIoU 为 FoRIS 29.38、整图 T 31.75、九窗 T 37.56（+8.19 [+5.03, +11.11]），88% 的任务变好。道路在整图下只有 8–16 px 宽，放大两倍后才被网格分辨。
- LVIS 细小类别（<32 px，127 例）九窗 +3.6 到 +8.5；≥32 px 的类别约为 0。
- PACO 在所有宽度上九窗都更差（−3.5 到 −12.9），包括细部件。部件靠整体物体的上下文定义，裁窗后丢失。所以“细就放大”只对自成一体的细结构和小物体成立，对部件不成立。
- 用单个参考的宽度做门控（<32 px 才用九窗）：DeepGlobe 保留全部增益（逐例 30.4 → 36.4），LVIS +0.7（T）／+1.7（IND0），PACO −0.6／−0.5。

两个限制：

- 九窗口的收益来自观察分辨率，不专属于我们的读出：同 100 例上基于 FoRIS 的旧九窗区域法是 37.34（`NINE_WINDOW_EXECUTION_20261011.md`），与 37.56 持平；它在 LVIS600 上是 52.01 对整图 FoRIS 47.78，在 PACO600 上是 34.97 对 38.46。公平对照是“FoRIS 加同样的窗口”。
- 成本是九次额外编码（FoRIS 整图为两次）。九窗里包含四个互不重叠的角窗，可在不新增编码的前提下评估 2×2 平铺。Fundus 没有窗口缓存。
