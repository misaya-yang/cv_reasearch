# W57：去掉点证据里的“参考先验”项——参考大小渗漏是不是它造成的

2026-10-15 写定。第 1–3 节在运行前固定，执行中不改。

## 1 动机

- [W56](W56_contrast_boards_PLAN.md) 的图板和事后回归发现两类方法共有的“参考大小渗漏”：目标大小与数据集固定时，参考面积每大一倍，输出面积变大（弹性系数 a：SH+ +0.27，FoRIS +0.17，点线 U0 +0.35，原型线 M′ +0.14）。参考是目标 8 倍以上时，两者 IoU 都只有约 26，输出约为 GT 的 4 倍。
- 点证据的精确形式（W51 恒等式，r5 `independent`）：
  - c = df/(df + db)，df = Σ_j k_ij y_j，db = Σ_j k_ij (1 − y_j)，k_ij = exp(s_ij/τ)；
  - 等价地，logit c = log(N_F/N_B) + log(m_F/m_B)，其中 N_F = Σy、N_B = Σ(1 − y) 是参考的前景/背景 token 量，m_F、m_B 是前景/背景的核均值。
  - 第一项就是**参考自己的先验对数几率**，它直接进入查询的每一个判定。参考前景占 1% 时，它相当于在 F − B 上减去约 0.23（余弦单位）。
- **猜想：** 点线的参考大小渗漏主要来自这一项。把它换成与参考无关的常数，渗漏应明显下降，参考远大于目标的例子应明显变好。
- 这不是换方法，而是去掉公式中一个已识别的偏差项；以前的 label-shift 工作（mixture600）是“从查询估计查询先验”，结论是纯 label-shift 不成立。这里不估计查询先验，只去掉参考先验。

## 2 设计

**样本：** W23 S 半 1,285 例（含回退例，回退路径同样使用 c32）。T 半与留出不读。

**三个臂（冻结 SH，CRF 前；只替换 r5 `independent` 输出中的 c32 及由它派生的 ind0_32、indn_32，其余不变）：**
- **A0：** 原样（参考先验）。
- **P_c：** c′ = π₀·m_F / (π₀·m_F + (1 − π₀)·m_B)，π₀ = .088，即 S 半 1,285 个参考 mask 前景比例的中位数（只用参考，运行前算定）。
- **P_h（诊断）：** 同上，π₀ = .5。

实现：用 `independent` 返回的去偏特征与 y，按 r5 原式重算 sim、核、df、db；先以参考先验重算并核对与原 c32 一致，再替换先验，ind0/indn 用同一 kmeans 标签与 sim_max 重算。原型线 M′、log_e、back_f、rho 不变。

**评分：** 与 W23–W27 相同的十域 mIoU（CRF 前），500 次照片 bootstrap 配对区间；按 log₂(参考面积/GT 面积) 分档的逐例平均 IoU；W56 的回归系数 a、b。

## 3 预测与读法（运行前写定）

**我的预测：**
- **机制：** P_c 下 SH 的系数 a 从约 .27 降到 ≤ .15。
- **分档：** log₂(参考/GT) > 1.5 的例子（212 例）平均 IoU 提高 ≥ 3 点；< −1.5 的例子变化在 ±2 点内。
- **总体：** 十域 mIoU（CRF 前）P_c − A0 在 +0.5 到 +2 之间，ISIC 提升最大。
- **P_h：** 总体低于 P_c（大多数目标前景比例远小于 .5，等先验会整体偏大）。

**读法：**
1. 实现检查：以参考先验重算的 c 与原 c32 最大差 < 1e-4；A0 与 W23 SH 一致 ≥ 1,280/1,285。
2. **a 下降且失配分档改善、其余不变差：** 渗漏的主要通道就是这一项，去掉它是一个由缺陷推出的修正。下一步：T 半一次、新数据一次；再看 FoRIS 侧的同类项。
3. **a 下降但 IoU 不改善：** 渗漏不是 IoU 损失的主因，损失更多来自大小压缩（b）或原型线，记录后转向那边。
4. **a 基本不降：** 渗漏走的是其他通道（原型线、min-max、调制），这一项不是主因，猜想错误。
5. 只作检验，看结果后不调 π₀，不换臂。

## 结果

**2026-10-15 完成。** 1,285 例，中位 1.3 s/例。实现检查：以参考先验重算的 c32、ind0/indn 与冻结值的最大差均为 0；A0 与 W23 SH 一致 1285/1285。报告 `../cv_data/a/x1013_W57/report.txt`，证据 `evidence/research/w57_reference_prior_S.jsonl.gz`。

| 臂 | 十域 − A0（CRF 前） | 显著 + / − | 渗漏系数 a | 压缩系数 b |
|---|---:|---|---|---:|
| A0（参考先验） | — | — | +0.264 [+0.220, +0.317] | −0.456 |
| P_c（π₀ = .088） | **−0.95** | 3 / 4 | **+0.100** [+0.057, +0.142] | −0.463 |
| P_h（π₀ = .5） | −5.34 | 0 / 6 | +0.109 [+0.063, +0.160] | −0.521 |

- P_c 逐域：ISIC +3.89 [+0.6, +7.5]、Fundus +1.02、Lung +0.64 显著为正；PASCAL-Part −4.66、LVIS −3.96、Road −3.43、PACO-Part −2.87 显著为负；COCO、SUIM、iSAID 不显著。
- 按 log₂(参考/GT) 分档（逐例平均 IoU，A0 → P_c）：< −3 为 49.3 → 51.0；大小相当（±.5）为 63.8 → 60.9；+1.5～+3 为 45.0 → 45.2；> +3 为 26.4 → 29.4。失配 > +1.5 的 235 例 +1.13，< −1.5 的 232 例 −0.34。

**与预测对照：**
- 机制（a ≤ .15）：**成立**，a 从 .264 降到 .100；
- 失配 > +1.5 提高 ≥ 3 点：**不成立**（+1.13）；
- 失配 < −1.5 在 ±2 内：成立（−0.34）；
- 总体 +0.5～+2：**不成立**（−0.95）；ISIC 提升最大：成立；
- P_h 低于 P_c：成立。

**按读法 3（a 下降但 IoU 不改善）：**
- 点线上的参考大小渗漏，确实主要来自 c 里的参考先验项；去掉后渗漏下降六成。
- 但参考先验同时也是信息：在部件域和 LVIS，参考大小能预示查询目标大小（W56：PASCAL 组内相关 .74），去掉它就赔；在 ISIC，参考大小与目标大小无关（−.01），去掉它就赚。结果又是一次域间此消彼长，不是修复。
- 大小压缩 b 没有变化，说明压缩不是这一项造成的，W56 里“渗漏和压缩是同一件事两面”的猜测不成立。
- **结论（适用范围：S 半、SH 点线、这一种常数先验）：** 参考先验项不是可以直接删掉的“缺陷”。用参考的先验或用常数，各在一部分域上错；现有点证据恢复不出查询目标该有的范围。这是方法的失败，不是任务没有答案：旧 6,200 例协议审计（五域）没有发现完整输入对应多个合法查询答案，不能用“单参考天然有歧义”解释。看结果后不调 π₀。
