## 0. 一页结论

**核心问题的回答。** DINOv3 的表征没有输在"找不到目标"。在五个物体/部件数据集上，完整 FoRIS 的汇总召回都在 70–81%；COCO 上分数最高的 token 有 82% 落在真值上。它输在另一件事上：**每张查询图都会多圈出一块面积，这块面积的大小与目标多大无关，与召回多少也无关**。类 mIoU 在类内汇总交并，所以恒有

```
IoU_c = ΣI / Σ(g + F) = r_c · ḡ_c / (ḡ_c + F̄_c)        g 真值面积，F 误报面积，r 召回
```

小目标（LVIS）和大误报（PACO-Part）是同一个公式的两种取值。把误报拿掉、召回不动，五个数据集全部落到 75–82；现在它们散布在 42–61，这段差距全部来自 F̄/ḡ。

**为什么会这样。** 一张参考图给出了正例和它自己那张照片里的反例，但没有给出"不是目标的东西在查询图里最多能有多像"。现有流程用查询图自身的分数范围代替这个量（逐图 min–max 后取上半段），于是上半段总是非空，误报面积由场景决定而不由目标决定。全局排序 AUC 约 0.95 已经很高，但目标只占图 1–10%，这个 AUC 对应的误报率乘上九成以上的背景，面积就与目标同量级。**缺的不是更好的相似度，而是一个零模型：在候选区域内部把目标和误报分开的证据。** 仓库里候选内 AUC 最好的信号是 0.78–0.79，把误报减半（召回只让 5 点）需要 0.88。

**这把两周的正负结果放进同一张图。** 仓库里每个臂都只是在（召回，误报）平面上沿一条交换曲线移动，没有把曲线整体推开（第 2 节）。九窗"LVIS 有益、PACO 有害"不是部件粒度问题：两个数据集都是目标占图 <5% 时得分、>20% 时因目标被窗口切断而丢召回，PACO 只是大目标多。

**方向。** 由此推出的算法不是再换一种相似度或阈值，而是"**让参考裁决**"：先用高召回的候选（现有流程已够），再把候选拿回唯一有真值的那张图上检验——候选在参考图里解释了哪些背景，就用这些背景作反例，在候选自身的坐标系里用不依赖分数水平的秩统计量做取舍；参考图里找不到对应反例时明确弃权，交给第二个信息源（空响应/诱饵、联合编码）。每一步的前提都先用一个统一的量具测，过线才组装。

### 1.2 数据集差异可以移植

独立性模型（每例的 (r, F) 从同数据集里随机换一例）复现各数据集的逐例平均 IoU：62.7/62.1、56.5/57.8、61.0/58.8、43.1/44.3、45.6/43.8（实际/模型）；分档趋势也复现，个别小样本档有偏差（SUIM 1–5% 档 60.8 对 46.3）。把 LVIS 的目标配上 COCO 的 (r, F) 得 44.8，与 LVIS 自己的 43.9 几乎相同；把 COCO 的目标配上 PACO 的 (r, F) 得 38.3，把 PACO 的目标配上 COCO 的得 66.8。**LVIS 的误报面积与 COCO 相同（占图均值 3.03% 对 3.05%，中位数 1.00% 对 0.87%），难只因为目标小；PACO 的目标不小，难是因为误报面积是 COCO 的 3.5 倍（占图均值 10.58%）。** 数据集之间不需要各自一套机制来解释。

### 1.3 误报在哪里（COCO fresh600，64×64 token，FoRIS 响应）

- 质量的 64.5% 离真值超过 4.5 个 token，20.2% 在 1.5 个 token 以内。去掉远处的：60.32 → 71.04；去掉贴边的：→ 64.43。**主损失不是边界和细结构。**
- 69.5% 位于与真值相连的预测连通块里。按分数形态：42.5% 是"带着正确峰的连通块的低裙边"，25.5% 是错误的高峰，32.0% 是没有正确峰的低分区。主导形态是**从真目标向外漫出**，其次才是独立的相似干扰物。

### 1.4 例外：细结构域

DeepGlobe 道路不服从上面的独立性：召回只有 45.9% 且随目标增大而下降（ρ −0.36），无漏检天花板（63.94）高于无误报天花板（45.95）。原因可以从参考掩码直接读出：目标质量落在覆盖率 ≥90% 的 token 里的比例，Deep 是 0.02，其余队列 0.66–0.91。目标比一个 token 还窄，token 特征被背景主导。这是第二个体制（召回受分辨率限制），可以只凭参考掩码的几何合法地识别。预计 Fundus 属于同一体制（卡 A 检验）。

## 4. 统一解释：缺失的零模型

**已证实的部分。** (a) 第 1 节的加性结构与独立性。(b) 误报主要是远处的、与真目标相连的外漫。(c) 现有场上，候选内部的排序信息很弱：仓库在 LVIS 1400 例上实测 MEAN 引导场的全局 AUC 0.954，进入 FoRIS 最终掩码后 0.743（`evidence/local/m4/lvis_tail_signal1400_20261009.md`）；困难区域研究里最好的信号在 FoRIS 前景内是 0.78（PACO，APD 岭回归整图）和 0.79（Deep，局部四窗）。(d) 绝对水平不跨图迁移，而带界的相对证据（有界锚）能迁移。(e) 参考反例只在封闭世界（查询里出现了参考背景里的东西）有效。

**机制陈述（由上面推出）。** 单参考分割是一个只有正例和"本图反例"的判别问题。流程必须决定"多像才算"，而唯一不依赖水平的现成参照是查询图自己的分数范围，于是每张图都产出一块上半段。这块面积是场景和流程的性质：它在目标缺席时也应当存在（卡 C 检验），在窗口里会被再生产一次（九窗全收 ×1.49，已证实）。因此：

- 目标占比决定同一块误报值多少分（基率放大）；
- 放大、开窗只改变占比，本身不提供新证据，所以必须配一个"目标在不在这个视野里"的判断才有净收益；
- 换相似度、换图平滑、换切点都只是在同一条交换曲线上移动。

**换算成一个可测目标。** 在 FoRIS 掩码内部，"保留 95% 命中时还剩多少误报"记为 K95。按双正态近似，候选内 AUC 0.76 ↔ K95≈0.74；K95≤0.5 ↔ AUC≥0.88；K95≤0.25 ↔ AUC≥0.95。按第 1 节的公式，K95=0.5 约等于 COCO +3.9、PASCAL-Part +5.2、SUIM +2.9、PACO +6.8、LVIS +4.8；K95=0.25 约等于 +8.7 / +11.3 / +6.7 / +14.4 / +11.3。**项目的缺口可以写成一个数：把候选内 AUC 从 0.76 提到 0.88 以上。** 这个量与流程无关，在缓存特征上几分钟可测。

**泛化判据（对汇总 IoU 是恒等式，类 mIoU 近似服从）。** 一条规则在某数据集上保留命中的比例为 h、保留误报的比例为 k，则 IoU 上升当且仅当

```
(1 − h) / (1 − k)  <  θ_D ，    θ_D = ΣF / (Σg + ΣF)   该数据集误报占并集的份额
```

左边是规则的交换比（每删掉一份误报赔掉几份命中），右边只与数据集有关：PASCAL-Part 0.16，COCO 0.19–0.20，SUIM 0.24，LVIS 0.36–0.39，PACO 0.40–0.43；大目标数据集（ISIC、Chest X-ray）预计低于 0.1。仓库里的臂：九窗加接受在 LVIS 上交换比 0.21（得分），在 PACO 上 0.62（失分）；整图角色竞争在 PACO 上 0.21；LVIS 连通块 0.23；有界锚在 PACO 试点 100 例上 0.12、在全部 600 例上 0.23；MEAN 在 COCO 上 0.06。**交换比在 0.2 左右的方法只能在 θ 大的数据集（LVIS、PACO）上得分，到 COCO 已没有余量，到 PASCAL-Part 为负。这就是"不能跨数据集泛化"的定量形式。** 10 月 10 日新封存的验证正是这个形状：有界锚加参考岭回归在 PACO600 上保留命中 0.918、保留误报 0.638，类 mIoU +2.31；原样搬到 COCO200，保留命中 0.972、保留误报 1.099，两边都变差，类 mIoU −0.90 [−2.46, +0.36]（`evidence/local/parallel_signal_20261010/02_task_identity/ridge_coco_validation/`）。在 COCO 上它已经不在交换曲线上，说明参考侧的证据在开放世界里方向就是错的，而不只是代价太高。 通用方法需要交换比低于所有数据集的 θ：五个物体/部件数据集要求低于 0.16（K95≤0.5 对应 0.10）；θ 低于 0.1 的数据集上只能弃权或改走召回侧。交换比不是方法的常数（九窗在 PACO 上因大目标被切断而变差），必须逐数据集实测。

**合法的信息只有三处（假设，逐条对应实验）。**

1. 参考图的反例，但只在候选被参考图"支持"的地方用。做法是把查询候选拿回参考图：候选解释得和目标一样好的那些参考背景 token，就是这一对图像上真正会混淆的反例（有真值，可核对）。找不到时弃权。——卡 B。
2. 相对关系而不是水平。在候选自身的坐标系里（参考侧以"目标+混淆物"为中心，查询侧以候选为中心）比较；用秩统计量，它有不依赖水平的零点：查询 token 作为探针去检索参考图，把参考目标排在混淆物前面（AUC>0.5）才保留。——卡 B、卡 D。
3. 参考图给不出反例的开放世界误报（COCO 的相近类别物体）需要另一个来源：对任何概念都会亮的区域（空响应/诱饵），或让冻结编码器在一次前向里同时看到两张图。——卡 C、卡 E。

细结构域单独处理：由参考掩码纯度触发高分辨率读出（仓库已有九窗和细读出），不与上面的误报机制混用。

## 6. 算法方向：让参考裁决

```
候选   C = 高召回的初始掩码（现阶段直接用完整 FoRIS；它的召回与峰值命中率已够）
回投   对每个参考 token，取它与候选内查询 token 的最大相似度；
       参考背景中被解释得不差于"目标 token 中位数"的那些 = 混淆反例 N（参考真值在场，可核对）
裁决   在以 {参考目标 ∪ N} 和 {候选} 各自为中心的坐标系里，
       每个候选 token 作为探针检索参考图：把参考目标排在 N 之前的程度 = 证据 e（秩统计量，零点 0.5）
弃权   N 不足时 e 记为无证据，候选原样保留，交给开放世界证据（卡 C/E 的结果决定其形式）
输出   沿用仓库的有界锚规则，零证据时逐位还原 FoRIS
细结构 参考掩码纯度低于门限时改走高分辨率读出
```

增量开销是一次 4096×4096 相似度和若干排序，CPU 上低于 1 秒，不增加编码。与已有做法的区别：FoRIS/INSID3 的最近邻投票只看每个查询 token 的一个最近参考 token，且反例取全部参考背景并在每一级被 min–max 冲掉；这里的反例由候选在有真值的一侧"招供"出来，判别量对全部参考 token 取秩，决定点不依赖水平。需要查新的近邻工作：Matcher 的双向点匹配、CyCTR 的循环一致注意力、INSID3 的反向校验；它们都在点或 token 层面做一致性过滤，没有把"候选在参考图上的误差"当作反例来源。**这一方向的每个前提目前都是假设，卡 B 决定它是否成立。**

## 7. 通宵批次（2026-10-10 修订）

通用规定沿用仓库：冻结 DINOv3-L/16、1024 输入、不训练；查询真值不进入任何字段或规则；一个源的全部字段封存后才打开查询掩码；与完整 FoRIS（含 CRF）同批配对。第 5 节里的卡号对应：卡 A = 量具输出的底噪行；卡 B = 量具；卡 C = 量具里的外来参考诊断（完整版留到明天）；卡 D = 量具里的规则得分（粗粒度，完整版留到明天）；卡 E = `joint_encoding.py`。

### 7.1 一个量具同时回答五件事

`evidence/local/false_alarm_floor_20261010/inmask_evidence.py` 对每个数据集输出：

1. **底噪行**：FoRIS 类 mIoU、汇总召回、ΣF/Σg、θ_D、无误报与无漏检天花板、三个 ρ、回投混淆反例非空的比例。
2. **分离度**：每个证据字段在完整 FoRIS 掩码内的 AUC、K95、K90。
3. **规则作为真实掩码的精确得分**：掩码取"完整 FoRIS 限制在证据高于其自然零点的 token 上"，在存储帧（有原尺寸预测时即原图帧）计类 mIoU，报告相对完整 FoRIS 的差、逐例自助 95% 区间、h、k 与交换比。这是一个不含 CRF、按 token 取舍的粗粒度完整输出，足以回答"同一条规则在各数据集上是正是负"。
4. **掩码外**：同一字段能否把漏检目标排在真背景之前（AUC，以及只放进 1% 外部背景时找回多少漏检质量）。这是召回侧的读数，为 θ 很小的大目标数据集准备。
5. **外来参考诊断**：另一类参考在本查询上的上半段盖住了多少 FoRIS 误报和多少命中（P2 的特征级代理）。

字段共 17 个，全部在看结果之前固定：

|组|字段|用到的信息|
|---|---|---|
|对照|`fg_peak`、`foris_score`（仅 `--run` 源）|单侧相似度；FoRIS 自己的分数|
|参考反例，三种取法|`two_sided` / `two_sided_hard` / `two_sided_back`；`ridge_all` / `ridge_hard` / `ridge_back`；`back_auc` / `back_auc_hard`|全部背景；FoRIS 式难背景；候选回投找到的混淆反例|
|候选中心坐标系|`centred.two_sided_back`、`centred.back_auc_hard`、`centred.ridge_back`|同上，两图各自去掉共享的宿主分量|
|反向分配|`reverse`|每个参考 token 在查询 token 之间分配，目标与背景争夺同一个查询 token|
|同图诱饵|`decoy_relative`|参考背景聚成 8 个诱饵概念，各自按自己在查询上的相对刻度读出|
|查询自身结构|`seed_centred`|候选质心的哪一侧是最匹配的那些 token|
|诊断|`diag.foreign_contrast`|外来参考；不属于任务允许的输入，不参与选择|

规则有两处弃权，都不看真值：混淆反例不足 4 个时依赖它的字段在该例缺席，原样保留 FoRIS；规则若会删掉候选九成以上的面积，原样保留 FoRIS。

### 7.2 泛化检验是机械的

```bash
python3 evidence/local/false_alarm_floor_20261010/inmask_evidence.py summary --design paco coco --confirm lvis pascal_part
```

在设计集上按"最差数据集的差值"选一个字段（要求每个设计集都为正），然后原样报告它在确认集上的差值与区间；诊断字段和没有零点的字段不参与。设计集取 PACO-Part 与 COCO（一个封闭世界、一个开放世界），其余全部作确认集。判定在运行前写定：

- **通过**：确认集全部区间下界高于 −0.3，且至少一半确认集差值不低于 +1.0。→ 明天做完整版输出（有界锚、CRF、全协议）。
- **部分通过**：只在封闭世界数据集为正，其余因弃权接近 0。→ 得到一个"不伤害任何数据集"的部件，开放世界的误报看联合编码的结果。
- **否定**：没有字段在两个设计集上都为正。→ 末层双编码器证据不足以支持"让参考裁决"，第 6 节的裁决一步记为被否定，主线转联合编码和其他层。

### 7.3 命令

`--cohort` 是主要读法，对应 M4 上的真实存储：清单队列（`manifest.json`）加按输入哈希保存的原始缓存（O/24，4096×1024，FP32），token 通过仓库自己的 `RawFeatureCache` 与 `load_inputs` 读取，不重新前向；完整 FoRIS 掩码、分数场和查询掩码（含 iSAID 的 ignore）从队列各自保存的位置读。已知的几种布局自动识别：

|项|识别顺序|
|---|---|
|队列目录|目录本身，或其 `run/` 子目录|
|预测索引|`inference.jsonl`（逐行）或 `inference.json`（列表）；文件名字段 `filename` 或 `prediction_file`|
|FoRIS 掩码|`original/foris.crf`（尺寸取文件里的 `original_hw` 或清单的 `query_size_hw`），否则 `cli/foris.crf`、`cli1024/foris.crf`（1024 画布）|
|原始缓存 profile|`--profile`，否则队列 `config.json` 的 `raw_profile` / `profile_path`，否则 `raw_cache.json` 的 `profile_path`，否则共享 profile|
|分数场（仅作对照字段）|`fields/<同名文件>` 里的 `score`，否则 `source_score_index.json`；没有就跳过|

FoRIS 掩码由另一个 run 写出时，用 `--foris` 指向那个目录（按 `episode_id` 对齐）。`--branch O/12`、`QK/24`、`V/24` 可读其他已缓存分支。`--run` 仍可读 `scripts/run_m4_baselines.py infer` 的输出目录（PACO 四折）。

先看读取函数在真实队列上识别到了什么（不打开查询掩码、不写任何文件）：

```bash
python3 evidence/local/false_alarm_floor_20261010/inmask_evidence.py probe --cohort a/coco_role_competition200_20261010
```

再整队运行：

```bash
PYTHON=python3 bash evidence/local/false_alarm_floor_20261010/run_source.sh 6 --cohort a/coco_role_competition200_20261010 --name coco
```

```bash
PYTHON=python3 bash evidence/local/false_alarm_floor_20261010/run_source.sh 6 --cohort a/lvis_mean200_20261008 --foris a/lvis_foris1400_score_reuse_20261009 --name lvis
```

`run_source.sh` 先单独跑第一例（路径或键名不对在这里就停），再开 N 个进程分片计算，最后封存并评分；中断后重跑会跳过已完成的例。输出在 `evidence/local/false_alarm_floor_20261010/inmask/<name>/`（`report.json`、`episodes.jsonl`），日志在 `inmask/logs/`。仓库里出现过的队列名：PACO `a/paco_role_competition600_20261010`、`a/paco_fast9_600_20261009`；COCO `a/coco_role_competition200_20261010`；LVIS 如上；DeepGlobe `a/deepglobe_role_competition100_20261010`；试点 `a/joint_role_pilot200_20261010`；Fundus 200 例与 Chest 600 例用 `scripts/run_extended_foris.py` 的输出目录。更大的已缓存队列同样直接传目录。

联合编码探针（新前向）。执行端已确认 2048×1024 输入可行，CPU 上一次并排前向约 15.2 秒，MPS 在 11.23 GiB 进程额度内放不下 8192 个 token。因此默认改为每张图边长 768：并排画布 1536×768 共 4608 个 token，与一张普通 1024 输入相当；对照臂（两图分开编码）用同一边长、同一设备，比较里不混入分辨率变化。

```bash
python3 evidence/local/false_alarm_floor_20261010/joint_encoding.py fields --cohort a/coco_role_competition200_20261010 --name joint_coco_try --limit 3 --side 768 --device mps
```

```bash
python3 evidence/local/false_alarm_floor_20261010/inmask_evidence.py evaluate --cohort a/coco_role_competition200_20261010 --name joint_coco_try
```

三例跑通并读出耗时（`records/*.json` 的 `joint_seconds`）后，换一个 `--name` 跑 150 例，可加 `--shard k/n`；`--masked` 增加"参考背景置均值色"一臂。有余量时在 CPU 上用 `--side 1024 --device cpu` 抽 30–50 例，核对结论不依赖 768 这个边长。评分复用量具，字段带 `separate.`、`joint.`、`masked.`、`shift.` 前缀。

### 7.4 时间

本机实测量具每例约 6 秒（单进程 2 线程），`--cohort` 读法另加两张图的解码、变换与缓存校验；联合编码探针在边长 768 时每例的证据计算约为量具的一半乘以臂数，另加三到四次前向。

|步骤|内容|设备|估时|
|---|---|---|---:|
|0|自测与每个源的首例|CPU|1 分钟|
|1|四个主流数据集各 600 例过量具|CPU，6 进程|每个约 10–15 分钟，合计约 1 小时|
|2|其余数据集各 300 例：带特征的完整 FoRIS|GPU|每个数据集约 25 分钟，六个约 2.5 小时|
|3|这些数据集过量具|CPU，6 进程|每个约 5–8 分钟|
|4|`summary`|—|秒级|
|5|联合编码探针（边长 768），四个主流数据集各 150 例|MPS + CPU|约 1–1.5 小时|
|5b|同上，边长 1024，每个数据集 30–50 例|CPU|每例约 1 分钟，合计 2–3 小时，可与其他步骤并行|
|6|余量：把步骤 1 扩到全部已缓存的例|CPU，6 进程|每 1000 例约 17 分钟|

步骤 1 完成后一小时内就有第一批结论；全部做完约 5–6 小时，其余时间用于步骤 6 收窄区间。

仍不确定：

1. `--cohort` 读法已在本机对三种真实布局的伪造队列端到端跑通，其中缓存和输入读取用的是仓库自己的 `RawFeatureCache` 与 `load_inputs`，但还没有碰过真实缓存。每个队列先跑 `probe`；若有第五种布局，把 `probe` 的输出或报错发回即可定位。

3. 联合编码在 768 边长下的耗时，以及 768 与 1024 两个边长的结论是否一致（步骤 5b）。
4. 第 6 节方向相对已发表工作的新颖性需要专门查新，本文只列了我所知的近邻。
5. 所用队列都是开发集；误报底噪律和今晚选出的规则在未暴露的确认集上是否保持，需在冻结后复核。
