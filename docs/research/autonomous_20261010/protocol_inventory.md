**Current conclusion:** there is no complete method with a verified advantage on all ten datasets. The strongest audited gains are real paired development results, but the same candidate fails on COCO and falls below the stronger local-view baseline on DeepGlobe.

## Frame and sampling rules that affect the comparison

The released [model builder](/Users/misaya.yanghejazfs.com.au/paper_project/cv_data/third_party/foris_official/models/__init__.py:109) sets `resize_to_orig_size=False`; [inference.py](/Users/misaya.yanghejazfs.com.au/paper_project/cv_data/third_party/foris_official/inference.py:80) resizes raw GT and ignore maps directly to the model output. At default settings this is **1024² CLI scoring**. The paper's original-resolution description and the released CLI differ. Retain both frames, label them explicitly, and use CLI1024 when claiming released-code replication. Existing candidate tables often emphasize original loader-query size and cannot be subtracted from the paper's published number.

Pool I/U within `(fold, class)`, then average classes within each fold, then folds. PASCAL's unequal fold class counts make an all-class average a different statistic. Preserve official class slots, including absent zero slots in limited PACO/COCO subsets. iSAID's `tgt_ignore_idx` must be frozen and passed to [counts/gross_edits](/Users/misaya.yanghejazfs.com.au/paper_project/cv_reasearch/src/ics/metrics.py:10). The existing five-dataset scorer does not load an ignore map. Do not map original ISIC/SUIM GT through an intermediate JPEG-size frame before the final evaluation frame.

The existing [official runner](/Users/misaya.yanghejazfs.com.au/paper_project/cv_reasearch/scripts/frozen_dino_plan.py:69) and [data adapter](/Users/misaya.yanghejazfs.com.au/paper_project/cv_reasearch/src/ics/official_data.py:18) cover five datasets. Official seed0, development seed1, and validation seed2 are separate immutable manifests; serial `num_workers=0` sampling and legal repeated draws are preserved. Existing seed2 manifests for all five are ready. A new seed alone is not proof of unseen photographs or unexposed validation: perform the existing photo/RGB overlap audit when claiming confirmation. The current `confirm` runner explicitly remains disabled pending that audit.

The benchmark-extension agent owns separate extended adapters/preparation. This audit did not alter that implementation or the established runner. Its receipt-backed adapters now cover exact iSAID, ISIC, Chest and Fundus input preparation. DeepGlobe remains explicitly blocked for exact published-protocol reproduction.

## What can actually be reused

The primary shared pool is [raw_cache](/Users/misaya.yanghejazfs.com.au/paper_project/cv_data/a/paco_mean200_20261008/raw_cache/0a555915a7972480b74fcce11c876a79c4e776c93db8573d31f8b0e01c1c6158/profile.json). At this audit it has **16,710 input entries**, all with metadata for `O/24`, normally 4096×1024 FP32, before projection and L2 normalization. Payload paths all exist. Provenance tags account for LVIS 8,774; PACO 6,163; DeepGlobe 1,100; COCO 464; PASCAL 82; SUIM 83; unclassified 44. These are input/crop entries, not unique photos, full episode coverage, or a guarantee that any new manifest is cache-complete.

Use [RawFeatureCache](/Users/misaya.yanghejazfs.com.au/paper_project/cv_reasearch/scripts/raw_feature_cache.py:38), [CachedDINO/cache_host](/Users/misaya.yanghejazfs.com.au/paper_project/cv_reasearch/scripts/cached_dino.py:38), and `--raw-cache-profile ... --encoder-device cpu` for encoder-free replay. Actual replay validates profile, transformed-input identity, payload SHA and array SHA; absent branches fail without encoder fallback. Weight SHA is `45172f209c9583c40538afc26b60a07033e6fcc2e8c30228338e6b2e932e7941`; the frozen profile records MPS FP32, timm1.0.30/torch2.10.0, 1024² ImageNet normalization. Changed crops, image resolution, branch/layer or producer configuration require genuine matching features. The two small secondary caches preserve selected Q/K16/24 branches on 12 inputs, plus O24 on 32; their exact live branch counts are in the inventory. The large main pool is not a multilayer archive.

Existing complete masks, source scores and original I/U should be reused when candidate inputs/parameters match. LVIS1400 score reuse already demonstrated zero DINO/front-end calls for completing the FoRIS baseline; COCO200 source-score and full FoRIS endpoint identities were independently checked in its `matched_raw` run. Cached replay wall time is incremental cost after saved encoding/baseline, not cold-input end-to-end efficiency. GPU/MPS-versus-released-CUDA parity remains a separate validation question.
