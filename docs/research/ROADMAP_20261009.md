## 0. 一页总览

### 核心判断

1. **分数随目标变大而单调上升，五个数据集都是。** LVIS 从 17 升到 77，PACO-Part 从 17 到 56，PASCAL-Part 从 29 到 67。这是全部数据里最大、最一致的规律。
2. **现有流水线只在一个"工作窗口"里好用**：目标占画面 5–20%，物体级的粒度。窗口内 FoRIS 是 59–73；窗口外的误差方向是确定的：小了圈多，大了圈少，部件会外溢到父物体。
3. **各数据集差在有多少例子落在窗口外。** LVIS 有 75% 的目标偏小；PACO-Part 的粒度比窗口细；SUIM 有 43% 的目标偏大；COCO 两头都有。
4. **过去两周试的几乎都是同一张 64×64 分数场上的读法**（切点规则、图平滑、重排），不带新信息，而且结论几乎都在 COCO 上得出。图平滑这一族读标签的上限也只有 +2 到 +3。
5. **方向：把例子搬进窗口，而不是让流水线去适应窗口外。** 尺度靠重新取景，粒度靠按参考定分组，大目标靠补全。三件事是否成立都还没测，但每一件都能在 M4 上一两天内判定。
6. **决定"五个数据集全部超过"的是 SUIM 和 PACO-Part，不是 LVIS。** 现有底座在这两个上只有 +0.2 到 +0.3，区间跨零。LVIS 可能给出最大的涨幅，但主张能否成立取决于最弱的两个。

### 推进方式

- **一个固定的开发集、三张固定的表**（第 4 节）。以后每个问题都用它回答，不再临时去看一个点。
- **三条主线，各对应一种窗口外的情形**（第 5 节）：A 尺度、B 粒度、C 大目标补全。
- **每条主线先量"读标签最多值多少"，够大才做方法**；不够就关，不做变体。
- **所有机制都带触发条件**，不触发时输出与底座逐例相同。这样加机制不会让别的数据集变差。

### 1.1 相对 FoRIS 我们有多少

"底座"指我们现有的流水线：FoRIS 的证据，换成图求解，再加细读出，切 0.5。

官方全长下区间半宽的外推是 COCO ±0.26、LVIS ±0.13、PACO-Part ±0.12、PASCAL-Part ±0.21、SUIM ±0.40。所以每个数据集至少要有 +0.3 到 +0.5 的真实优势，主张才站得住。现在只有 COCO 和 PASCAL-Part 够。

### 1.2 为什么像在原地打转

1. **结论都来自 COCO。** 已关闭的几十条路线几乎都只在 COCO 上测过。COCO 的主要错误是"相近类别的更大物体连着圈进来"，这恰好是最难的一种。LVIS、SUIM、PACO-Part 的主要错误不同，没有系统量过。
2. **试的是读法，不是信息。** 切点规则、平滑、重排都在同一张分数场上操作。这类操作能拿到的上限本来就低。
3. **先做方法，后量池子。** MEAN 跑了 1400 例才知道打平。应该先量"这一类最多值多少、钱在哪一档"。
4. **没有共同的尺子。** 批次不配对、口径不一、每个代理用自己的样本，结果累积不到一张表上。

### 1.3 从现在起的规则

1. **先量上限，再做方法。** 一个方向读标签的上限不到 +3，就不做。
2. **每个候选对应分数账上的一格**，说清它瞄准哪个数据集的哪一档。
3. **五个数据集都看，按目标大小分档看。** 不再只报一个总分。
4. **只做配对比较。** 同一批例子、同一口径、和 FoRIS 及底座逐例配对。
5. **结果进同一张板。** 每次运行只交一张结果卡（第 4.5 节），不另写报告。

## 2. 理论：工作窗口

### 2.1 流水线里有三个固定量

现有方法（INSID3、FoRIS、我们的底座）是同一个骨架：逐 token 算与参考的相似度，在查询图内部做分组或平滑，归一化后切一刀。其中三个量对所有例子都一样：

| 固定量 | 现在的取值 | 它隐含的假设 |
|---|---|---|
| 画面尺度 | 整图缩到 1024，64×64 个 token | 目标占的 token 足够多 |
| 分组粒度 | FoRIS 用固定阈值 0.6 做硬聚类并选一个种子簇；我们用固定强度的图平滑 | 要分的东西是"一个簇"那么大的单位 |
| 切点 | min-max 之后 0.5 | 目标和背景各占分数范围的一半 |

参考掩码其实规定了三件事：是什么、多细（整个物体还是一个部件）、以及在参考图里多大。现有方法只用它做第一件，后两件交给了这三个固定量。

### 2.2 证据：窗口存在，而且五个数据集一致

**FoRIS 的逐例平均 IoU，按目标占画面的比例分档 [本地]。** 括号里是该档例数占比。

| | <0.2% | 0.2–1% | 1–5% | 5–20% | >20% |
|---|---:|---:|---:|---:|---:|
| LVIS | 16.6（16%） | 37.3（30%） | 46.7（29%） | 71.0（19%） | 77.2（7%） |
| COCO | | 43.5（6%） | 55.7（38%） | 72.5（35%） | 70.7（21%） |
| PASCAL-Part | 6.9（1%） | 29.4（4%） | 40.1（19%） | 57.2（36%） | 67.0（41%） |
| PACO-Part | | 17.2（3%） | 31.8（24%） | 43.4（47%） | 56.1（26%） |
| SUIM | | 38.5（5%） | 60.8（22%） | 59.2（30%） | 65.8（43%） |

M4 上 LVIS 1400 例的同一张表是 13.7 / 35.9 / 56.2 / 68.0 / 70.2，结构相同 [M4]。

**尺度。**

- 把 LVIS 各档按 COCO 的大小构成重新加权，逐例平均 IoU 从 45.6 变成 60.8，COCO 自己是 63.9 [本地]。LVIS 与 COCO 的差距大部分是构成。
- LVIS 在 64×64 网格上的上限只有 74.5；最小两档是 32.8 和 68.3 [M4]。COCO 的同一上限是 95.5 [旧账]。
- 目标小于约 1%（20–40 个 token）时，分数场的峰不在目标上：把切点从 0.5 提到 0.7，圈内是目标的比例不升反降（LVIS 0.2–1% 档从 43% 掉到 16%）。目标 ≥1% 时是从 55% 升到 90% [本地]。

**切点。**

- 整档的最佳切点：小目标 0.54–0.70，占 5–20% 的目标 0.47–0.61，占 20% 以上的目标 0.34–0.39。五个数据集同一方向 [本地]。
- 也就是 0.5 只对 5–20% 的目标是准的。逐例换成最佳切点值 +7.1 到 +12.3 [本地]。

**粒度。**

- 把"圈多的部分"折成一圈的厚度（单位 token，只看圈到目标的例子）：COCO 0.0–0.9，SUIM 约 0，LVIS 0.1–2.0，PASCAL-Part 0.5–2.7，PACO-Part 3.2–5.5 [本地]。
- PACO-Part 在所有大小上都外溢 3–5 个 token，PASCAL-Part 是 1–3 个；物体数据集不到 1 个（LVIS 的小目标除外）。这不是模糊，是分到了父物体那一级。
- PACO-Part 切到面积与真值相当时，圈内仍只有 50–76% 是目标；COCO 同档是 95–97% [本地]。

### 2.3 两种信息缺口

窗口外的失败背后是两种不同的缺口，对策不同：

| 缺口 | 表现 | 哪些数据 | 约束内能加的信息 |
|---|---|---|---|
| **像素不够** | 目标只有几个到几十个 token；网格放不下；峰不在目标上 | LVIS 的大部分；各数据集的小目标档 | 对目标重新取景、重新编码 |
| **语义分不开** | 错圈的区域和目标在特征上一样像参考，或目标的一部分不像参考 | COCO 的相近类别物体；PACO-Part 的父物体；SUIM 只圈到一部分的大目标 | 未知。已试的 token 级、区域级、裁剪级相似度都不够 [旧账] |

这两种缺口在小目标上会混在一起。LVIS 的小目标到底是哪一种，现在不知道，这是第一个要判定的问题（预测 P1）。

### 2.4 用这个框架解释已有的负结果

- **所有无标签的切点和面积规则都失败**：它们想从同一张分数场里读出该圈多大，而目标小于 1% 时掩码大小与真实大小几乎无关（LVIS 上对数斜率 0.28，应为 1）[本地]。这张场里没有这个信息。
- **图平滑不涨分**：它不改变三个固定量里的任何一个，只是在同一粒度上再抹一次。最小的目标还会被抹掉（MEAN 在 <0.2% 档圈到目标的比例从 74.7% 掉到 56.7%）[M4]。
- **FoRIS 相对单原型的全部改进主要也是切点**：固定切点下从 45.6 提到 58.5，逐例最佳切点下只从 63.9 到 68.6 [旧账]。FoRIS 的各个部件对排序本身的改善不到 5 点。
- **COCO 上放大重跑为负**（−0.05 [−1.40, +0.98]）[旧账]：COCO 的圈多是相近类别的物体，属于语义缺口，放大不改变它。这个结果不能外推到像素缺口为主的数据。

### 2.5 五条可检验的预测

判定线是事先定的。Astra 可以在看到数据之前调整，看到之后不调。

| 预测 | 判定实验 | 成立的表现 | 判否 |
|---|---|---|---|
| P1 LVIS 小目标的失败是像素不够 | 放大实验里用真值定框的两个臂 | <1% 两档的平均 IoU 各升 10 点以上 | 两个臂相对 FoRIS 都不到 +2 |
| P2 搬进窗口后切点自动变准 | 同上，看裁剪内掩码与真值的面积比 | 中位数回到 1.0–1.3 | 仍在 2 倍以上 |
| P3 部件在查询图自己的分组里存在 | 分数阶梯的第 4 级，PACO-Part 和 PASCAL-Part | 比逐例最佳切点高 8 点以上 | 高不到 3 点 |
| P4 粒度可以由参考决定 | 粒度旋钮的上限，加参考统计量的预测力 | 上限 ≥ +3，且与逐例最优粒度的秩相关 ≥ 0.4 | 上限 < +3，或相关 < 0.2 |
| P5 大目标的漏圈能由查询图自己补全 | 分数阶梯的第 3 级，SUIM 的 >20% 档 | 比逐例最佳切点高 5 点以上 | 高不到 2 点 |

### 4.2 表一：分数阶梯

回答"从现在的分数到满分，每一级丢多少"。每个数据集一张，按目标大小五档分列，原图口径，所有级别用同一种放大方式。

| 级别 | 定义 | 它和上一级的差说明什么 |
|---|---|---|
| L0 | 完整 FoRIS（含 CRF） | |
| L1 | FoRIS 的连续场切 0.5，不做 CRF；底座的场同样报一行 | |
| L2 | 同一张场，逐例取最佳切点（0.05 到 0.95，步长 0.025） | 切点错了多少 |
| L3 | 用查询图自己的真值算原型（去位置、归一化后的 token 按真值覆盖率加权平均），余弦当分数；报切 0.5 和逐例最佳切点 | 参考原型搬到查询图丢了多少 |
| L4 | 查询 token 做球面 k-means（K=64，种子 0），真值覆盖率均值 ≥0.5 的段记为前景 | 单个原型表达不了的部分 |
| L5 | 真值在 token 级二值化（覆盖率 ≥0.5） | 分组也分不出的部分；100 − L5 是网格放不下的 |

COCO 上已有一组可对照的旧数 [旧账]：L1 58.5，L2 68.6，L3 最佳切点 78.7，L4 80.6，L5 95.5。新实现先在 COCO 上对上这组数的量级，再跑别的数据集。

### 4.3 表二：三个旋钮各值多少

回答"如果这个固定量能逐例取对，最多涨多少"。

| 旋钮 | 做法 | 输出 |
|---|---|---|
| 切点 | 就是 L2 − L1 | 已有 [本地]，在 D1 上重做 |
| 粒度 | 从缓存重放 FoRIS（不做 CRF），聚类阈值取 0.4、0.5、0.6、0.7、0.8；执行端先读 FoRIS 源码确认这个参数的作用 | 每个固定取值的分数；逐例取最优的上限；按五档分列 |
| 尺度 | 放大实验里用真值定框的两个臂 | 同上 |

同时记下每例几个不读查询标签的参考统计量，看它们能否预测逐例最优的粒度和切点（秩相关，D1 对半分）：

- 参考前景的内聚度（前景 token 到前景均值的平均余弦）。
- 参考的边界对比（前景均值与掩码外 2 个 token 以内的背景均值的余弦）。
- 参考的"部件指数"：在参考图自己的分数场上，分数过半的背景面积与前景面积之比。部件的参考会很高，整个物体的参考接近零。

提醒：[旧账] 里参考内聚度只能预测查询内聚度到 0.44，用参考校准面积是 −21.18。这里测的是粒度而不是面积，先看相关再说。

### 4.4 表三：圈多的部分在哪

回答"圈多是贴着目标的一圈，还是外溢到别的东西"。不需要编码。

对每例，算误圈像素到真值的距离（1024 口径下做距离变换，除以 16 换成 token）。按五档报告误圈面积落在 ≤1、1–2、2–4、>4 个 token 的比例。

- 集中在 2 个 token 以内：贴边的一圈，属于像素不够，放大应当有效。
- 集中在 4 个 token 以外：外溢，属于语义缺口，放大大概率重现同一团。

这张表在放大实验出结果之前就能预告它的结论。

## 5. 三条主线

### 5.1 主线 A：尺度，重新取景

**想法。** 第一遍在整图上跑，得到一个大致位置。按这个掩码把查询图裁出来、放大到标准尺度、再跑一遍。参考图按它自己的掩码同样裁一次。目标于是进入窗口，切点也随之变准。它不需要估计目标多大，只需要第一遍的位置对。

**为什么有可能成立。** 小目标多数已经被圈到（LVIS 上圈到一半以上的占 75–89%）[M4]，只是圈大了。LVIS 小目标的外溢厚度中位数是 1.5–2.5 个 token，比 PACO-Part 的薄 [本地]。

**为什么可能不成立。** COCO 上的先例是负的；LVIS 用的照片约 640×480，占图不到 0.2% 的目标只有约 15–25 像素见方，放大只是插值。

**第一版算法。**

```text
M0 = 底座(参考, 参考掩码, 查询)                 # 整图第一遍
参考' = 按参考掩码的框裁剪参考图和掩码           # 只做一次
最多两轮：
    框 = 当前掩码的外接框，边长取 2 倍长边，至少 64 像素
    如果框的边长超过当前画面短边的一半：停
    M = 底座(参考', 参考掩码', 裁剪后的查询)，贴回原位，框外记背景
输出最后一个 M
```

**判定实验**已交给执行端（LVIS 600 例，五个臂），定义见 `evidence/local/transfer_probe_20261009/ASTRA_BRIEF_20261009.md` 第 8 节。之后用同一脚本在 PACO-Part、PASCAL-Part、COCO、SUIM 的 D1 上各跑一遍，每个数据集约 55 分钟。

**按结果分支。**

| 结果 | 下一步 |
|---|---|
| 真值定框的臂和 FoRIS 定框的臂都为正 | 这是方法核心。加第二轮；按连通块分别取框；在 D1 上定下触发条件后进验证 |
| 真值定框为正，FoRIS 定框弱 | 定位是瓶颈。改成整图重叠分块，每块跑一遍后合并 |
| 只有参考裁剪那一臂为正 | 单独保留，它只多一次编码 |
| 都不到 +2 | LVIS 小目标是语义缺口。关闭 A，LVIS 并入主线 B |

### 5.2 主线 B：粒度，按参考定分组

**想法。** 参考掩码说明了要分的是部件还是整个物体。让查询图的分组粒度随参考变，而不是固定的 0.6。

**先测前提，不先做方法。** 两个问题按顺序回答：

1. 部件在查询图自己的分组里存不存在？看表一的 L4。如果用标签挑段也只比最佳切点高不到 3 点，说明末层特征在这个尺度上分不开部件和父物体，粒度这条路关闭，转向其他层的特征（第 5.4 节）或主线 A 在部件数据集上的结果。
2. 粒度旋钮值多少，参考能不能预测它？看表二。

**前提成立后的第一个候选。** 在参考图上对 token 做同样的聚类，找出"能用整簇拼出参考掩码"的最粗粒度（拼出的 IoU 不低于各粒度最高值的 0.9 倍），把这个粒度用到查询图上。它只用参考掩码，不需要编码。

**已知的反面。** Astra 的 C1（3×3 外观加掩码模板）在 PACO-Part 和 COCO 上是 −1.3 到 −4.1；圈内的改动本质上是删，PACO-Part 上删对的比例要超过 70% 才回本。

### 5.3 主线 C：大目标补全

**想法。** 大目标内部不均匀，单个原型只像其中一部分，于是只圈到一部分。第一遍圈到的部分通常很纯，用它在查询图自己的特征空间里再找同一物体的其余部分。

**先测前提。** 看表一的 L3 和 L4 在 SUIM 的 >20% 档。

**前提成立后的第一个候选。** 只在第一遍掩码超过画面 20% 时触发。取掩码里分数较高的一半做种子，聚成 4 个原型；取分数低于 0.25 的 token 聚成 8 个背景原型；每个 token 取"最像的前景原型"减"最像的背景原型"，归一化后切 0.5。

**已知的反面。** COCO 上用查询图自己的原型没有涨分（最好 +0.33），向低分处扩张全为负 [旧账]。但 COCO 的大目标亏损比 SUIM 小（+2.8 对 +4.9），且那些测试没有按目标大小触发。

### 5.4 另一个可能的新信息来源：其他层

M4 上已经实现了 24 层输出和 Q、K、V 的读取，并且在 COCO 952 例上存下了 194 种表示的圈内判别读数，但那次运行被停了，读数还没评分。评分不需要任何新计算（卡 6）。它回答：有没有哪一层或哪种表示，在"已圈区域内部分辨对错"上比末层强。有的话，它是语义缺口的一个候选信息来源，优先给 PACO-Part 用。

[旧账] 里中间层的输出做全图排序远差于末层（18.95–27.70 对 61.83），所以新表示只能用在已圈区域内部。

### 5.5 底座与合并规则

- 底座暂定为现有的图求解加细读出。D1 的配对表出来后，哪个数据集上它低于 FoRIS，就在那个数据集的分档表里找原因。
- 三条主线的机制各带一个不读标签的触发条件：A 在第一遍掩码小的时候触发，C 在掩码大的时候触发，B 逐例给出一个粒度。
- 不触发的例子，输出必须与底座逐像素相同。每个候选先过这条身份检查。

### 5.6 不做的事

MEAN 加批次或精简；按输出面积定切点；参考占比当大小估计；图平滑的各种读出对照；ASTRA_BRIEF 第 6 节列的其余已关闭路线，除非第 4 节的表显示它在某个数据集的某一档有 +3 以上的上限。
