# 单参考、零新增编码实验：已完成，十域通用目标未达到

完成1360例十域开发实验，以及每域50例、共500个未用有向配对的一次冻结验证。最终候选相对完整FoRIS六域正、四域负；PASCAL-Part、Lung、Fundus的逐域照片配对95%区间完全高于零，LVIS的区间完全低于零。单参考、0新DINO编码、推理不读查询GT均保持；验证评分后未改参数。

本轮确实改善了部分缺口，但开发集的改进未稳定迁移到新参考配对，不能宣布跨数据集通用方法成功。R5相对MEAN也在相同四域为负。

## 2 哪个假设被支持，哪个被否定

|实验|完整执行|主要结果|决定|

R1的区别在于：低解释度降低对原始分数的锚定，让查询邻居参与修正；它不直接把该位置改成背景。该机制比全局新颖度惩罚更能保留部件，但高解释度也可能来自相似背景，低解释度也可能是真目标。因此，E仍只是可靠度代理。

## 3 剩余矛盾的实测定位

- 校准方向不一致：开发网格内COCO只有.55/.575高于FoRIS，ISIC只有.40/.425/.45高于FoRIS，没有共同正阈值。降低到.475在开发ISIC+0.643，却使LVIS−.816pp。到新配对后，.475相对.5在ISIC反而−.339、LVIS−.554pp；这一收益不稳定，验证后没有切回.5冒称成功。
- 新配对COCO的漏检率接近FoRIS（.208对.211），FP/GT却为.358对.250，主要仍是额外覆盖。LVIS则漏检率升至.375对.318，三档目标的逐例均值均下降；不能用一个“统一收缩”同时修复这两种错误。
- SUIM的FP/GT略低于FoRIS（.476对.495），但漏检升高（.235对.203），中小目标明显下降。它在新参考配对上暴露了任务覆盖问题，开发小面板的+0.309pp不能外推为稳定收益。
- ISIC的固定块内位置余量极小，而UN场的开发GT最优阈值高达84.991；当前合法范围规则仍不能实现这个诊断潜力。该最优阈值用了GT，绝不是可部署方法。
- R2的参考内边界规律可以迁移到部分Fundus任务，却在部件和自然图像上几乎没有稳定增量。原来的硬区域上界与本轮面积保持实验都不构成DINO特征信息不足的证明。

这些结果支持保留“未知降低置信”这一机制，但否定了它配合本轮图、J、共同阈值、块内像素重排就能获得通用方法的判断。它们没有证明单参考或现有缓存理论上无解。

## 5 协议与计算

R5固定seed2026101203，同fold/class、不同R/Q照片，按class轮转每域50，排除32,825个既有有向配对。R5仍使用旧照片、已有输入裁剪与缓存协议；它只检验这些照片内的新参考配对泛化，不是全新照片，也不代表论文完整基准。iSAID仅在协议准备中生成ignore文件，方法推理不读取查询前景GT或ignore标签；忽略区只用于评分。

所有主指标为CLI1024，按(fold,global_class)池化I/U后对观察槽等权。报告同时保存逐例均值、目标三档、FN/GT、FP/GT、面积对数误差和照片配对1000次bootstrap；相同照片的任务成组重采样。

本轮使用CPU并行，无新增DINO前向。以下是缓存特征上的实验计算，不是从RGB开始的端到端延迟：

|阶段|实测|口径|
|---|---:|---|
|R1成功逐例生产合计|178.805秒|8新臂共同计算，3 worker；合计wall不是CPU时间|
|R2成功逐例生产合计|789.446秒|参考拟合及全部对照，3 worker|
