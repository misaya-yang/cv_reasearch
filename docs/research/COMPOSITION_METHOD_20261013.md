# 组合对照的历史数值定义与关闭结论

**研究定位更正：本线已关闭，以下保留数值定义与历史开发选择。组合−U和CRF新增贡献的确认区间均跨零，本组合不作为主方法；现行T0–T9计划照常执行。**

本轮只约束 DINO 特征、零训练和完整推理延迟。方法选择依据是最终掩码的十域等权 class mIoU；操作数量、单步是否涨分、某个域是否回退都不是额外限制。两批开发完整比较后冻结的评测公式为 **`rho>0.9 ? T : officialCRF([0.5M+0.5U>0.5])`**：先融合两种连续读出，参考中缺少纯前景 patch 时走独立软覆盖，其余任务执行一次原参数的官方 CRF。

## 输入和三条证据

输入是参考 RGB、参考前景 mask、查询 RGB，以及同一 DINOv3-L/16 编码器的 64×64 token 特征。推理不读取查询标注，不拟合分类头或新增模型参数。固定位置子空间、官方 FoRIS 组件和历史 MEAN/UN 数值实现均复用原参数。选择预先列出的组合属于开发集算法选择；开发分数不能作为未见数据的性能声明。

- **M：FoRIS 语义分数经 MEAN 修正。** 先保留完整 FoRIS 的前景/背景、投票和查询先验处理所得分数，再用参考纯前景均值的相似度秩作 0.25 强度修正，并在查询互近邻图上做 λ=16 的正则化求解。它提供另一种目标范围与查询内部一致性判断。M 使用原实现的半精度特征交接、64→1024 双线性读出，不额外归一化或截断。
- **T：参考软覆盖匹配。** 每个参考 token 的标签是其 16×16 patch 中前景像素比例，而不是单点或硬标签。在原位置去偏特征上，经双向共同均值中心化，以温度 0.05 的指数相似度加权这些比例。T 保留细结构在混合 patch 中的贡献；读出保持原双线性插值、min-max 和严格 `>0.5`。
- **U：T 加区域调制、候选投票/先验与可靠性图。** 原 R1 实现从固定九个强度中按无 GT 的参考回收代理量选择调制，再加入独立计算的 V/P 信号，在查询互近邻图上求解。可靠性来自参考匹配解释量。U 与 M 共享原始 DINO 输入，保留各自的特征精度、条件去偏及图定义；相似的中间名称不代表可以直接复用数值。

M/U 都是数值读出场，不声称是校准概率。组合的作用来自它们错误的互补性，不能从“使用不同名称”推断独立证据，也不能声称其中一条能正确识别每个高分假目标或低分真目标。

## 连续组合如何做一增一减

当前两批开发共同首位父公式是 `P = [0.5 M + 0.5 U > 0.5]`，以 FP64 做加权与严格比较。没有在混合后做额外 min-max、阈值拟合或 CRF。

相对 M 的二值掩码，组合在 `M≤0.5` 且 `U>1−M` 的位置补入，在 `M>0.5` 且 `U≤1−M` 的位置删除。它允许原分数较低的像素因另一条读出有充分支持而入选，也允许原分数较高的像素因另一条读出缺乏支持而被移除。这个条件只是明确的决策规则，正确性仍须由完整配对结果验证。

对任一 class/fold 池，令原交并为 I、V，补回 TP、新增 FP、删除 TP、移除 FP 分别为 a、b、c、d，则新 IoU 为 `(I+a−c)/(V+b−d)`。在并集非零时，提升条件为 `a−c > (I/V)(b−d)`。因此不能只看补回量、只看删除量，或将重叠步骤的四项计数直接相加。实验记录最终掩码相对同一基线的净编辑。

## 参考形态分支

设参考 patch 覆盖率为 f，定义 `rho = 1 − sum(f·[f≥0.9])/sum(f)`：参考前景质量中未落在近纯前景 patch 的比例。当前候选增加固定的 `rho>0.9 ? T : P`，沿用原 U 的阈值，不按域切换，也没有搜索 rho。

该分支针对一个可在推理前观察的问题：纯前景 patch 几乎不能代表参考目标时，M 的纯前景均值和后续平滑可能改变细结构范围。这是选择 T 的设计依据，不是对所有细目标的正确性保证。两批开发的平均增益只有 +0.0641/+0.0130 pp，区间均跨零；第二批同时出现 Fundus +1.1380、LVIS −0.9515 pp。成本上的作用更明确：249/1360、94/500 例可在算出 rho 后只执行 T，跳过 FoRIS 语义核、M、V/P 和 UN 图。

## 为什么继续组合 CRF

在此前父式 `.25M+.5U+.25T` 上，完整 CRF 的十域均值从 55.1886 降到 54.5733；只保留 CRF 新增区域的 `P OR CRF(P)` 却得到 55.3429。CRF 增加约 210 万 TP 和 248 万 FP，同时其删除动作损失约 502 万 TP。保留增加、舍去删除是由这组已知编辑结果推动的下一步，不是假设“CRF 总会改好边界”。

在 `.5M+.5U` 的两个完整开发队列上，原 P、完整 CRF、OR、AND、固定块内面积保持及其参考门控副本共十臂已完成。18,600 张自然输出全部产生并封存后再读取 GT。改变父式后重新评估了整个组合，没有把先前 +0.1543 pp 直接加到新父式。

CRF 单独接到 P 后平均下降 0.2641 pp；参考门控单独增加 0.0385 pp；二者组合却比 P 增加 0.2894 pp。交互效应为 +0.5150 pp，不能把各步独立增益相加预测最终成绩。G(CRF(P)) 比 G(P) 增加 0.25085 pp，两批分别 +0.19422/+0.30748 pp；共享照片簇配对区间分别为 [0.11074,0.28619]/[0.14580,0.50151]，联合区间 [0.15672,0.36152]。这些仍是用于选择方法的开发证据。

新一轮 CRF 平均耗时 1.0611 秒/例。实际方法的门控真分支不会执行 CRF。完整共享实现及 RGB 到掩码已另行实测；非门控 COCO/PACO 实例相对 FoRIS 增加约 0.6 秒，Fundus 门控实例节省约 1.3 秒。该成本来自实际编码和后处理，未用自然产物重放耗时替代。
