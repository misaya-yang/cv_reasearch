## 1 问题与目标

**设定：** 冻结 DINOv3-L/16（不训练、不微调），输入一张参考图、它的完整前景 mask 和一张查询图，输出查询图的完整 mask。查询 GT 只用于评分和标明的诊断。

**研究问题：** 只有一张参考图和它的 mask，用冻结特征，查询里的目标什么时候能被识别、靠什么机制识别，又在什么情况下确实识别不了。具体分三层（[W45](x1012_tasks/W45_solvability_PLAN.md)）：
1. **表示：** 冻结特征本身能否把目标和其余部分分开。分不开的例子，才是这层表示下的难例。
2. **迁移：** 参考图定义的“目标是什么”，怎样在另一张图里重新找到。
3. **读出：** 找到之后，怎样决定范围（取多少、到哪里为止）。

**研究的做法：**
- 先弄清每一层在哪些例子上失败、为什么失败，再针对失败机制设计方法。
- 判断一个例子“做不出来”，必须给出证据（信息不在给定输入或特征里），不能以别的方法也失败为据。
- 方法的取舍看它解决了哪一层的问题、解决了多少，而不是看在哪个基准上领先谁。

**外部检验：** 在十个公开基准上与已发表方法同协议比较，以此检验方法是否真的解决了问题。比较结果是检验，不是研究对象，也不决定先研究哪个问题。

- **FoRIS 是外部检验中的主要同协议强基线。** [原始论文](https://arxiv.org/abs/2609.03384) v1 提交于2026-09-03，项目原记录的官方代码为 commit 1aa02a1。投稿还需正面比较 INSID3、RSRM、FROST、FSSDINO，不能把单一基线当作穷尽性 SOTA 证明，见 [W35 文献与贡献审计](x1012_tasks/W35_cvpr2027_readiness_REPORT.md)。

## 2 当前方法：SH（不依赖 FoRIS 的头）

定义和代码见 [W23_simple_pipeline.md](x1012_tasks/W23_simple_pipeline.md)，实现为 `scripts/x1012/w23_simple_pipeline.py::simple_head`。全部常数见 [server/EXPERIMENT_PLAN.md](../../server/EXPERIMENT_PLAN.md) 第 2 节。

1. 位置去偏后的参考和查询 token；参考覆盖率 y；rho = 参考前景中不落在纯前景 token 上的比例。
2. **点证据 U0。** 先做核迁移 c，即温度 .05 的软前景份额。若 rho > .9，直接输出 c > .5（细结构回退，如 Fundus）。否则：
   - 用新奇度调制 c，调制强度按无标签的 max-J 逐例选择；
   - 在查询 kNN 图 L 上做 λ=16 的求解。
3. **原型证据 M′。** p = q·μ_fg − .55·q·μ_bg⊥，即一个前景原型对一个难负背景原型。在**同一张图 L** 上做排序引导的 λ=16 求解。
4. **SH+** = 官方 CRF([.5·M′ + .5·U0 > .5])。

**一句话叙事：** 点证据（逐 token 迁移）与原型证据（类级对比）的错误互补；共用一张查询图融合，不需要 FoRIS 的聚类先验、投票和语义修正，就能更准、更快。

## 7 下一阶段：方法本身（W30 之后）

- 已经试过的，是一个个**具体构造**，不是方向。不能据此说方法到了上限，也不按“失败了多少次”下结论。
- 我们还没有真正的 0→1。SH 是对已有部件（核迁移、原型对比、图求解、CRF）的组合与简化。
- W30 跑完后，从问题本身重新想方法，而不是继续修补 SH。下面这些现象，是新方法要解释并超越的，不是边界：
  - 排序基本正确，错在范围：切点余量约 10 个点，两条线共享（W14）；
  - 点证据与原型证据的错误互补（W27、W28）；
  - 大目标与部件、小目标之间的粒度交换（W20、W24、W26）。
  - **可判定性分解（[W45](x1012_tasks/W45_solvability_PLAN.md)）：** SH+ IoU < .3 的灾难例（20%）中，只有 37.5% 在这层 token 特征下确实分不开（Fundus、Road、LVIS 的细小结构）；其余在查询自己的特征里可分（交叉拟合探针 ≥ .5）。COCO、PACO、SUIM 的灾难例以“参考到查询的迁移失败”为主，ISIC、PASCAL-Part 以“排序对、面积错”为主。查询特征的线性上限是 71.6 mIoU（SH 53.6），直接用参考拟合的线性分类器只有 38.3。
  - **三层的量化（S 半，CRF 前，十域 mIoU）：**
    - **读出族的硬上限 83.6：** 真实 64 网格覆盖率取 .5 阈值。W45“表示不足”的灾难例中，61% 连这个几何上限都到不了 .5（Fundus、Road、LVIS 的细结构）。这是有证据的难例；8 像素网格能救其中一半，4 像素网格能救八成（[W49](x1012_tasks/W49_token_resolution_PLAN.md)）；
    - **参考换成查询本身时 SH 为 75.7。** 这是泄漏 token 标签的 oracle，它高本身不说明问题。有信息量的是：证据近乎正确时，SH 的读出机制只比几何上限低 8 点，读出不是主要瓶颈；
    - **真参考 53.6。** 与 75.7 的 22 点差距按构造就是“证据不对”的部分，不是独立发现。W45 的“读出失败”一类在自参考下平均 IoU 为 .886，说明证据近乎完美时面积是对的（自参考泄漏答案，不能据此说读出规则没问题）；

## 9 研究规则

工作约定（文件、Git、删除、记录方式）见 [AGENTS.md](../../AGENTS.md)。这里只列研究协议。

- **数据使用：**
  - S 半用于选择；T 半每个方法只读一次；
  - 新照片留出只评分一次（MFU 已用过一次；SH 的那一次在 W30）；
  - 读法必须在运行前写下，只做预定的一轮。
- **研究与贡献分两层：**
  - **研究层：** 任何与问题有关的信息都可以研究，包括 token 以下的像素信息、分辨率、编码器的其他层。W45 中 37.5% 的灾难例就卡在 token 装不下的细小结构上，这是问题本身的一部分。
  - **贡献层（写论文、和别的方法比较时）：** 只把方法本身带来的提升算作贡献。翻转、位移、提高分辨率、多视图这类通用推理设置，别的方法用上同样会变好，不算方法的改进；若使用，必须让对比方法使用同样的设置（W29 当时据此取消）。
- **指标：**
  - 开发时：(fold, class) 槽池化后等权，再十域等权；照片成组 bootstrap。
  - 官方：每个 fold 内类 IoU = ΣI/ΣU，对类平均，再对 fold 平均；CLI-1024 画面。
  - 两种口径不能相减。
- **算力：**
  - 本机（M4 Max，14 核，36 GiB）：平时用固定种子的开发子样本，最多 4 个 worker，留出约 30% CPU；同一时间只跑一个 MPS 编码进程。周末经用户批准可全功率（W30）。
  - 服务器（RTX 4080 Super 32GB）：只做 GPU 端到端计时，以及本机没跑完的部分。
  - 不建磁盘特征缓存；全量运行边编码边算。
- **冻结文件：** `r5_candidate.py`、`w23_simple_pipeline.py`、`w27_sh_single_line.py`、`scripts/x1013/*`、`x1013_tasks/REPORT.md`、`scripts/x1012s/photo_holdout.py`、x1012_* 产物。

## 11 术语

| 名字 | 含义 |
|---|---|
| O24 | 冻结 DINOv3-L/16 最后一层 token。1024 输入，64×64 个 token，每个 1024 维 |
| 去位置 | 把特征投影出位置子空间再归一化。位置子空间来自黑图特征（`positional_basis.pt`，500 维通道子空间） |
| y（coverage） | 参考 mask 在每个 16×16 块里的前景比例，保留软值 |
| rho | 参考前景中不落在纯前景 token（y ≥ .9）上的比例。> .9 时走细结构回退：直接输出 c > .5，不做 CRF |
| c / T | 核迁移场：每个查询 token 对参考 token 的软前景份额（温度 .05）。T 是直接对 c 取阈值的读出 |
| max-J | 用无标签的 J = P·C/(P + C − P·C) 选择新奇调制的强度 |
| U0 | 点证据线：调制后的 c 在查询 kNN 图 L 上做 λ=16 求解 |
| M′ | 原型证据线：前景原型对难负背景原型的对比，在同一张图 L 上做排序引导求解 |
| SH / SH+ | .5·M′ + .5·U0 > .5；SH+ 再做一次官方 CRF。现行方法 |
| FoRIS | SOTA 基线，指完整方法：前景/背景处理、投票、聚类先验和后处理 |
| MFU | CRF(.5·FoRIS 线 + .5·U)，依赖 FoRIS 的旧主候选 |
| MEAN / fine | 10-10 前在 FoRIS 上的增强：图求解，以及四个位移编码的细读出。已不作为方法 |
