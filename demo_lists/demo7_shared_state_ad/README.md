# demo7：增强记忆库里“整图共享一个成像状态”的异常检测

状态：2026-10-02 立项，来源是用户的候选简报 `CVPR2027候选方法与优先选择.docx` 的优先方案。
工作方式遵循 `../RESEARCH_PROTOCOL.md`：先量问题有多大，再谈方法。

## 基线和数据

- 基线 SuperADD（CVPR 2026 VAND 4.0 工业赛道，免训练）：DINOv3 ViT-H+/16 的第 7/15/23/31 层特征；
  每张参考图乘一个 [0.8, 1.2] 的随机增益后入库；每层最近邻欧氏距离除以维度，跨层平均。
  代码 https://github.com/LukasRoom/SuperADD （commit 44cf251，CC BY-NC 4.0）。`adx/common.py` 按它逐步重写。
- 数据 MVTec AD 2。训练集和验证集只有常规光照；**公开测试集 `test_public` 含全部光照条件且有像素级真值**，
  同一个场景编号在每种光照下各拍一张，光照条件写在文件名里（regular / overexposed / underexposed / shift_k）。
  所以“已知真实状态”的上限可以在真实光照变化上直接量，不需要提交到评测服务器。
- 实测的真实曝光变化很小：vial 过曝约 ×1.13、欠曝约 ×0.87；fruit_jelly 约 ×1.08 和 ×0.92。
  shift_k 是加了别的光源，亮度比在图内不均匀（10%–90% 分位约 1.00–1.38），不是全局增益。

## 问题 A 和它的可检验假设

问题 A：增强库允许每个 patch、每一层各自选一个成像状态，局部缺陷可以借另一个状态被解释成正常。

| 假设 | 含义 | 用什么量 |
|---|---|---|
| H1 代价存在 | 增强让缺陷处的分数比正常处降得更多 | 常规光照下 B 对 A；P 对 G1 |
| H2 收益存在 | 增强在光照变化下有用 | 过曝 / 欠曝 / shift 下 B 对 A |
| H3 状态可辨识 | 从整图能估出状态 | 估计的增益是否等于该光照条件对应的增益 |
| H4 共享能拿回代价 | 整图共享状态优于逐 patch 自由选 | S-cond、S-hind 对 P |

读出的定义见 `scripts/readout.py` 开头。所有读出来自同一张距离表（层 × patch × 增益），阈值各自在留出的正常图上按 SuperADD 的规则校准。

## 第一个实验（跑之前写下的四行）

1. **实验**：每个类别建三种库（A 无增强、B SuperADD 增强、配对网格 7 个增益 × 10 万个 patch 身份），
   在公开测试集全部光照条件上算 A / B / An / G1 / P / C / S / S-cond / S-hind，按光照条件分开报告像素级 AP、AU-PRO(5%)、校准阈值下的 F1。
2. **预测**（跑之前的判断）：DINOv3 对 ±13% 的增益不敏感。B 与 A 的差在 ±1 点以内；S 与 P 的差在 ±0.5 点以内；
   事后最优的 S-hind 比 P 高不到 1.5 点。
3. **如果 S-hind − P 在各类平均下不到 1 点**：共享状态没有可恢复的空间，问题 A 在这个基准上不存在，停。
   反馈是 H1 不成立（或增益太小），下一步应看 shift_k（非全局增益的光照变化）上的损失来自哪里。
4. **如果 S-cond − P ≥ 1.5 点且估计出来的 S 保住其中三分之二以上**：继续，下一步做强对照
   （简单光度归一化 An、同预算的 B、NFAD 式投影）和状态估计的稳健性。
