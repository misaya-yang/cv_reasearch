# demo4：免训练上下文分割里的“选哪块区域”

状态：2026-10-02 立项。问题已量出，十四类免训练规则都没有明显超过基线，还没有可以称为“方法”的结果。
工作方式遵循 `../../.claude/skills/measure-first-research/SKILL.md`。

## 赛道

上下文分割（in-context segmentation）：给一张参考图和它的掩码，在目标图里分出同一个概念，不训练。
基线是 INSID3（CVPR 2026 Oral，只用冻结的 DINOv3 ViT-L，代码公开：https://github.com/visinf/INSID3）。
它在 9 个数据集上的平均 mIoU 是 55.1，COCO-20i 上是 57.6，离有监督方法（70 以上）很远。

选它的理由：

- 结构上就是“先分组、再认领”：目标图聚类成若干簇，再决定哪些簇属于参考概念。demo2 的诊断工具可以直接用。
- 预测是不确定的（单样本匹配），不像闭集分割那样是高置信的整块错误，决策规则有发挥余地。
- 全部是冻结特征上的推理，1000 个 episode 约 10 分钟；规则可以在 CPU 上离线试。
- 基线很新，后续工作刚开始出现（REBASE，2026-07）。

## 问题 A（已量出）

INSID3 的错误出在哪一段。COCO-20i，单样本，4 折各 1000 个 episode，脚本 `scripts/budget.py`。

| 量 | 4 折平均 mIoU |
|---|---:|
| INSID3（本机复现；论文 57.6） | 56.3 |
| 64×64 网格上限 | 93.2 |
| INSID3 的簇 + 按真值挑簇（分组上限） | 82.1 |
| 只补上漏掉的前景簇 | 71.5 |
| 只去掉错选的背景簇 | 64.3 |
| 把种子换成真值最优簇，聚合规则不变 | 63.2 |

- 分组本身够用（82），**损失在“挑簇”上，约 26 个点**。
- 最大的一类错误是“种子选对了，但漏掉同一物体的其他部分”：占 26% 的 episode，只修这一类能到 65.7（第 0 折）。漏掉的前景里 90% 属于种子所在的同一个连通物体，不是别的实例。
- INSID3 在固定高度切树。目标物体恰好是这一刀上的一个簇的情况只有 32%；40% 被切碎，28% 已经和别的东西并在一起。
- 保留整棵聚类树时，**单独一个树节点**就能达到 79（`scripts/hier.py`，第 0 折前 300 个 episode）。

所以问题 A 是：在目标图的聚类树里，选出对应参考概念的那个节点。上限 79，现状 56。

## 方法 a 的尝试

离线近似评测（特征分辨率、软真值），与官方评测相差约 0.3。除注明外为第 0 折前 300 个 episode；INSID3 在同一评测下 54.9，树节点上限 79.2。

| 规则 | mIoU | 结论 |
|---|---:|---|
| 双向一致性 F1：精确率 = 节点内“最近的参考 patch 是前景”的比例；召回率 = 参考前景 patch 的最近邻落在节点内的比例；选 F1 最大的节点 | 57.1 | 无超参。4 折各 300 个 episode 的平均是 55.4，INSID3 是 56.1，持平 |
| 池化特征与参考前景原型的余弦 | 38.5 | 否定“整体对整体最像” |
| 软匹配、互匹配（dual softmax） | 55–56 | 不优于硬最近邻 |
| 最优传输（均匀边缘） | 29 | 两图前景占比不同，质量守恒反而有害 |
| 树的持久度（合并高度差）作为物体性先验 | ≤ 57 | 真值节点的持久度只排在约 35 / 1900 |
| 从参考树迁移粒度（合并高度） | 40–50 | 两图的高度相关性只有 +0.18 到 +0.36 |
| 分布距离（MMD，线性核 / 随机傅里叶特征） | 12–31 | 偏向过大的节点 |
| 互换角色的循环验证，重排前 5 / 10 / 20 名 | 46–55 | 反向预测同样有噪声 |
| 参考树节点作为带标签区域，最近邻 / 核回归迁移 IoU | 3–27 | 跨图的区域级池化特征匹配不可靠 |
| 最小贝叶斯风险选择、平台规则 | 53–57 | 证据相同，换决策规则没有用 |
| 换层、多层平均 | ≤ 57 | 最后一层去偏后最好；逐 episode 选层的上限是平均 IoU 0.68 对 0.56 |
| 证据变体：去偏分量数、中心化、白化、5 近邻、参考图翻转 / 放大 | 42–57 | 都不改善；真值节点处的精确率 / 召回率始终约 0.78 / 0.75 |
| 第二眼：把前 12 个候选各自裁出来重新编码，与参考物体的裁剪比较池化特征，再乘 F1 | 59.7 | +2.5，候选内上限 71.5 |
| INSID3 输出与 F1 节点的并、交、择优 | 55–56 | 不改善；两者的真值择优是 61.7 |

F1 规则的错误构成：与真值节点相同 36%，选在真值节点内部（偏小）33%，包含真值节点（偏大）20%，选到别的分支 10%。

官方评测（1024 像素）下的核对，第 0 折前 300 个 episode（`scripts/shots.py`）：

| 参考图数 | INSID3 | F1 节点规则 | 树节点上限 |
|---|---:|---:|---:|
| 1 | 55.2 | 57.4 | 79.7 |
| 5 | 64.1 | 66.6 | 80.5 |

参考图从 1 张加到 5 张，两种方法都涨约 9 个点：证据的数量是主要变量。

### 用学习出来的打分器当测量工具

这两项用了基类标注，不是免训练方法，只用来回答“现有证据里到底有没有足够的信息”。3 折训练、第 4 折测试，类别不相交。

| 打分对象 | 特征 | INSID3 | 学习的打分器 | 上限 |
|---|---|---:|---:|---:|
| 树节点（`scripts/ranker.py`，4 折各 300） | 38 个无标签统计量，梯度提升回归 IoU | 56.1 | 59.9 | 79.9 |
| INSID3 的平面簇（`scripts/learn_clusters.py`，4 折各 1000） | 簇级统计量及其在 episode 内的排名，梯度提升分类 | 56.1 | 58.1–58.5 | 81.6 |
| 同上，再加簇的池化特征和参考原型（只跑完第 0 折） | | 55.4 | 54.9–56.8 | 81.7 |

**结论**：把所有证据交给一个有监督的组合器，也只多 2–4 个点。瓶颈是证据本身：单张参考图、跨实例的最近邻匹配，信息量不够定出物体的范围。换决策规则解决不了。

### 覆盖率门控（外部笔记 `INSID3_coverage_gate_result.md` 的检验）

笔记的结构性结论成立：官方聚合分数含覆盖率因子，覆盖率不超过 0.2 的非种子簇永远选不上。实测 4 折各 1000 个 episode（`scripts/gate.py`）：

| 量 | 4 折平均 |
|---|---:|
| 被锁死的真前景占全部真前景 | 13.4% |
| 官方规则 | 56.1 |
| 覆盖率因子换成“覆盖率 > 0”的指示（笔记建议的单因素干预），阈值 0.2 | 46.7 |
| 同上，阈值调到最好（0.3） | 52.2 |
| 完全去掉覆盖率因子，阈值 0.3 | 50.9 |
| 干预新增面积里真前景的比例 | 18.7% |

干预使真阳性面积增加 14.5%，假阳性面积增加 197%。覆盖率因子是这条规则里最主要的精度来源，去掉它得不偿失。被锁死的前景簇在其余证据上和背景簇分不开（前景相似度 0.45 对背景相似度 0.46）。

## 文件

- `icx/common.py`：编码器封装（timm 的 DINOv3 权重，无需申请）、episode 复现、指标。
- `icx/dissect.py`：INSID3 流程的逐步复刻，已与官方实现逐 episode 核对一致。
- `scripts/budget.py`、`failures.py`、`missed.py`、`edges.py`：误差账本。
- `scripts/hier.py`、`leaves*.py`：保存聚类树和证据的 GPU 脚本；`scripts/rules*.py`、`nodes*.py`：离线规则。
- `tools/prep_coco20i_masks.py`：从官方标注重建 COCO-20i 掩码（服务器访问不了 Google Drive）。

COCO-20i 复现 56.3，论文 57.6。可能的原因：掩码是自己重建的、权重来自 timm 的副本、numpy 版本不同导致抽到的 episode 不同。正式实验前需要拿到官方掩码核对。
