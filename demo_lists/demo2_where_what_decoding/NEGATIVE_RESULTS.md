# 已证伪的方向（不要重做）

日期：2026-10-01 / 02。下面每一条都是在服务器上实测后放弃的，脚本和原始数字都保留在 `pilots/`。
写这份文档的目的只有一个：让后续执行者不要再把时间花在这些方向上。

## 0. demo1：SAM 解码器的精确跨提示共享

结论见 demo1 的评审。核心数字（128 提示，FP32，编译后）：

| 方法 | 解码器耗时 |
|---|---:|
| 官方（eager） | 133 ms |
| 最快稠密基线 | 35.9 ms |
| 最快因子方法 | 33.6 ms |

创新点只贡献最后 6.5%，端到端（ViT-B 编码器 87 ms）不到 2%。另外 5e-5 的数值门槛设错了：
官方解码器自己换批大小就有 6.2e-3 的 logit 差。

## 1. SAM 解码器的"输出敏感 / 稀疏"解码

想法：每个掩码只有约 1.5% 的父 token 含边界，远处背景 token 用所有提示共享的参考状态替代。

脚本：`pilots/pilot1_sam_sparse_background.py`（6 张图 × 1024 个网格点提示，SAM ViT-B）。

| 量 | 数值 |
|---|---:|
| 远离物体的 token 相对"空提示"参考的偏离 | 46% |
| 远离物体的 token 相对"跨提示均值"参考的偏离 | 37% |
| 真值活动集 + 均值参考，掩码一致性 IoU | 0.94–0.97 |
| 同上，IoU < 0.99 的掩码比例 | 37%–55% |
| 全共享的粗通过（不看提示相关状态）的掩码 IoU | ≈ 0 |
| 官方自身噪声底（换批大小） | 0.04 个翻转像素 / 掩码 |

**原因**：SAM 的双向解码器把提示信息稠密地写进所有图像 token，背景 token 也需要"物体描述"才能输出负值。
稀疏化只剩上采样头那一块，上限约 1.4 倍。放弃。

## 2. SAM 解码器的"上下文集 / 目标集解耦"（神经过程视角）

结构事实（正确，但没用上）：图像 token 之间从不互相注意，掩码在每个位置上是
"该位置特征 + 位置编码 + 物体码"的逐点函数。于是设想物体码可以在少量 token 上算、在别的 token 上求值。

脚本：`pilots/pilot2_sam_context_target_decoupling.py`（24 张图 / 70 个物体，SAM ViT-B）。

| 变体 | 框提示：与标准掩码一致性 | 框提示：对 GT 的 IoU |
|---|---:|---:|
| 标准 | 1.00 | 0.788 |
| 物体码只用 1/4 上下文 token（步长 2） | 0.90–0.91 | 0.753–0.775 |
| 物体码只用 1/16 上下文 token（步长 4） | 0.79 | 0.698 |
| 物体码不变，在 2 倍放大瓦片的 token 上求值 | 0.72 | 0.635 |

**原因**：读注意力很尖锐，子采样上下文会改变物体码；放大瓦片的编码器特征与原尺度特征不兼容。
免训练做不成，放弃。

## 3. 用模型自身统计量估计"图像里有哪些类"

想法：按类的概率质量、argmax 面积或最大概率设阈值，去掉"小而弱"的类。

脚本：`pilots/pilot6_presence_gating.py`。SegFormer-B5，ADE20K 全验证集：所有阈值的增益都在
−4.3 到 +0.04 mIoU 之间。**原因**：幻觉出来的类是成片的、高置信的，模型自己看不出来。
（真值门控的上限是 +10.3，所以这条路的问题不在"门控"，而在"存在性必须来自独立的信息源"。）

## 4. 用全局特征探针估计"图像里有哪些类"

想法：冻结 DINOv2-L 的全局特征（CLS、patch 均值、patch 最大值）加多标签探针，在 ADE 训练集的图像级标签上训练，
再按 `THEORY.md` 的规则 P 做门控或软融合。

脚本：`pilots/pilot7_presence_probe.py`。SegFormer-B5，ADE20K 全验证集：

| 量 | 数值 |
|---|---:|
| 探针的存在性 mAP（线性 / MLP） | 66.2 / 67.9 |
| MLP 探针在阈值 0.5 时对真实存在类的召回 | 67.8% |
| 最佳硬门控 | 51.01（+0.02） |
| 最佳软融合 | 51.29（+0.30） |
| 真值存在性上限 | 61.25（+10.3） |

**原因**：门控对召回率极其敏感，错删一个真实存在的类要赔上它的全部像素；
全局特征看不清小物体，召回不够。图像级接口太粗。
**同一个编码器换成区域级接口就有效**（+1.9 到 +7.2），这正是 demo2 主线的由来。

## 5. "为指标解码"作为主贡献

这条**不是失败**，但不够当主线，记在这里避免高估。闭式规则见 `THEORY.md`，全部无标签：

| 模型（ADE20K） | argmax | 规则 | 增益 |
|---|---:|---:|---:|
| SegFormer-B0 | 37.43 | 38.57 | +1.14 |
| Mask2Former Swin-T | 47.99 | 48.94 | +0.95 |
| Mask2Former Swin-L | 56.05 | 56.55 | +0.50 |
| UperNet ConvNeXt-L | 53.22 | 53.62 | +0.40 |
| SegFormer-B5 | 51.00 | 51.37 | +0.37 |

模型越强增益越小；用 NLL 最优温度校准后增益反而消失（B5：T=2 时 −0.01）。
合成的"理想校准世界"里同一规则的增益是 +2.8。差距来自：强模型的错误是高置信的整块错误，
决策规则救不回来。另外评测集小于约 500 张时规则会变差（300 张：−0.76），因为很多类不出现。

它在 demo2 里的定位是**配角**：理论干净、零成本、与主线可叠加。

## 6. “区域级融合强于像素级集成”（demo2 原来的主线）

2026-10-02 阶段 A 实测后推翻。完整记录和原因分析见 `RESULTS.md`。

| 分割器（ADE20K 全验证集） | 同一编码器的逐 patch 头做像素级集成（最优指数） | 区域识别器（指数固定为 2） |
|---|---:|---:|
| Mask2Former Swin-T | 54.57 | 54.31 |
| SegFormer-B5 | 53.65 | 53.16 |
| EoMT-L | 59.56 | 59.84 |

**原因**：先导实验里的对照没训好（单独 41.5，训好后 49.1）。两种接法带来的是同一份信息：叠在一起不比较好的一种多；
“先池化再分类”与“先分类再池化”相等；需要改名的区域恰恰是分割器切出来的碎片，池化没有更干净的证据可用。

同一天一并证伪的：

- 把第二个分割器、或同一分割器的翻转 / 多尺度视角，在区域内平均后再融合：不比像素级好（−0.25 到 −0.7）。
- 用分割器预测的区域训练识别器：命名准确率 +4.4 个点，mIoU +0.1。
- 掩码分类模型丢弃低置信度查询、对查询类别分布做幂次：全量上 −1.7 到 +0.1。
- 融合时除以识别器的训练先验：多数情况变差。

**教训**：对照没做强之前，不要按“通过”写结论；60 张、300 张子集上的差异不可信（本次两回反号）。
