# Fixed RCG ablation audit

2026-10-05. Scope: the existing CPU ablation, retained RCG equations, rendering,
statistics and source evidence. No new component or parameter selection. No GPU

## Finding

On the historical training-pool 600 episodes, the fixed reciprocal feature graph
carries most of RCG's improvement. Reference rank correction has no established
standalone improvement, but adds a positive conditional improvement on that
fixed graph. This supports the two-stage construction on reused development
data; it does not establish a new identity mechanism, superiority to the simple
mean guide, or a fresh/public4000 confirmation result.

The original ablation report does not retain convergence checks or final RCG
pixel parity. Its fixed point estimates and intervals match the existing sealed
600 anchors, but numerical verification and inspectable per-episode evidence
must accompany final acceptance. A fixed three-arm verifier is now prepared;
its actual run is pending at this audit's creation.

## Exact two stages

Sources: `src/ics/methods/rcg.py:17-82`, and the retained locked
`evidence/local/research_20261005/astra_portable/rcg_readout.py:29-93`.
The latter is byte-identical to
`evidence/dots-2026-10-05/evidence/05_06/strong_method_controls_20261005/validation121_locked/locked_methods/rcg_readout.py`:
SHA256 `865ca65310cd9e1cf87f12e7015d97cd746fdc12eebdc672cb21ee3f5919f1e6`.
The parent-named `external/astra_emd/` does not exist locally; the retained copy
provides the original readout evidence. Remote source-file identity was not
independently retrieved by this audit.

For unit query/reference tokens, let `C_ij = q_i^T r_j`, `F` be reference tokens
with mask coverage >=0.9 (or all maximally covered tokens if none qualify), and
`dq_i`, `dr_j` the means of the top ten cross-image similarities in each row and
column. The reference guide and corrected unary are

```
g_i = max_{j in F}(2 C_ij - dr_j) - dq_i
R(x)_i = (average_rank(x_i) - 0.5) / 4096
s = minmax(FoRIS continuous 64x64 response)
y = s + 0.5 (R(g) - R(s))
```

This first stage corrects relative reference matching/ranking and adjusts the
FoRIS response. It is not a calibrated foreground probability, a hard mask
gate, or a standalone guarantee of selecting the correct object. `dq/dr` use
unlabeled similarities; only `F` uses the allowed reference mask. No query GT
or query class name enters these equations.

The second stage builds directed 20-nearest-neighbor query edges, excludes
self-edges, weights each edge by `exp(-(1-cosine)/max(row's 20th distance,1e-6))`,
then keeps reciprocal edges with geometric-mean weight. It divides the graph
by its mean weighted degree. With `L = diag(W 1)-W` and
`a_i = (0.1+|2s_i-1|)/mean(0.1+|2s-1|)`, it solves

```
(diag(a) + 16 L) z = diag(a) y
```

Equivalently, it minimizes `(z-y)^T diag(a)(z-y) + 16 z^T L z`.
High-confidence FoRIS tokens anchor the corrected unary more strongly;
reciprocal feature neighbors share evidence. This is one fixed convex graph
solve, with CG used numerically, not repeated encoder inference or iterative
reference re-selection. Feature edges can connect distant positions and can
also propagate mistakes. Neither continuous mean conservation nor a lower
graph energy guarantees thresholded mask area or IoU preservation.

The renderer casts the solved field to FP32, bilinearly interpolates to
1024x1024 (`align_corners=False`) and thresholds at `>0.5`. There is no clipping,
second minmax, CRF, or post hoc area choice.

## Controls and comparisons that need careful wording

- `uniform_anchor` keeps the corrected unary and graph, replacing normalized
  FoRIS confidence by all ones. Both beats it +0.468185 [0.180446,0.829769]. This
  supports the particular fidelity weighting on these inputs, not calibration
  or object identity.
- `spatial_graph` replaces the feature graph by an unweighted 5x5 position
  graph, still normalized by mean degree. Its lambda16 score of 49.049918 is
  much worse, while spatial lambda1/0.25 reach 62.373259/62.187981. Equal mean
  degree does not equalize spectrum, connectivity, or smoothing strength.
  Therefore lambda16 alone is a misleading test of "all spatial smoothing".
  The existing weaker spatial rows remain diagnostics, not newly selected
  controls or evidence that every position smoother fails.
- The retained strongest simple mean guide scores 64.264087 on the exact same
  historical600 (`../fresh600_complete/report.json`); RCG minus mean is
  -0.026391 [-0.401313,0.414807]. Its guide is normalized mean reference FG and
  alpha0.25, while RCG uses the corrected-max guide and alpha0.5
  (`astra_portable/components.py:59-79`). This is a valid complete
  same-information comparator, but changes both guide and strength and hence
  is not a pure CSLS/hubness ablation. The present no-rank control isolates the
  entire correction, not the density correction within `g`.
- Lambda64 and alpha1 were included in the existing diagnostic table. They
  must not be promoted after reading this cohort. Lambda64's improvement
  over fixed RCG is unresolved: +0.470322 [-0.396593,1.009041]. No sweep or
  new variant is authorized by this audit.
- RCG vs pre measures graph/rank modifications to the continuous FoRIS input.
  RCG vs native compares two complete finalizers, because native includes the
  original FoRIS CRF (`src/ics/foris.py:49-66`, `scripts/run_foris.py:35-47`).
  It is inappropriate to call the +3.293308 vs pre the gain over complete
  FoRIS. Neither `RCG+CRF` nor a renderer-matched CRF comparison is in these
  fixed rows, so no claim about preserving/improving FoRIS CRF is supported.

## Numerical, leakage and source checks

Observed from local evidence:

1. The original `foris_pre_sealed` edits vs recomputed pre are exactly
   `[0,0,0,0]`. These four nonnegative counts exhaust additions/deletions
   against binary GT, so they imply zero pre XOR pixels over all600, stronger
   than merely equal mIoU. The source evaluator also explicitly checks this
   renderer (`src/ics/experiment.py:157-161`).
2. Ablation native/RCG scores and the full RCG-vs-native contrast dictionary
   exactly equal `fresh600_complete/report.json`. This anchors the cohort and
   statistics, but equal I/U or aggregate score does not prove mask identity.
3. The largest re-solved RCG-field difference is
   `5.9602099256039764e-08`. The ablation compares its FP64 CG solution to a
   stored FP32 field before casting (`run_rcg_anatomy.py:80-85`), whereas the
   locked method returns FP32. This is compatible with ordinary cast rounding;
   it is not proof of returned-field equality or final pixel equality near
   the 0.5 threshold.
4. The locked RCG and mean producers reject nonzero CG status. The ablation
   captures `status` and discards it, without residuals, iterations or failure
   counts (`run_rcg_anatomy.py:82`). This matters even if the both arm matches:
   smooth and diagnostic arms are separate right-hand sides/solves.
5. No inference expression uses query truth/pre/native to create a variant.
   However the original ablation loads GT before computation, immediately
   counts every result, and does not seal its own outputs before scoring.
   Its source-run seal/field/prediction/input hashes are not verified by the
   ablation. This is an evidence-isolation gap, not observed label leakage.
6. The original report keeps aggregate scores/edits and field maxdiff, but
   drops per-episode I/U, solver info, variant fields/masks and bootstrap draws.
   `report()` also removes the dummy correction summaries. Its pooled pixel
   edits cannot establish object identity, whole-object recovery, or a
   class-macro decision threshold. The feature-free4000 anatomy has different
   cohort evidence; its categories are morphology/GT diagnostics, not stage
   ablation or semantic instance identity.
7. Local current source hashes: ablation
   `6319898e421f776bcf14cccbd0d5b2695f82bc50c2b79f73a700a79bbc16a33e`;
   `src/ics/methods/rcg.py`

The graph/correction can improve several non-FoRIS fields, so its *incremental*
benefit is not exclusive to a FoRIS response. However the established strong
complete score in this particular fixed recipe is tied to the strong FoRIS
host: replacing that host by these tested margins/INSID3 fields does not retain
the complete-method performance. This supports dependence of this tested
construction, not a requirement that future methods use FoRIS.

Two confounds prevent a broader conclusion. First, every host-alone arm applies
per-image `minmax(field)`, bilinear1024 and `>0.5`; for an ordinary nondegenerate
signed margin this corresponds to its image mid-range, not the natural zero
margin. Thus the 20.124049 raw-NN row is not canonical nearest-token label
transfer; the source stage bank stores that separately as `fg[argmax(sim)]`.
Likewise the raw mean's canonical rule is margin>0, and INSID3's native rule
uses its combined-score threshold and token-mask rendering, not this universal
minmax renderer (`src/ics/methods/stage_bank.py:97-105,108-137`). These rows are
not fair evidence that complete raw-DINO or released INSID3 methods are weak.
Second, the host fields originate from saved raw final-layer tokens
(`scripts/run_stage_bank.py:65-77`), while the RCG guide and graph still use the
existing cache q/r (`run_rcg_hosts.py:25`), whose exporters save FoRIS's
conditionally position-debiased tokens in FP16
(`scripts/export_confirm_cache.py:55-62`). The experiment changes the host
response, not the entire feature/prior pipeline; mixed raw-field/debiased-graph
spaces and differing numeric precision remain. It does not isolate a purely
raw-DINO graph method or prove FoRIS's priors indispensable. This diagnostic
also loads GT before computation and retains aggregate reports only; no new
inference or parameter search was performed for this follow-up.
