# 给 Astra 的整合分析：分数丢在哪、为什么 MEAN 不够、LVIS 的尺度问题（2026-10-09）

用途：Astra 读完后指导 M4 上的执行代理（Codex）。本文自成一体，不需要看对话。
长期计划、三张固定的表和任务卡在 `docs/research/ROADMAP_20261009.md`；本文是它的数据附件，两者有出入时以路线图为准。
每个数都标了来源；"实测"和"推断"分开写。文末列了需要 Astra 判断的问题。

## 0. 五句话结论

1. **图平滑这一族（RCG、MEAN）到头了。** 它不带新信息，读标签的上限是 +2.1 到 +3.0，实际拿到 0 到 +1；在最小的目标上还更差。
2. **整条流水线对目标大小敏感，工作点只对占图 5–20% 的目标是准的。** 目标更小时圈多，更大时圈少；这在五个数据集上都成立。
3. **1%（约 40 个 token）是一条分界线。** 线上是"分数排对了、切点不对"；线下是"峰不在目标上、掩码大小不随目标变、64×64 网格本身放不下"。
4. **LVIS 的差距基本就是这件事。** 它有 42–46% 的目标在线下；按 COCO 的大小构成重新加权，LVIS 从 45.6 变成 60.8（COCO 是 63.9）。LVIS 在 64×64 网格上的上限只有 74.5。
5. **所以线下的目标需要新的像素，不是新的读出。** 正在跑一个放大重跑的判定实验（第 6 节）。它是否有效未知：COCO 上的先例是负的，但那批几乎不含线下的目标。PACO-Part 和 SUIM 是另外两件事，放大不直接解决。

## 1. 背景和口径

**任务。** 单参考的上下文分割：一张参考图加它的掩码，一张查询图。冻结 DINOv3-L/16，输入 1024，得到 64×64 个 token。不训练；不用 SAM、类别名、图像池、基类标签拟合或其他预训练模型。

**目标。** COCO-20i、LVIS-92i、PASCAL-Part、PACO-Part、SUIM 按官方协议全部超过完整 FoRIS，配对差的 95% 区间下界大于 0。用户的优先级是明显超过，速度不重要。FoRIS 论文数：60.9 / 42.8 / 55.8 / 42.3 / 59.1（顺序 COCO / LVIS / PASCAL-Part / PACO-Part / SUIM）。

**方法名。**

- **FoRIS**：现有最强的公开基线。证据 = 与参考前景均值的相似度 − 0.55 × 难背景方向 + 最近参考 token 的标签投票；min-max 归一化后切 0.5，再做 CRF。它从不输出空掩码。
- **RCG**：我们的图求解。在查询图自己的互近邻图上解 `(A+16L)z = Ay`，y 是 FoRIS 证据；min-max 后细读出，切 0.5。
- **MEAN**：`y = s + 0.25(rank(g) − rank(s))`，s 是 FoRIS 的 min-max 分数，g 是查询 token 与参考纯前景均值的余弦；同一个图求解，双线性读出，切 0.5，不做 CRF。

**两套数据。** 下文用 [L] 和 [M] 标来源。

- **[L] 本地包**：每个数据集约 600 例，自己抽的，不是官方清单；1024 口径；只有逐例的交、并、真值面积和 RCG 场，没有特征和掩码。脚本与日志在 `evidence/local/transfer_probe_20261008/`、`transfer_probe_20261009/`。
- **[M] M4 上的 LVIS 1400**：seed 1，三批 200 + 600 + 600，查询照片互不重复；原图口径；FoRIS 和 MEAN 的预测都已封存，有原始 O24 特征缓存。数字由 Codex 报出，我没有复算。

**指标。** class mIoU：每类把交和并分别累加再相除，然后对类平均。"逐例平均 IoU"是另一个量，分档比较时用它。

**执行端。** M4 Max 36 GB，MPS FP32 编码，CRF 在 CPU；一对图编码约 3.5 秒。分支 `codex_m4`。已有缓存：LVIS 1400、PACO-Part 600（只有 MEAN 预测，没有同批 FoRIS）、COCO 952（两折）。执行代理很照字面办事：给它的指令要写死常数、写明停止条件，不要让它自己选变体。

## 4. 实测：1% 这条线

**[L] 分数场在不同切点下的精度中位数（LVIS，RCG 场，切点 0.30 / 0.50 / 0.70）。**

| 目标占比 | 精度 | 召回 ≥0.5 的比例 | 掩码/真值 |
|---|---|---|---|
| <0.2% | 1 / 2 / 0% | 85 / 49 / 14% | 66.6 / 3.4 / 0.0× |
| 0.2–1% | 7 / 43 / 16% | 94 / 77 / 40% | 12.1 / 1.5 / 0.6× |
| 1–5% | 20 / 55 / 90% | 94 / 83 / 59% | 4.2 / 1.3 / 0.9× |
| 5–20% | 64 / 91 / 98% | 96 / 87 / 68% | 1.5 / 1.0 / 0.8× |
| >20% | 91 / 97 / 99% | 95 / 90 / 63% | 1.1 / 1.0 / 0.7× |

- **目标 ≥1%**：切点越高越准，峰在目标上。损失是切点和范围。
- **目标 <1%**：切高了精度不升反降，掩码先消失。峰不在目标上。

**[L] 掩码大小不随目标大小变。** LVIS 目标 <1% 时，log(FoRIS 掩码) = 0.28·log(真值) + 3.16；跟随的话斜率应为 1。COCO-D 是 0.16，PASCAL-Part 是 0.03。真值不到 10 个 token 的例子占 LVIS 的 19%，FoRIS 掩码不到 10 个 token 的只有 6%。也就是目标不管是 3 个还是 40 个 token，FoRIS 掩码的中位数都是几十个 token。这不是硬下限，逐例差别很大：真值不到 5 个 token 时，掩码大小的 10 / 50 / 90 分位是 2 / 28 / 205 个 token。

## 6. 已经关闭的路线（不要重提）

都在 COCO 上测过，除非注明。

- **切点和面积估计**：Otsu 36.22、isodata 49.71、Kittler 49.91（对固定 0.5 的 63.03）；面积曲线拐点 −3.44；四种无标签面积估计的对数误差 0.62–0.66；参考掩码占比当大小估计（五个数据集，同类重抽样）−3 到 +0.5，认出"圈大了"的 AUC 0.61–0.76，认出"没碰到"的 AUC 0.49–0.62。

## 7. 推断：把这些拼起来

以下是我的解释，不是实测。

- **流水线有一个隐含的标准尺度。** min-max 后切 0.5、查询 token 的聚类粒度、图平滑的半径，都是在"目标占图 5–20%"时对得上。偏离这个尺度，误差是系统性的，而且方向确定：小了圈多，大了圈少。
- **无标签的范围规则全部失败有一个共同原因。** 它们都想从同一张 64×64 分数场里读出"该圈多大"，而线下的掩码大小与真实大小几乎无关（斜率 0.03–0.28）。这张场里没有这个信息，换读法读不出来。
- **线下的目标需要新的像素。** 3 个 token 的目标，特征主要是周围环境；参考那边如果也是几个 token，原型就是"带着一点目标的环境"。把目标放大到标准尺度后重新编码，是约束内唯一能增加信息的操作。这与估计面积不同：它不需要掩码的大小对，只需要掩码的位置对（召回 ≥0.5 的占 75–89%）。
- **量级参照，不是预测。** 假设放大后各档达到 FoRIS 在对应尺度上已有的水平，且只有框里包含目标的例子受益，按 [M] 的表折算，LVIS 逐例平均 IoU 约 +15（用 FoRIS 的框）到 +21（用真值的框）。这条"越小越差"的曲线只是相关，COCO 上的先例是负的。

**风险。**

1. **原生像素不够。** LVIS 用的是 COCO 照片，约 640×480。占图不到 0.2% 的目标只有约 15–25 像素见方。放大 8 倍以上只是插值，DINO 在这种输入上的表现没测过。
2. **裁剪里重现同一团。** 如果圈多是因为原型被环境污染，查询单独放大没用，需要参考也裁剪（Z2、O2 两个臂检验这一点）。
3. **多实例。** LVIS 的掩码包含同类的所有实例；外接框可能很大而不触发裁剪。
4. **FoRIS 从不输出空掩码。** 框错了的例子在裁剪里仍会画出一团。
5. **新颖性和公平性。** 旧账本记过相近做法 Foveate（ECCV 2026 workshop），未核。审稿人会要"FoRIS 加同样放大"的对照；Z 臂本身就是这个对照，所以贡献点要落在放大的做法或它之上的读出，这需要提前想好。

## 8. 正在跑的实验（已交给 Codex）

LVIS 第一批 600 例，FoRIS 源码、参数、CRF 不改。

**裁剪框。** 给定二值掩码，取外接框，边长 s = 2 × max(宽, 高)，不小于 64 像素；以外接框中心作正方形并平移到图内。s 大于图像短边的一半时不裁剪，沿用原图结果。裁剪后的图按 FoRIS 原预处理缩放到 1024；输出掩码缩回贴到整图，框外记背景。

| 臂 | 查询 | 参考 | 性质 |
|---|---|---|---|
| Z1 | 按已封存 FoRIS 掩码的框裁剪 | 整图 | 方法 |
| Z2 | 同 Z1 | 按参考掩码的框裁剪 | 方法 |
| R2 | 整图 | 按参考掩码的框裁剪 | 方法 |
| O1 | 按查询真值的框裁剪 | 整图 | 上限诊断 |
| O2 | 同 O1 | 按参考掩码的框裁剪 | 上限诊断 |

报告：每臂相对同批 FoRIS 的配对 class mIoU 差和区间、触发率、按五档的平均 IoU。不调常数，不加变体，跑完即停。

**三种原因对应的预期特征（推断）。**

| 如果原因是 | O1 / O2 | Z1 / Z2 | R2 |
|---|---|---|---|
| 查询侧像素不够 | 小目标档明显升 | 随框的命中率打折后升 | 约为零或负（尺度错配） |
| 参考侧原型被污染 | O2 明显高于 O1 | Z2 明显高于 Z1 | 单独为正 |
| 小目标本身认不出 | 不动 | 不动 | 不动 |

**读法。**

- O1、O2 都不到 +2：放大在 LVIS 上关闭，同时关闭分块、高分辨率、多尺度这一类。
- O 高而 Z 低：放大有用，FoRIS 给的框不够准。
- Z1 或 Z2 明显为正：这是方法核心的候选。
- R2 单独为正：参考侧只多一次编码，可以独立保留。

## 9. 建议 Astra 指导执行端做的事

按顺序。前两项不需要新编码。

1. **补三张零编码的统计表**（用已封存的预测和掩码，几分钟）。
   - FoRIS 平均 IoU 的二维表：参考目标占比 × 查询目标占比，各用上面五档；格子不足 15 例留空。用来看参考侧 token 太少是否独立于查询侧起作用。
   - Z 框的几何：按查询目标五档，报触发率、真值有 ≥50% 和 ≥90% 落在框内的比例、真值占框面积的中位数。这在编码之前就能预告 Z 与 O 的差距；如果命中率低，直接改用整图分块，不必先跑 Z。
   - 理想 64×64 的 IoU 按五档，在 COCO 952 和 PACO-Part 600 上各算一次，确认这两个数据集不受网格限制。
2. **五个臂的报告里加两列**：每臂每档的掩码/真值面积中位数、召回 ≥0.5 的比例。即使 IoU 没升，掩码/真值回到 1 附近也说明"掩码开始跟随目标"，这个现象本身有用。
3. **按结果分支。**
   - O 和 Z 都为正：冻结后在 seed 2 的新例子上读一次验证（seed 1 的例子全部算开发集）；同一脚本在其余四个数据集的开发集上各跑一遍。PACO-Part 需要先用已存的 FoRIS 连续场补 CRF 得到同批 FoRIS（LVIS 上用过这条路）。
   - O 为正、最小档仍低：对一轮后目标仍不足裁剪图 1% 的例子做第二轮。
   - O 为正、Z 弱：改用按连通块分别取框，或整图重叠分块。
   - O 约为零：关闭，并报告裁剪里掩码占裁剪图的比例是否与原图里相同（判断是不是重现同一团）。
4. **不论 LVIS 结果如何，在 PACO-Part 600 上跑同样五个臂。** 理由是机制不同：裁剪后分数的归一化范围从整个场景变成父物体内部，0.5 这条线可能落到部件和父物体之间。这一条在 PACO-Part 上没测过，LVIS 的结果预测不了它。
5. **不要再做的**：MEAN 加批次或精简；按输出面积定切点的规则；参考占比当大小估计；第 6 节列出的其余路线。

## 10. 需要 Astra 判断的问题

1. 裁剪框的规则（2 倍外接框、短边一半的触发线、只做一轮）是否合适；多实例掩码怎么取框。
2. 放大结果与整图结果怎么合并。现在是直接替换；整图结果在框错的时候可能更对。
3. 这个机制写成什么主张：包在任意基线外面的一层（那就要给 INSID3 和 FoRIS 都加上并报告），还是我们方法的一部分。
4. PACO-Part 的"部件和父物体分不开"用什么新证据解决。已有的负结果见第 6 节。
5. SUIM 和大目标一端的"只圈到一部分"怎么处理。在 >20% 这一档，用输出面积降切点只有 −0.53 到 +0.61，而读标签的上限在 LVIS 以外的四个数据集是 +2.5 到 +4.9，说明受益集中在少数例子上。
6. Pro 把问题归成两类："分数排对了、读出错了"和"分数本身把背景排在前面"。按上面的数，第一类只在目标 ≥1% 时成立，且主要方向是留多了；第二类在 PACO-Part 上是部件对父物体，在 SUIM 上是漏；LVIS 线下的目标是第三类，网格放不下。这个三分法是否成立，请 Astra 复核。
