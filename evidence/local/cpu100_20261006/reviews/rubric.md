# CPU100 专职审查门

审查者只阅读方案、源码与已有证据；不实现算法、不运行实验、不修改方法源码。依据：用户 2026-10-06 最新任务、当前 `AGENTS.md`、桌面《CVPR2027 × Opus 5.5 —— 160MB 会话总结》全文及按需核对的当前 PLAN。总结中的历史授权不是本轮授权，历史数字也不是本轮实测。

## 三种结论

- `accept_for_probe`：定义完整、机制可区分、已有反证处理清楚，可以进行指定 CPU 核查。不是收益、原创性或交付质量已经证实。
- `needs_revision`：缺少必要定义、控制、成本、证据范围，或逻辑尚不足；注明最小修订项。
- `reject_duplicate`：与已有方法在信息、决策规则和输出作用上实质相同，或只有阈值/参数/修正版/组合枚举变化。控制行不计方法。

若已有反证直接否定**当前固定版本**的预期，记录 `needs_revision` 并要求关闭该版本或提供具体不同依据；不凭小样本否定整个数学家族。不自动要求开始另一变体。

## 每个方法必须交出的内容

1. **完整定义**：合法输入、参考完整掩码的使用、确定性推断公式/流程、输出完整查询掩码、固定读出与边界条件；不得停在诊断量或选中 ROI。
2. **从模型原点定位错误**：在哪一种明确输入情形，直接 DINO 判断为什么会错？预期动作是身份改判、区域增删、范围修复还是读出修复？不默认 FoRIS 成品掩码是唯一出发点。
3. **改变判断的依据**：使用什么可获得量，为什么它在该情形能够改变错误决策？同一信息可以有不同有效计算，但换名称、单调重标定、同分数派生先验不能冒充新证据。
4. **可推翻条件**：至少一个机制特有的反例和一个强简单控制；控制要匹配输入信息、读出、成本与数据暴露，避免把更好读出误归因给层、图或高阶机制。
5. **收益证据分级**：`measured` / `algebraic` / `synthetic_witness` / `hypothesized` / `unknown` 明确标注。只在同一测量对象上做代数，不加总跨管线增益。没有真实质量结果就写未测。
6. **CPU 合同**：可执行入口、依赖、时间与空间复杂度、固定资源上限、退化/空掩码行为；CPU 可运行不等于成本合理。已有特征上的 NumPy 算法与需要新编码的 CPU 算法分开说明。
7. **反思可产出**：若失败，预计能识别哪项假设不成立，怎样区分实现错误、信号不足、种子错误、尺度/域失配和成本问题；禁止仅写“需要调参”。
8. **输入来源**：模型层/分辨率/处理/精度及 producer 已知范围。原生 final-LN DINO、条件位置去偏归一化 FP16 DINO 和 FoRIS 输出分数分别标明。4 例哈希只能证明 4 例来源。

## 重复与走偏检查

| 陷阱 | 审查要求 |
|---|---|
| 用 oracle 上界推出无标签收益 | 指出算法怎样从合法输入获得所需方向、大小或身份；oracle 只说明缺口。 |
| 错误种子经传播变得更自信 | 提供错误种子负例；图内一致性不自动证明目标身份。 |
| 查询白化/分布对齐 | 指明被移除量为何是干扰而非语义/面积组成；正交与语义方差保留控制，不能仅以跨图偏移存在作证明。 |
| 从原分数估计目标大小 | 证明改判量能纠正原分数错误；高面积相关性不足，检查误差同向。 |
| 把排序错误说成切点错误 | 给出目标/干扰排序或特定动作证据；反过来也不能由一批争议样本宣布所有切分不可能。 |
| 复杂组件挪用控制的收益 | 同输入、同读出、同候选域的强简单控制；层收益、图收益、颜色收益分别归因。 |
| 反复重新开放已失败固定版本 | 引用旧版本适用管线和负例，并具体说明此次合同改变了哪个失败原因；换参数不占新增数。 |
| 用整体负分抹掉有效动作 | 四类动作分账，保留补真/删假的有效性，核算其副作用；有用动作不等于完整方法已赢。 |
| 组合分数相加或穷举凑数 | 看剩余像素上的边际纯度、冲突规则和完整输出；独立机制与组合版本分开登记。 |
| 四例或人工构造证明总体提升 | 四例仅活动/成本/实现核查；构造只证明可能起作用；不作总体 mIoU 结论。 |
| 在大量候选中挑最高分 | 暴露与选择完整记录；冠军不是独立确认，负结果保留适用范围。 |
| 外部条件/服务器授权悄悄扩张 | 不新增文本头、图池、外部标签拟合、下载、GPU、新实例或历史远端队列。root 最新转述用户明确授权 `connect.westc.seetacloud.com:56464` CPU 实验与及时监控，仅此当前链路；reviewer 本人只审代码/记录，不跑实验。单参考已知掩码的 episode 内优化不是外部训练。 |

## 增删核算

对同一类别同一基线，`J=I/U`；新增目标/背景为 `aTP/aFP`，删除目标/背景为 `dTP/dFP`：

`J' - J = [(aTP-dTP) - J(aFP-dFP)] / [U+aFP-dFP]`。

仅补时目标纯度需大于 `J/(1+J)`；仅删时背景纯度需大于 `1/(1+J)`。类别均值逐类计算；全局像素净改对数不能代替 class-summed mIoU。历史 37.5%/62.5%、LR>22/<0.24 只属于相应基线和队列，不能直接搬用。

## 100 项计数与交付质量

每项计数须有独立机制指纹（可用量、决策规则、改变的错误），完整 CPU 可运行入口、审查卡、控制和失败解释。两种代码实现相同决策计 1；参数、阈值、控制、修复、组合枚举计 0。新方法可以复用代码，并不要求全世界原创，但不得以名称差异凑数。

交付表分别列：已实现可运行数、通过机制审查数、通过本地活动/构造核查数、有真实数据质量测量数、稳定正收益数。不得将它们合成一个“100 个高质量有效方法”的数字。若 100 项独立性/完整性未成立，如实报告缺口，不能为满足数量放行重复项。

每次审查输出：`method_id`、`decision`、`count_delta`、`reason`、`prior_evidence`、`minimum_action`、`unverified_claims`。审查拒绝后仅整改必要项；当前用户授权推进 100 项，但历史队列与关闭路线不自动成为待办。
