# 从匹配到 INSID3、FoRIS：到底删了什么，又补了什么

参考相似度能给出候选线索，但相似背景可能得到高分，外观不同的真实目标也可能得到低分。INSID3 把逐点匹配改成 query 分区、seed 选择和整组聚合；FoRIS 进一步加入参考 FG/BG 对比、稠密候选、软 seed 先验和冲突重权。这些步骤改变了预测，却不自动取得一份独立的正确类别证据。要判断它们是否纠错，必须同时记录删掉的 FP、误删的 TP、补回的 FN，以及新增的 FP。

本文使用已核作者源码与原论文，区分设计意图、算子性质和实际像素变化。这里的“完整掩码”仅指整张输出，不保证识别出正确对象。不能把失败全部归因于模型，也不能把原始相似度不可用当作定理。

## 一、两种方法的实际关键差别

INSID3 的原始 query 特征用于聚类和图内相似度，去偏特征用于跨图匹配。它选一个 seed，并将每个 cluster 的参考相似度、seed 相似度和候选占比相乘，最后以 0.2 阈值输出。FoRIS 则在其默认路径里把参考对比响应、NN 投票、query seed-cluster 先验、冲突惩罚和 cluster 重权组合为连续场，再做逐图 min-max、上采样和 0.5 切割。[INSID3 模型](https://github.com/visinf/INSID3/blob/main/models/insid3.py)、[FoRIS 固定代码版本](https://github.com/Xi-Mu-Yu/FoRIS/tree/1aa02a11ef5f6673ed7a8a666ccf7d5586998d9e)。

FoRIS 默认代码没有“从预测 query 前景重新估计一个新前景均值，再重新匹配全图”的独立步骤。它使用 query seed 原型构造图内先验，reference 相似度、投票和冲突共同参与最终分数。将其叙述成我们额外测试过的 queryseed 均值方案，会误认算法内容。

## 二、逐模块的 FP/FN 作用与失败条件

| 方法/模块 | 输入与实际改变的推断 | 预期纠错方向，只是设计意图 | 怎样反过来造成损伤 |
|---|---|---|---|
| 原始匹配 | reference FG 均值、FG/BG 均值差或 NN，把 query token 变成标量 | 找到与指定区域相近的像素 | 相似背景成为 FP；姿态、材质、遮挡不同的目标成为 FN；不同匹配统计不能混称一条原算法 |
| INSID3 去偏 | 从低语义图像编码估计位置子空间，跨图匹配使用投影后的特征，图内保留原始特征 | 减少同坐标伪对应 FP；让不同位置的真匹配有机会出现 | 被移除方向也可能携带任务信号；不是任意图像都获益 |
| INSID3 候选定位 | 原型正相似度与 query→reference NN 的 FG 投票相交；前向全空才用 0.9 分位 fallback | reference 背景提供排除线索，削掉部分 FP | reference 没涵盖目标外观时把真实部分挡在候选外；这个“backward”不是严格互为 NN 闭环 |
| INSID3 query 聚类与 seed | 在原始 query 特征上做 average-linkage；从有候选的 cluster 中选最接近 reference 的 seed | 将散乱匹配变成连贯区域，减少孤立 FP | cluster 可以混入相邻类别；seed 可能直接选错类别，导致后续整组方向错误 |
| INSID3 聚合 | cluster 的跨图均值相似度 × 与 seed 的图内相似度 × 候选占比；seed 占比强制为 1 | 排除与 seed 无关的误匹配，纳入同对象的部分，兼顾 FP 与 FN | seed 错时会强化错对象；与 seed 外观差异大的真部件会被抑制；占比低会漏掉弱匹配部分 |
| FoRIS 自适应去偏 | 参考 FG 与 query 全局均值的相似度参与是否去偏的判定，默认界为 0.8 | 避免在本来需要空间先验的任务中过度去偏 | 全图均值与目标身份不等价；单参考的这个判定也可能错误 |
| FoRIS 参考 FG/BG 对比 | 对 reference FG 聚类，前景用 log-sum-exp；取最像 FG 的 20% reference BG 建困难背景方向，并相对 FG 均值正交化 | 多原型可能补回均值遗漏的外观；背景扣分可能剔除相似背景 FP | 一个 reference 的背景未必代表 query 干扰类别；正交化可能丢掉可用区分，也可能压制真目标。若 FG 只有一个有效簇，多原型本身没有额外覆盖 |
| FoRIS 候选与稠密补充 | NN 前景投票，加固定每两格一点的稠密候选供 seed 先验；NN 投票另以软项加分 | 提高候选覆盖，允许原 NN 筛选漏掉的区域进入后续推断 | 新候选也增加错误区域入口；稠密点没有提供新类别标签 |
| FoRIS query 软先验 | 有 target 图像状态时，DINO/RGB/xy 联合聚类；seed 按 reference 相似度×候选占比选择；相似 cluster 得软先验 | 让匹配弱但图内一致的区域有机会补回；抑制与 seed 无关的区域 | RGB 与坐标主要提供分组线索，不保证跨类别身份；错误 seed 仍可能扩大 FP |
| FoRIS 冲突与 cluster 重权 | 不确定位置的 FG 分数与 NN/seed 不一致时扣分；FG/BG 同时高时扣分；对 cluster 的 FG/BG 均值重权 | 压制含混 FP，支持相对纯的 FG cluster | 几个量都来自同一份错误相似度时可能一起错；真实难例本就不一致，会新增 FN |
| 双线性、切点与 CRF | 将连续场或二值低分辨率输出转成最终掩码，CRF 利用图像边界 | 改善边缘锯齿、局部泄漏与孔洞 | 可能移走正确边界或切断细目标；通常不能独立判定远处整块区域是否属于目标类别 |

FoRIS 的 stage-1 正标量 feature gate 还需特殊对待：默认后续评分使用未乘 gate 的分支，另一路在聚类前重新 L2 归一化，正标量在实数算术中相消。因此不能仅凭函数名“背景抑制”就把它列为有效 FP 删除操作；浮点临界分群的微差应另查。源码中 reference/query 的归一化轴与 `set_target` 状态也影响实际入口，不能悄悄修正后仍称同一个官方基线。

## 三、论文消融证明了哪些效果，尚未证明哪些归因

[FoRIS 原文 Table 1、Table 3](https://arxiv.org/html/2609.03384v1) 报告 COCO-20i 1-shot 最终 60.9，表内 INSID3 为 57.6。该比较提供完整方法表现，不能单独将 3.3 点分配给 FP 删除或 FN 补回。

论文 Table 3(b) 的候选 densification 为 60.1→60.9；这与扩大覆盖的设计意图相容，但没有像素四向计数就不能断言全部来自补 FN。Table 3(d) 前景巩固中，不加两项为 58.5，加 SDP 为 59.9，加 SR 为 60.2，两项都加为 60.9；它支持该配置的完整输出收益，不证明各项都是纯粹的 FP 抑制器，也不保证两个消融效应线性相加。

此外，FoRIS 的最终切点随全图 min/max 变化。即使某模块在局部只扣分，最终掩码也可能在别处扩张：例如 raw 分数 `[0,0.4,1]` 仅把最大值压成 0.6，原始尺度的中点就由 0.5 降到 0.3，中间位置从背景变为前景。因而“raw 分数下降”不等于“最终删除 FP”，需要在同一末端渲染后逐像素核对。

## 四、现有旧 120 掩码的实际四向变化

下面直接读取已经冻结的 120 例掩码和 GT，没有重新编码、选参数或改预测。它们位于相同 1024 工作栅格，67 类；mIoU 按类累计 I/U 后宏平均。INSID3 是本项目单缓存空间适配版：119 例去偏、1 例未去偏，无官方完整双空间复现保证。因此下表用于说明已有构造怎样修改错误，不能替代论文 INSID3→FoRIS 的正式同协议比较，也不是逐模块因果消融。

起点“均值匹配”特指本项目 reference FG−BG 均值零阈值控制，低分辨率先二值化再双线性渲染，并非 INSID3 的完整原始阶段。[逐例计数与脚本说明](evidence/09/frozen_chain120.json)。

| 固定输出之间的变化 | 补回 TP，即修复 FN | 新增 FP | 误删 TP，即新增 FN | 删除 FP | class mIoU |
|---|---:|---:|---:|---:|---:|
| 均值 FG−BG → cached INSID3 | 428,144 | 627,132 | 2,114,213 | 10,085,646 | 45.097→62.189 |
| cached INSID3 → FoRIS pre-CRF | 1,188,269 | 1,693,508 | 910,988 | 1,687,703 | 62.189→61.156 |
| cached INSID3 → FoRIS native | 1,210,601 | 1,631,810 | 984,466 | 1,817,701 | 62.189→62.018 |
| FoRIS pre-CRF → native | 211,287 | 245,054 | 262,433 | 436,750 | 61.156→62.018 |

这份数据支持三个具体观察：

1. 从弱均值匹配到 cached INSID3，大量背景被删除，同时损失一部分 TP。提升主要伴随更强的背景抑制，不能描述成单纯“把漏掉的对象补全”。
2. 从 cached INSID3 到 FoRIS native，既补又删。净 TP 增加 226,135，净 FP 减少 185,891，但 class mIoU 仍略低。这不是矛盾：大对象贡献更多像素，不同类的分母与权重不同，像素总量净改善不保证类宏 IoU 改善。
3. CRF 也不是只修 FP：它删除 436,750 个 FP，同时误删 262,433 个 TP；新增区域里同时含 TP 和 FP。其最终收益应按完整输出评价。

这些计数不要求新的 query 身份判据，也不证明模型获得新语义能力。它们的作用是让“纠错”一词有可检验的具体含义。

## 五、后续实验固定使用的四象限账

令旧输出为 H₀、新输出为 H₁、仅评分时可见的真值为 Y。新增集合 A=H₁−H₀，删除集合 D=H₀−H₁。每个操作必须同时记录：

| | 真值前景 Y | 真值背景 非 Y |
|---|---|---|
| 新增 A | `add_TP`：补回 FN，纠错 | `add_FP`：引入错误，损伤 |
| 删除 D | `delete_TP`：制造 FN，损伤 | `delete_FP`：剔除 FP，纠错 |

净 TP=`add_TP−delete_TP`，净 FP=`add_FP−delete_FP`；总纠错=`add_TP+delete_FP`，总损伤=`add_FP+delete_TP`。这些数量应给逐例、逐类和批次合计，并与最终 class mIoU、配对区间、各折及升降例数并列。它们不是替代 mIoU 的新目标。

下一次针对某模块的验证应固定相同输入、其它模块与最终渲染，只改变已定义的一步，先冻结全部预测再评分。除了四向账，还需说明该步能触达哪些原 FP/FN：近边界、完整错区域、完全漏掉的目标分别有多大预算。若它只改变原掩码附近，却声称解决远处错对象，解释就不成立。

最后要核实纠错证据的来源。如果新决策仍完全依赖原错误相似度的单调重标定，能够调整输出范围，却没有改变该排序；如果引入 query 内部分组，需证明它在真实错误处提供额外选择依据，而非只是把原错误扩成整组。原相似度可以有用，关键是明确哪一步利用了它的可靠部分，以及哪一步足以推翻它的错误判断。
